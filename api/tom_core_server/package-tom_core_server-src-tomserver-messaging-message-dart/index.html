The shape of an outbound message, independent of how it is delivered.

This is the transport substrate behind CE-NT notifications and CE-RP report delivery. It deliberately stops short of the notification model — which events notify, which users subscribe, what their per-channel preferences are — because that is a CodeSpecs part decision, not a framework one. What lives here is only the envelope and the wire.

Why the shape is not an email

CE-NT names its channels abstractly — email, push, SMS, webhook — and only the first of those has a subject line, a Cc:, or a MIME tree. A message type modelled on SMTP would make the other three subclasses of a thing they are not, and every non-email transport would spend its life ignoring fields.

So the shape here is the intersection, plus two escape hatches:

  • Common: a [TomMessage.channel], [TomMessage.recipients], an optional

[TomMessage.subject], one or more [TomMessageBody] alternatives, and [TomMessage.attachments]. - [TomMessage.headers] carries transport-level name/value pairs that only some channels have (email headers, webhook HTTP headers). - [TomMessage.metadata] carries channel-specific delivery hints (a push priority, an SMS sender id) that are not headers at all.

A transport reads what it understands and ignores the rest. That is what lets a spec that names email today name sms tomorrow without the message type changing.

Everything round-trips through JSON

A message is not delivered on the thread that created it — it goes onto the durable outbox queue and may be delivered after a restart, in a different isolate. So [TomMessage.toJson] / [TomMessage.fromJson] are not a convenience; they are the reason the outbox can promise that an accepted message survives a crash. Attachment bytes are base64 in that encoding, which is also exactly how MIME will need them.

class TomAttachment

class TomAttachment

A file carried with a message.

Bytes are held in memory rather than referenced by path, because a message may be delivered long after the process that composed it — and a path that resolved at compose time is exactly the sort of thing that has stopped resolving by the time a retry runs.

class TomMessage

class TomMessage

An outbound message, ready to hand to a [TomMessageTransport].

See the library dartdoc for why the shape is channel-neutral. The one invariant enforced here is that a message has somewhere to go: an unaddressed message is a programming error that would otherwise surface as an obscure transport failure minutes later, on a retry, in another isolate.

class TomMessageBody

class TomMessageBody

One representation of a message's content.

A message carries a list of these because the same content often has to be offered twice — an HTML mail and its plain-text fallback — and picking one for the recipient is the transport's job, not the caller's. Ordering is least-preferred first, matching MIME's multipart/alternative convention, so the richest representation is last.

Methods

bool _mediaTypeIs(String type)

Whether [mediaType] names [type], which is spelled in lower case.

Media types are case-insensitive by specification, so the comparison has to be too. It lives in one place because the alternative was tried: the HTML check lowercased, the plain-text check was an inline == inside a selector, and the two drifted apart — a body spelled Text/Plain was not found while Text/HTML was. Predicates that share an implementation cannot disagree about their own rule.

Matching only; the caller's own spelling is what [mediaType] keeps and what the MIME encoder puts on the wire.

Static

static String defaultCharset

The character set a part carries when the caller names none.

Written once and referenced, because it was written four times: the primary constructor's default, both named constructors, and the [TomMessageBody.fromJson] fallback. They agreed only because nobody had changed them — altering the default meant finding four sites, and missing one would leave the class disagreeing with itself about what a body built without a charset contains. That is the same failure [_mediaTypeIs] records having already suffered once, in this same class.

Public, so that a caller deciding whether a part needs a charset conversion can ask what the default is rather than restating it and becoming a fifth site itself.

static String _plainTextMediaType

The media type [TomMessageBody.text] builds and [isPlainText] recognises.

The constructor and the predicate must name the same type or a part built by one is invisible to the other, so they name it through here rather than each spelling it. Lower case is load-bearing: [_mediaTypeIs] lowercases only the left side of its comparison.

static String _htmlMediaType

The media type [TomMessageBody.html] builds and [isHtml] recognises.

class TomMessageChannel

class TomMessageChannel

Which delivery channel a message is bound for.

A named value rather than an enum, because the set is open: CE-NT fixes four channels by name but a deployment may add one (an internal chat webhook, a pager gateway) without the framework being rebuilt. The constants below give the four that CE-NT names a spelling everyone agrees on, which is what an enum was buying; the constructor keeps the door open, which is what an enum was costing.

static TomMessageChannel push

Mobile or browser push notification.

A reserved name, not an unfinished implementation. No transport ships for it, and the constant is still worth having: the channel set is open, so what a name in this class buys is that every deployment wiring up its own push transport spells the channel the same way. Shipping one would mean picking a vendor — FCM, APNs, or both — and a preset for an API this repository cannot test against is a plausible-looking guess that fails in production, which is the same reason no SMS vendor preset ships.

A [TomNoOpMessageTransport] registered here makes a spec that names the channel runnable, at the cost of discarding the message silently.

class TomRecipient

class TomRecipient

One addressee of a message.

[address] is deliberately not called emailAddress: for SMS it is a phone number, for push a device token, for a webhook a URL. Naming it after the only channel that happens to use @ is how a transport-neutral type stops being one.

enum TomRecipientKind

enum TomRecipientKind

How a recipient is addressed relative to the others.

Meaningful for email; every other channel has only [to], and a transport that cannot express copies is expected to say so rather than silently flatten them (see [TomMessageTransport.supportsCopies]).

Values

to

A primary addressee.

cc

A copied addressee, visible to everyone.

bcc

A copied addressee, hidden from everyone — including the other blind copies.
