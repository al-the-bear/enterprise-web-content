TomS3BlobStore

package:tom_core_server/src/tomserver/file_storage/s3_blob_store.dart

import 'package:tom_core_server/src/tomserver/file_storage/s3_blob_store.dart';

The external object-store backend: S3 and everything that speaks its API.

One implementation covers Amazon S3, MinIO, Ceph RadosGW, Backblaze B2's S3 endpoint, DigitalOcean Spaces, Hetzner, Wasabi and Google Cloud Storage's interoperability endpoint, because they all speak the same four requests with the same signature. Azure Blob is the one that does not; it is reached by writing a [TomBlobStore] over its REST API, which is the same amount of work as this file and shares its shape.

How the upload streams

S3 will not accept a PUT without a Content-Length, so a body of unknown length cannot be sent as one request. The protocol's own answer is multipart upload, and it is what makes streaming possible here: the incoming stream is buffered up to [TomS3BlobStore.partSize], and

  • if the stream ends inside that first buffer — the common case, an

attachment or a report — it goes out as a single PUT, one round trip; - otherwise the upload is opened, each full buffer becomes one part, and the upload is completed at the end.

Memory is therefore bounded by the part size, not by the object size: a 4 GB upload costs 8 MB of buffer. A failure at any point issues an AbortMultipartUpload, so a half-sent object never becomes readable and the bucket is not left paying for orphaned parts.

Why the responses are read with regular expressions

S3 answers in XML, and this file needs exactly two values out of it: the upload id, and an error code when a request fails. Adding an XML parser to the dependency set to extract two leaf elements from documents whose shape is fixed by the protocol would be the more expensive choice, not the safer one. Anything that needs the whole document is not a request this store makes.

class TomS3BlobStore

class TomS3BlobStore extends TomBlobStore

A blob store over an S3-compatible object store.

Constructors

TomS3BlobStore.new({required Uri endpoint, required String bucket, required String region, required TomAwsCredentials credentials, bool pathStyle = true, int partSize = defaultPartSize, String? keyPrefix, Client? client})

Creates a store for [bucket] at [endpoint].

[endpoint] is the service root without the bucket — https://s3.eu-central-1 .amazonaws.com, or http://127.0.0.1:9000 for a local MinIO.

[pathStyle] addresses objects as <endpoint>/<bucket>/<key>. It defaults to true because it is what every self-hosted implementation accepts, whereas virtual-host style (https://<bucket>.<endpoint>/<key>) needs wildcard DNS and a certificate to match. Set it false for Amazon, which prefers virtual-host addressing.

[partSize] is the multipart part size and the upload buffer bound, defaulting to [defaultPartSize]. S3 requires every part except the last to be at least [minimumPartSize], so values below that are rejected.

Stream<List<int>> _openObject(String key, {TomBlobRange? range})

The object at [key], optionally only [range] of it.

One body for both reads because everything below the header is the same request, and the reasoning about the 404, the failure and the yield* is what would have to be duplicated — and then kept in step — to have two.

S3 answers a ranged GET natively, which is the whole reason [TomBlobStore.doGetRange] is overridable: the bytes before the range never cross the wire. The header is inclusive at both ends, so the exclusive end this module carries is written as end - 1; an open-ended range is bytes=start-, which S3 reads as "to the end" without being told where that is. The response comes back 206, which the >= 300 check below already treats as success.

Signs and sends one request, turning a rejection into a named failure.

[operation] and [key] are what the caller is doing and to which object — not what this method is sending. They are separate parameters from [method] and [uri] because they answer a different question: an operator reading a failed request needs to know that a part upload stopped, and a caller needs its own key back. PUT /examplebucket/tenant-7/big.bin is neither, and is reported alongside rather than instead.

Map<String, String> _requestHeaders({required String method, required Uri uri, required Map<String, String> headers, required String payloadHash})

The signed headers to put on a request, minus host.

host is signed (the canonical request requires it) but not set here: the HTTP client derives the identical value from the URI, and dart:io rejects some attempts to override it.

String _prefixed(String key)

[key] under [keyPrefix], refused if the two are unusable together.

Both halves are already known to be valid on their own — the prefix at construction, the key by [TomBlobStore.put] and its siblings — so the only clause left is the one neither can settle alone: two keys inside [TomBlobStore.maxKeyLength] can join past it. S3 would not object, its own limit being twice ours, so the refusal has to come from here or from nowhere; without it this backend alone would store keys every other backend refuses.

Named against the prefix rather than the key because the key is the caller's and is fine: it is the deployment's prefix that leaves no room, for this key and every other one this store will be asked for.

Uri _objectUri(String key, Map<String, String> query)

The URL of [key], honouring [pathStyle] and [keyPrefix].

TomStorageException _failure(String operation, String key, Uri uri, int status, String body)

Builds the module's one "the store said no" error.

[key] is the caller's key, never the request path. Every error in this module and in [TomBlobStore] puts the caller's key under key, and a handler that logs or renders parameters['key'] cannot know that one backend meant something else by it. Under a [keyPrefix] the path is worse than merely unrecognisable — the prefix is typically the tenant, and the bucket is infrastructure detail.

The path is still reported, under [Uri.path] as objectPath. It is what an operator reading a rejected request actually needs, and autoLog: true means one will read it. The separate name is the point: rendering parameters wholesale then visibly opts into infrastructure detail instead of being handed it by a field called key.

static int minimumPartSize

S3's minimum size for any part but the last.

static int defaultPartSize

The default bytes per multipart part, 8 MiB.

Above [minimumPartSize] with room to spare, so the common case is not sitting on the protocol's floor, and small enough that the upload buffer it bounds stays a reasonable per-upload allocation.

Declared here rather than repeated at each defaulting site, for the same reason the table names are declared in database_blob_sql.dart: a default restated is a default that can diverge.

static String fileNameHeader

The header the original file name is carried in.

static String digestHeader

The header the content digest is carried in.

User metadata rather than a protocol header, because S3 has none that means this. x-amz-content-sha256 is the signature's payload hash, sent per request — on a multipart upload it is a part's hash, never the object's — and ETag is an MD5 only for single-part objects and an opaque string otherwise. Neither survives as a whole-object SHA-256, so the store records its own.
