SMS delivery: the segment arithmetic, the gateway mapping, and the failure classification that drives every retry decision downstream.

What SMS needs from the shared shape

Nothing of its own. [TomSmsTransport] is an ordinary [TomMessageTransport]: it takes the same [TomMessage] and returns the same [TomDeliveryReceipt] as SMTP, and the channel's peculiarities are carried by fields the shared types already have. [TomRecipient.address] is a phone number here rather than a mailbox, [TomMessage.metadata] carries the sender id, and the base's supportsCopies/supportsAttachments defaults of false are the right answer for a channel with neither. A second channel that fits without widening the contract is the evidence that the contract is about delivery rather than about email.

The classification rule

The transport's one judgement is whether a failure is worth repeating. SMS makes that harder than SMTP, because an SMS gateway answers on two levels and they routinely disagree: an HTTP 200 OK carrying {"status":"failed","code":21211} is an accepted request and a refused message. So the rule here has two layers:

LayerOwnerRule
HTTP status [TomDeliveryException.isTransientHttpStatus] 408 , 425 , 429 and 5xx are transient; every other non- 2xx is permanent
provider payload the deployment's [TomSmsGatewayProtocol] named codes are classified explicitly; an unrecognised code defers to the layer above

The second layer is configuration rather than code because the codes are a vendor's, not a protocol's, and a constant that hardcodes one vendor's numbering is a constant that starts lying the day the vendor renumbers.

No vendor presets

[TomFieldMappedSmsProtocol] can express the common gateways — field names, body format, response paths, error codes — but this file ships no TomTwilioProtocol or TomVonageProtocol. A preset for an API this repository cannot test against would be a plausible-looking guess that fails in production, and the failure would be attributed to the framework rather than to the guess. doc/messaging.md shows how to configure one instead.

class TomFieldMappedSmsProtocol

class TomFieldMappedSmsProtocol extends TomSmsGatewayProtocol

A protocol described by field names and response paths rather than by code.

Enough to reach the common HTTP gateways, all of which do the same thing in different words: post a destination, a sender and a body; read back an id and a status; report failures as codes. Naming those words in configuration rather than in a subclass per vendor is what keeps the transport free of vendor names — see the library dartdoc on why no presets ship.

class TomSmsSegmentation

class TomSmsSegmentation

How long a message is in the unit that is actually billed.

Characters are the wrong unit and every SMS integration that counts them eventually discovers why. Three rules make the count differ from text.length:

1. one character outside the GSM alphabet moves the whole message to UCS-2, cutting capacity from 160 to 70; 2. ten GSM characters — ^ { } \ [ ~ ] |, form feed and € — live in an escape table and cost two units each; 3. a message that does not fit one part is split, and each part spends seven bits on a concatenation header, so capacity drops to 153 (GSM) or 67 (UCS-2) per part — which means the 161st character adds a second segment holding eight characters, not one.

A character never straddles a segment boundary, so the packing here is greedy rather than a division: an 81-character message of € is two segments because the 77th euro sign would cross 153.

class TomSmsTransport

class TomSmsTransport extends TomMessageTransport

Delivers [TomMessageChannel.sms] through an HTTP gateway.

final transport = TomSmsTransport(
  TomSmsGatewaySettings.fromConfiguration(configuration)!,
  TomFieldMappedSmsProtocol(statusPath: 'status', /* ... */),
);
router.register(transport);

One HTTP request per recipient. A gateway that accepts a list would save requests and cost the receipt its per-number outcome, and partial delivery is the case that matters: one dead number in a list must not cost the others their message, exactly as a rejected RCPT TO does not in [TomSmtpTransport].
