The single column declaration of a table the framework itself owns.

The hole this closes

An application's tables are guarded by the CE-DB ↔ CE-MG convergence check: the entity model declares a shape, the migration chain builds one, and TomSchemaConvergenceCheck proves the two agree. The framework's own tables — the job queue, the lease table, the roll call, the blob pair, the audit trail — are not entities, so they sat outside that guard entirely, and each declared its columns twice: once in a CREATE TABLE string and again in the column lists of the statements that read and write it. Nothing related the two.

A column renamed on one side and not the other is a runtime failure on a path that may only ever execute in production — recoverAbandoned after a node dies, a chunk read of a large file — and the framework's own tables are the ones a deployment is least able to repair.

A [TomFrameworkTable] is that single declaration. Everything else is derived from it:

  • the create-if-missing DDL the stores issue ([createTableDdl]);
  • the column lists their statements interpolate ([columnList], [columnsOf]);
  • the INSERT/REPLACE shape ([insert]);
  • the [TomSchemaModel] the convergence guard compares — see

db_migration/framework_convergence.dart, which replays [createTableDdl] through the very same [TomSchemaDdlReader] the migration side uses, so the two sides cannot classify a type differently.

Why here and not in db_migration/

The stores that own these tables (scheduling/, file_storage/, audit/) already depend on datasources/ and must not be made to depend on the migration module — a deployment can use the scheduler without ever running a migration. The comparison, which is migration-shaped, lives in db_migration/ and depends on this file rather than the other way round.

What it deliberately does not do

It is not a query builder. The statements in these stores are conditional writes whose exact shape is load-bearing and documented at length — the affected-row count of UPDATE ... WHERE state = 'pending' is the arbitration — so rendering them from a template would trade a readable invariant for an unreadable one. What is generated here is the part that is pure repetition: the DDL and the column lists. Column references inside SET and WHERE clauses stay written out, and are guarded instead by [unknownFrameworkColumns], which audits the statements a store actually issues.

String insert(String verb, Map<String, String> values)

Renders a row-writing statement.

[verb] is the whole leading clause — INSERT, REPLACE, INSERT IGNORE. [values] maps a column name to the SQL text that supplies it, which is usually a :bind but may be a literal: the lease lock's first acquisition writes token and version as 1 and released as 0 in the same statement it binds the rest of.

Keying by column name rather than by position is deliberate. A positional list would put the column list and the value list in lock-step order, so inserting a column in the descriptor would silently shift every value one place along — which is a worse failure than the one this whole file exists to remove, because it type-checks.

function unknownFrameworkColumns

List<String> unknownFrameworkColumns(String sql, Iterable<TomFrameworkTable> tables)

The identifiers in [sql] that are not a column of any of [tables], not one of their names, and not SQL.

The guard for the half of a statement a column list cannot cover: the column references inside SET, WHERE and ORDER BY. Those stay written out — the exact shape of a conditional write is load-bearing and documented, so generating it would cost more than it saves — and are audited instead, by driving each store through a recording data source and passing every statement it issued through here.

Deliberately conservative in the direction that matters. String literals, :bind placeholders and numbers are removed before the scan, and a fixed set of SQL words is ignored; anything else that survives is reported. A word missing from that set is a false positive in a test, which is noisy and self-correcting, whereas a missed column reference is the production failure this exists to prevent.
