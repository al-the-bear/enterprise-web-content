Column-level access rights (C-4).

The kernel's [TomAuthState] four-state grade (none < disabled < read < full) is a presentation contract — the client renders a field editable, read-only, greyed-out, or hidden. C-4 makes the server honour the same grade authoritatively at the persistence boundary, so a hostile or buggy client cannot read a column it may not see or write one it may not change:

  • Read masking. A column the principal cannot see (state without

[TomAuthState.showsContent] — none/disabled) is nulled out of every row the repository returns, so its value never leaves the server. - Write enforcement. A change to a column the principal is not full on is rejected when the column is visible (read) — the caller could see the value, so changing it is a genuine violation — and silently overlaid from the stored value when the column is masked (none/disabled), so a round-tripped masked-null never clobbers the stored value.

A column opts in through [TomDbColumn.authKey], or through the kernel's @TomProtectedField on the entity field — the same annotation the JSON serializer honours. The repository resolves the key to a [TomAuthState] through a resolver, by default [TomResourceKeyProtection.automaticState]: the installed [TomAuthorization] adapter's grade met with the request principal's resource-key grade. A column with no key is unrestricted, so entities that declare none keep their behaviour exactly.

This is the database tier of the kernel's automatic protection, and it applies only while [TomResourceKeyProtection.globalSettingUseAutomaticDatabaseProtection] is on — its default. Switched off (tom.protection.database=false), every column is unrestricted, per-row resolvers included.

The decision ([decideWrites], [maskedColumns], [stateForKey]) is pure and reflection-free: it takes value/­key accessors as callbacks so the same algorithm drives the repository's reflection path and a sample's DTO path, and can be unit-tested without a database or the reflection runtime. The reflection-backed I/O ([applyReadMask]) lives beside it for the repository.

class TomColumnAuthorization

class TomColumnAuthorization

The C-4 decision algorithm, pure over abstract column tokens.

Both the SQL repository (over reflected [TomColumnInformation]) and a service-layer field check (over its own field descriptors) call these; they supply value/key accessors and — for a rejection — their own exception, so the single algorithm serves every enforcement point.

static TomColumnWriteDecision<C> decideWrites<C>({required Iterable<C> columns, required String? Function(C) gradeOf, required bool Function(C) changed, required Never Function(C, String, TomAuthState) onForbidden, TomAuthState Function(String)?? resolver})

Partitions [columns] into the ones the caller may write and the ones whose baseline value must be preserved, rejecting an unauthorized visible change.

For each column, [gradeOf] gives its resource key (or null = unrestricted) and [changed] whether the incoming value differs from the baseline. The grade decides the outcome:

  • [TomAuthState.full] → writable (the incoming value is persisted);
  • [TomAuthState.read] (visible, not editable) → if [changed], the caller is

altering a value they can see but not edit: [onForbidden] is invoked (and must not return); if unchanged, the column is preserved; - [TomAuthState.disabled] / [TomAuthState.none] (masked) → preserved unconditionally, so a round-tripped masked-null cannot clobber the stored value and cannot itself constitute a violation.

static T applyReadMask<T extends Object>(T instance, List<TomColumnInformation> columns, {TomAuthState Function(String)?? resolver})

Nulls out — in place — every field of [instance] the principal may not see (the [maskedColumns] of [columns]); returns [instance] for chaining.

The masked fields must be nullable on the entity (a masked value becomes null); an entity opts a column into masking by declaring its [TomDbColumn.authKey], and such columns are modelled nullable so the value can be withheld.

A column with a per-row resolver ([TomRowColumnAuthorization]) is skipped: its grade is not a column-wide fact, and a row projection — one synchronous answer applied to a whole result set — has no authority to decide it. Such a column is gated where its grade can actually be resolved, in the file operations that address a single row. Masking it here would additionally be self-defeating: the masked value is the blob key the gate then needs to read.

class TomColumnAuthorizationException

class TomColumnAuthorizationException extends TomServerException

Thrown when a write changes a column the current principal is not authorized to change (C-4): the column is visible to the principal (state [TomAuthState.read]) but not [TomAuthState.full], so altering its value is a genuine, rejectable violation rather than a masked-value round-trip.

class TomRowColumnAuthorization

class TomRowColumnAuthorization

Per-row column grades (C-4), for columns whose grade depends on which row is addressed rather than only on who is asking.

[TomColumnAuthorization] resolves a column's authKey through [TomResourceKeyProtection.automaticState], which is a pure key → state function of the caller: it can express "this principal may not see salaries", but not "this principal may edit the attachment of the items in the project they own and only read the ones in a project shared with them". A deployment whose grades are relational — derived from the caller's role on the row's owning aggregate — cannot be expressed that way, and cannot be computed synchronously either, because the role lives in another table.

This registry is the column-grade counterpart of [TomDataScopeRegistry.registerAsync]: a resolver is registered once at boot against the column's authKey, and is awaited per operation with the current principal and the row's id. Registration is process-wide and the resolver is stateless by contract — it reads the request's principal from its argument, never from a field — so one registration serves every concurrent request.

Only the file operations consult it. saveFile, openFile and describeFile each address exactly one row and are already asynchronous, so awaiting a grade there costs nothing extra. The row-projection paths ([applyReadMask], [decideWrites]) are synchronous and operate on whole result sets, and are deliberately left on the column-wide resolution: a per-row grade there would mean a cross-table read per row per column. 

// At boot:
TomRowColumnAuthorization.register(
  'todo.item.attachment',
  (principal, rowId) => grades.attachmentGradeFor(principal, rowId),
);

The per-row grade for [authKey] on the row keyed by [rowId], or null when the column is unrestricted (authKey == null) or has no per-row resolver — in which case the caller keeps its own column-wide resolution. While the database tier is switched off ([TomResourceKeyProtection.globalSettingUseAutomaticDatabaseProtection]) the resolver is not consulted and the grade is [TomAuthState.full].

The principal is read from the current zone, exactly as the C-3 row scope reads it, so a resolver sees the same caller the rest of the request does.

typedef TomColumnAuthResolver

typedef TomColumnAuthResolver = TomAuthState Function(String)

Resolves a column's [TomDbColumn.authKey] to the current principal's [TomAuthState] for that resource key.

The repository's default resolver is [TomResourceKeyProtection.automaticState]; tests pass a stub mapping keys to states.

typedef TomRowColumnAuthResolver

typedef TomRowColumnAuthResolver = Future<TomAuthState> Function(TomPrincipal?, Object?)

Resolves the [TomAuthState] a [principal] holds on one authorized column of a specific row, asynchronously.

[rowId] is the row's primary key as the repository read it; a null id means the row does not exist yet (an insert).
