The audit record — what an auditable action leaves behind (CE-LG).

An audit trail answers one question: who did what to which record, when, and did it work? That is a different question from the one diagnostic logging answers ("why did this fail?"), and the difference is not stylistic:

Diagnostic logAudit trail
Readeran operator debugging a failurean auditor reconstructing history
Retentiondaysyears, often statutory
Integrity best effort; rotation truncates freely append-only, tamper-evident
Completeness sampling and level filters are fine a missing entry is a finding
Contentwhatever helps diagnosisa fixed, attributable schema

Those columns conflict at every row, which is why this module does not extend the kernel's logging subsystem: a trail that shares retention and mutability with tomLog output is a trail nobody can rely on.

class TomAuditActor

class TomAuditActor

Who performed an audited action.

Attribution is the property an audit trail exists for, so it is never left blank: an action performed with no principal in the zone is attributed to [systemUsername] rather than to null. "The framework did this on its own behalf" and "we failed to record who did this" must not look alike in the trail, and an absent field cannot distinguish them.

factory TomAuditActor.fromPrincipal(TomPrincipal? principal)

Reads the actor from [principal], or returns [system] when it is null.

TomPrincipal spells "unset" as -1 for its three ids. That sentinel is meaningful inside the principal and meaningless in a trail an auditor reads years later, so it is normalised to null here — and null is then omitted by [toJson] rather than recorded as a user who does not exist.

factory TomAuditActor.fromCurrentZone()

Reads the actor from the current zone's [TomPrincipal].

The zone is the framework's ambient principal carrier — the endpoints pipeline installs it per request — so both chokepoints resolve the actor the same way without threading it through their signatures. A repository write reached from a background job simply finds no principal and is attributed to [system].

class TomAuditRecord

class TomAuditRecord

One entry in the audit trail: an attributable statement that an action happened.

The record is immutable. Nothing downstream may adjust an entry after the fact — that is half of what "tamper-evident" means, and the other half (detecting a change made outside the API) is the sink's hash chain.

before / after

[before] and [after] carry only the fields that actually changed, in their database representation. Two reasons for the narrowing:

  • A full row image on every update multiplies the trail's size by the row

width, and the unchanged columns add nothing an auditor can use. - Fields an entity marks as redacted never appear at all, so a password hash or an access token cannot be exfiltrated by reading the trail.

Values that a C-4 column grade would mask from the caller are recorded here in the clear. The trail is the authoritative record of what changed; masking it would produce entries stating that something changed to null, which is worse than useless. The trail is therefore privileged storage, and an entity that must never expose a value even to an auditor redacts it.

Unknown enum names fall back to [TomAuditAction.execute] / [TomAuditOutcome.failed] rather than throwing: a reader must be able to process an old trail written by a version that had a value this one does not, and refusing to parse would make the archive unreadable.

Properties

final String id

Unique id of this entry.

final DateTime timestamp

When the action happened, in UTC.

UTC without exception: a trail whose entries are written by servers in different zones cannot be ordered otherwise, and ordering is the first thing an auditor needs.

final TomAuditActor actor

Who performed the action.

final TomAuditAction action

What kind of action it was.

final String target

What it acted on — an entity type name, or an endpoint route.

final String? targetKey

The key of the affected record, when the action names one.

final TomAuditOutcome outcome

How the action ended.

final String? requestId

The id of the request the action was performed under, when there was one.

This is what stitches an endpoint denial together with the repository writes of the same request, so a trail can be read as a sequence of user interactions rather than a flat list of events.

final Map<String, Object?> before

The changed fields' prior values; empty for a create.

final Map<String, Object?> after

The changed fields' new values; empty for a delete.

final String? detail

A human-readable note — the denial reason, the exception message.

Methods

Map<String, Object?> toJson()

The record as a JSON map.

Key order is fixed and empty collections are omitted, so the encoding is canonical — the sink hashes this, and a hash over a map whose iteration order varied would break the chain for no reason.

String toString() override

Static

static Map<String, Object?> _encodableValues(Map<String, Object?> values)

[values] with every entry converted to something jsonEncode accepts.

The images are filled straight from an entity's fields, so whatever a column holds arrives here — and the record is JSON-encoded three times over: the chain hash, the file sink's line, the SQL sink's column. That makes encodability an invariant of the record, not of one writer, which is why it is established in the constructor beside [timestamp]'s coercion rather than in [toJson]. [TomAuditRecord.fromJson] builds through this constructor too, so the conversion has to be idempotent — it is, because everything it produces is already encodable and passes through untouched.

The invariant has to hold here rather than at the writers because the repository's _audit is deliberately uncaught: a value the trail cannot encode would not merely spoil the record, it would fail the mutation being audited. An entity with a DateTime column is the ordinary case, not an exotic one, so nothing about auditing an entity may depend on its columns happening to be JSON primitives.

static Object? _encodable(Object? value)

One value, converted only if jsonEncode would refuse it.

DateTime uses the same ISO-8601-in-UTC form as [timestamp], so a single record does not spell a moment two ways. Anything else unrecognised falls back to [Object.toString] rather than raising: the trail's job is to say that a field changed, and refusing here would make the framework cancel the operation instead of describing it approximately.

enum TomAuditAction

enum TomAuditAction

What kind of action a [TomAuditRecord] describes.

Deliberately small. These are the categories an auditor reasons in; the specific operation is carried by [TomAuditRecord.target] and [TomAuditRecord.detail], which are free-form.

Values

create

A new record was created (a repository INSERT).

update

An existing record was modified (a repository UPDATE).

delete

A record was destroyed (a repository DELETE).

read

A record was read.

The only action nothing in the framework produces. No repository read is audited and no annotation makes one audited — a record with this action exists because application code called TomAuditTrail.recordAction and said so. The value stays in the enum precisely so that call has a truthful category to use; see the audit_trail library comment for why the framework declines to make the choice itself.

execute

An action was invoked that is not itself a record mutation — an endpoint call, a job run, a report export.

enum TomAuditOutcome

enum TomAuditOutcome

How the audited action ended.

Values

succeeded

The action completed.

failed

The action was attempted and raised.

denied

The action was refused before it ran — authentication, authorization, row scope or column grade.

Distinct from [failed] on purpose. A failure is an operational event; a denial is a security event, and it is the one an auditor scans for first. Collapsing the two would bury attempted access in among timeouts.
