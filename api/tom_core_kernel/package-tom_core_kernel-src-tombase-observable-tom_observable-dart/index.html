class TomFunctionObserver

class TomFunctionObserver<T extends TomObservable> implements TomObserver<T>

A wrapper that allows using a callback function as a [TomObserver].

This is what the >> operator ([TomObservableObservation.operator >>]) creates, so [T] is normally inferred from the observable the operator was applied to.

The wrapper must be retained for as long as notifications are wanted. [TomObservable] holds its observers by [WeakReference], so this wrapper is the only strong reference keeping the callback alive; if it is not captured, it can be garbage-collected and the callback silently stops firing. Store it (e.g. in a field) and remove it explicitly via [TomObservable.removeObserver] when done — do not use the fire-and-forget form myObservable >> (obs) => ...;.

Example:

final observer = myObservable >> (obs) => print('Changed!');
// Later, to stop observing:
myObservable.removeObserver(observer);

class TomObservable

class TomObservable

A base class that implements the Observer pattern, allowing objects to be observed for changes.

[TomObservable] maintains a list of [TomObserver] instances that are notified when changes occur. Observers are held via [WeakReference] to prevent memory leaks - if an observer is garbage collected, it will be automatically removed from the observer list.

Notifications can be muted temporarily so that a run of changes surfaces as a single notification instead of one per change. Use [batch] for that — it releases the mute even when the body throws. [mute] and [unmute] are the unscoped form; they nest, so a batching method may be called from inside a caller's batch without cutting it short.

Example usage:

class MyModel extends TomObservable {
  String _name = '';

  set name(String value) {
    _name = value;
    notifyObservers();
  }
}

class MyView extends TomObserver<MyModel> {
  @override
  void onNotify(MyModel observable) {
    // React to changes
  }
}

int _muteDepth

How many mutes are currently held. Zero means notifications flow.

A counter rather than a flag so that batches nest: a batching method called from inside an enclosing batch must suppress its own notifications without releasing the caller's.

bool _dirty
final List<List<TomObservable>> _cascades

The cascade targets of each still-open mute, innermost last.

Invariant: _cascades.length == _muteDepth. Each [mute] snapshots the targets it silenced and each [unmute] releases exactly that snapshot, so membership changes made during a batch cannot unbalance it — an element added mid-batch was never muted here and is not released here, and one removed mid-batch was muted here and still is released here.

final Set<_ObserverRef> _observers

The registered observers, in registration order.

A set rather than a list because [addObserver] must reject a duplicate, and looking one up by walking the collection made attaching n observers cost O(n^2) comparisons — a bill a [TomList] pays in full, since it registers itself with every element it holds. [_ObserverRef] carries the identity hash of its target, so membership is an O(1) lookup. The default [Set] is insertion-ordered, so observers are still notified in the order they registered.

Methods

void mute()

Mutes all observer notifications, and those of [muteCascadeTargets].

While muted, calls to [notifyObservers] mark the observable as dirty instead of notifying. The matching [unmute] delivers a single consolidated notification if anything was marked dirty.

Mutes nest. Each call must be matched by exactly one [unmute]; notifications resume only when the outermost one is released. This is what lets a batching mutator be called from inside a caller's batch without cutting it short.

Prefer [batch], which cannot leak a mute on the throwing path.

void unmute()

Releases one [mute].

The cascade targets this mute silenced are released first, while this object is still muted, so any notification they emit collapses into this object's single notification rather than escaping as one of its own.

When the last mute is released and [notifyObservers] was called while muted, observers are notified once.

Releasing more often than muting is a no-op rather than an error: the depth floors at zero, so a stray call cannot poison later batches.

void _muteSelf()

Mutes this observable without cascading to [muteCascadeTargets].

Used by the batching mutators on the composites, which consolidate their own notifications but must leave the elements' own observers alone.

T batch<T>(T Function() body)

Runs [body] with notifications muted, releasing the mute afterwards.

The scoped form of [mute] / [unmute], and the one to reach for: the release happens in a finally, so a throwing [body] cannot leave the object silent for the rest of its life. Nests like [mute] does. 

list.batch(() {
  list.add(a);
  list.add(b);
}); // one notification

Returns whatever [body] returns.

T batchSelf<T>(T Function() body)

Runs [body] with this observable's notifications muted, without cascading to [muteCascadeTargets].

A composite mutator that makes several internal edits uses this to surface them as one notification, while leaving observers of the individual elements to hear about their own changes as they happen.

Returns whatever [body] returns.

void addObserver(TomObserver<TomObservable> observer)

Registers an observer to receive change notifications.

The observer is stored as a [WeakReference], so it will be automatically removed if it is garbage collected. This prevents memory leaks from observers that are no longer in use.

If the observer is already registered, this method does nothing. "Already registered" means the same object, not an equal one: an observer that overrides == is still distinct from its equals.

void removeObserver(TomObserver<TomObservable> observer)

Unregisters an observer so it no longer receives change notifications.

If the observer is not registered, this method does nothing.

void notifyObservers()

Notifies all registered observers of a change.

If the observable is currently muted (via [mute]), this method will mark the observable as dirty but will not notify observers. Observers will be notified when [unmute] is called.

This method also cleans up any weak references to observers that have been garbage collected.

Observers are told that this observable changed, not what changed: each receives the observable itself and reads its current state. There is deliberately no payload, and the reason is the mute contract rather than taste. While muted, calls here only mark the observable dirty, and the matching [unmute] sends a single notification for all of them — cascade targets' notifications included. A per-call message could not survive that: the one notification sent would have to carry one of the collapsed messages and drop the rest, and a caller batching through [batch] would see its payloads disappear depending on whether anyone else held a mute. Reading state from the observable gives the same answer however many changes were collapsed.

class TomObserver

abstract class TomObserver<T extends TomObservable>

Abstract base class for objects that want to observe changes in a [TomObservable].

Implementers must override [onNotify] to handle change notifications.

The type parameter [T] specifies the type of observable this observer can observe, allowing for type-safe access to the observable's properties.

Example:

class MyModelObserver extends TomObserver<MyModel> {
  @override
  void onNotify(MyModel observable) {
    print('Model changed: ${observable.name}');
  }
}

class _ObserverRef

class _ObserverRef

A weakly-held, identity-keyed handle on one registered [TomObserver].

Holding the observer through a [WeakReference] is the whole point of the registry — the observable must not keep its observers alive. The identity hash is captured at construction rather than computed on demand, so the handle keeps the same hash after its target has been collected and stays findable in the set; a dead entry that could not be found again could not be pruned either.

Equality is identity of the target, deliberately. It is what the linear scan this replaced compared on, and it is the behaviour that matters: two observers that declare themselves == are still two observers, and both get notified.

extension TomObservableObservation

extension TomObservableObservation<T extends TomObservable> on T

Adds the observation operator >> to every [TomObservable].

An extension rather than a method on [TomObservable] because the whole point is the receiver's type: an extension type parameter is inferred from the expression it is applied to, so count >> … on a TomInt yields a TomFunctionObserver<TomInt> and hands the callback a TomInt, while a method on the base class could only ever promise TomObservable. This works for classes the framework has never heard of — a user's Person extends TomClass gets TomFunctionObserver<Person>.

Operators

TomFunctionObserver<T> operator >>(void Function(T) callback)

Registers [callback] as an observer: count >> (obs) => print(obs.get()).

The callback runs whenever this observable notifies its observers, and receives the observable itself — typed as the receiver was, so a TomInt's callback can read obs.get() as an int with no cast.

Returns the [TomFunctionObserver] wrapper, which can later be passed to [TomObservable.removeObserver].

You must retain the returned observer for as long as you want notifications. Observers are held by [WeakReference] (see [TomObservable.addObserver]), so the returned wrapper is the only strong reference keeping the callback alive. If you discard it — the fire-and-forget form myObservable >> (obs) => print('Changed!'); — the wrapper becomes eligible for garbage collection and the callback silently stops firing at a nondeterministic later time. Always capture the result: 

// Keep `observer` alive (e.g. in a field) for as long as you observe:
final observer = myObservable >> (obs) => print('Changed!');
// Later, to stop observing:
myObservable.removeObserver(observer);

The wrapper is bound to the observable that produced it. Registering it on a different observable that is not a [T] fails at notification time — which is the point: the callback was written against a [T].
