import 'package:tom_core_kernel/src/tombase/resources/tom_resource_provider.dart';

Resource providers for managing application text resources and configuration.

This library provides singleton-based resource management for: - Text resources: Localized strings, UI labels, and messages - Configuration resources: Application settings and environment configuration

Both providers support hierarchical key access using dot notation (e.g., 'app.title') and can be initialized from JSON maps or loader functions.

Bootstrap

Both providers must be installed explicitly during startup, before anything reads from them; an uninstalled lookup throws rather than bootstrapping itself. Applications with no bundle install an empty one — every lookup then echoes its key, which is the intended degradation.

Example

// Install the bundles once, at startup.
TomTextResourceProvider.setAppResourceProvider(
  TomTextResourceProvider.from({
    'app': {'title': 'My App', 'version': '1.0.0'},
    'messages': {'welcome': 'Hello, World!'},
  }),
);

// Access resources anywhere in the app
final resources = TomTextResourceProvider.getAppResources();
print(resources.getText('app.title')); // 'My App'
print(resources.getText('messages.welcome')); // 'Hello, World!'

class TomConfigResourceProvider

class TomConfigResourceProvider

A singleton provider for managing configuration resources in the application.

[TomConfigResourceProvider] is designed for storing and retrieving configuration values such as API endpoints, feature flags, timeouts, and other application settings.

Usage

Setting up with a loader function

// Install once at startup; the loader runs here, not at first access.
TomConfigResourceProvider.setAppConfigProvider(
  TomConfigResourceProvider.load(() => jsonDecode(bundledConfig)
      as Map<String, dynamic>),
);

// Access configuration throughout the app
final config = TomConfigResourceProvider.getAppConfig();
final apiUrl = config.getObjectOrNull('api.baseUrl') as String? ?? '';
final timeout = config.getObjectOrNull('api.timeout') as int? ?? 5000;

[getObjectOrNull] rather than [getObject] here because [getObject] echoes the key back as a String on a miss, so as int throws — see [getObject].

Setting up from an asynchronous source

The loader is synchronous, so a configuration file that only arrives via a Future is awaited before the install and handed to [TomConfigResourceProvider.from] — the same shape as [TomTextResourceProvider], and usually the same initializeResources(): 

final contents = await readAsset('assets/config.json');
TomConfigResourceProvider.setAppConfigProvider(
  TomConfigResourceProvider.from(jsonDecode(contents) as Map<String, dynamic>),
);

Setting up with a custom provider

final customConfig = TomConfigResourceProvider.from({
  'api': {
    'baseUrl': 'https://api.example.com',
    'timeout': 30000,
  },
  'features': {
    'darkMode': true,
    'analytics': false,
  },
});
TomConfigResourceProvider.setAppConfigProvider(customConfig);

Checking configuration existence

if (config.exists('features.experimental')) {
  enableExperimentalFeatures();
}

Methods

bool exists(String s)

Checks if a configuration value exists at the given path.

Supports both flat keys (e.g., 'timeout') and hierarchical paths using dot notation (e.g., 'api.timeout').

[s] - The configuration key or path to check.

Returns true if any value exists at the path, false otherwise.

Object getObject(String s)

Retrieves the configuration value at the given path.

Supports both flat keys (e.g., 'timeout') and hierarchical paths using dot notation (e.g., 'api.timeout').

On a miss this returns the key itself, as a String — the same lenient fallback the text provider uses, which makes a missing key visible rather than fatal. For configuration that has a sharp edge: the caller wanted an int or a bool, so a direct cast throws. 

config.getObject('api.timeout') as int   // 30000 when present
config.getObject('api.retries') as int   // throws: String is not int
config.getObject('api.retries') as int?  // throws too — the miss value is
                                         // a non-null String, not null

The TypeError names String and int and never names the key, so it tells you nothing about which setting is missing. Use [getObjectOrNull] with a default instead — it is one lookup, and a miss cannot throw: 

final timeout = config.getObjectOrNull('api.timeout') as int? ?? 5000;

Cast [getObject] directly only where a miss is genuinely impossible, or behind an [exists] guard.

[s] - The configuration key or path to retrieve.

Returns the value if found (can be any type), or the key [s] if not found.

Object? getObjectOrNull(String s)

Retrieves the configuration value at the given path, or null when it is absent.

The presence-reporting counterpart to [getObject], mirroring [TomTextResourceProvider.getObjectOrNull]. Prefer it whenever the value is going to be cast: because a miss is null rather than the echoed key, a nullable cast with a default expresses "use the configured value, else this" in one lookup and one line. 

final timeout = config.getObjectOrNull('api.timeout') as int? ?? 5000;
final dark = config.getObjectOrNull('features.darkMode') as bool? ?? false;

A configured value of the wrong type still throws, which is the intent — that is a broken configuration file, not an absent setting.

[s] - The configuration key or path to retrieve.

Returns the value if found (can be any type), or null if not found.

Static

static TomConfigResourceProvider? _configProvider

The singleton instance of the configuration provider.

static Map<String, dynamic> Function()?? loader

Optional loader function consulted by the default constructor.

Declares how to build the configuration; [setAppConfigProvider] decides when it is installed. Setting this on its own installs nothing, and it stays set afterwards, so every later bare TomConfigResourceProvider() is populated from it — see [TomTextResourceProvider.loader] for the two-phase pattern, that process-wide coupling, its single-statement alternative [TomConfigResourceProvider.load], and why asynchronous sources are awaited before the install rather than inside a loader.

static void setAppConfigProvider(TomConfigResourceProvider provider)

Sets the application-wide configuration provider instance.

Use this method to replace the default provider with a custom pre-configured instance.

Announces nothing, by design. Unlike [TomTextResourceProvider.setAppResourceProvider] there is no revision to bump: configuration is installed at bootstrap and captured by its consumers when they are built — a declared client setting takes its baseline at declaration, a TomProperty at construction — so a counter would notify nothing that could act on it. Nor does it borrow [TomTextResourceProvider.appResourcesRevision]: re-rendering every text observer for a configuration change would cost what a counter costs without meaning what it means.

Replacing the provider later is allowed, and every read made after the call answers from the new one; a value captured before it is not updated. An application that replaces configuration at a session boundary — a per-user bundle after sign-in — rebuilds what depends on it itself. A revision counter becomes worth adding only when configuration has to change under a running screen.

[provider] - The provider instance to use application-wide.

static void clearAppConfigProvider()

Returns the process to the un-bootstrapped state, where [getAppConfig] throws again. See [TomTextResourceProvider.clearAppResourceProvider].

static TomConfigResourceProvider getAppConfig()

Returns the application-wide configuration provider.

Throws resources.config_provider.not_installed when [setAppConfigProvider] has not run. Configuration has no revision counter to keep honest, so this provider does not share the text provider's specific defect; it shares the contract because the two are used side by side, and a module in which one sibling refuses an unbootstrapped lookup while the other quietly answers "not configured" teaches nothing a caller can rely on.

class TomTextResourceProvider

class TomTextResourceProvider

A singleton provider for managing text resources in the application.

[TomTextResourceProvider] is designed for storing and retrieving text-based resources such as localized strings, UI labels, error messages, and other text content that may vary by locale or configuration.

It also holds values that are not Strings. [existsObject], [getObject] and [getObjectOrNull] resolve a value of any type, which is what lets the look-and-feel settings that travel with the text — TextStyles, Colors, and similar — live in the same bundle instead of a second one. The bundle is a Map<String, dynamic> either way; "text" names what the resources are for, not what type they are.

The String family ([getText], [getTextOrNull], [exists]) reports a non-String value as absent, so a Color is read with [getObject], not [getText]. Do not move such a value to [TomConfigResourceProvider] on account of its type: configuration is a different purpose, its accessors are a strict subset of these, and it has no [appResourcesRevision] to re-render from.

The provider supports: - Singleton access via [getAppResources], after an explicit install - Hierarchical key access using dot notation - Deferred loading with a loader function, separate from installation - Direct initialization from a map

Usage

Setting up with a loader function

// Install once at startup; the loader runs here, not at first access.
TomTextResourceProvider.setAppResourceProvider(
  TomTextResourceProvider.load(() => jsonDecode(bundledStrings)
      as Map<String, dynamic>),
);

// Access resources throughout the app
final resources = TomTextResourceProvider.getAppResources();
String title = resources.getText('screens.home.title');

Setting up from an asynchronous source

The loader is synchronous by design — [getText] is synchronous, so the bundle has to be in memory before anything reads it, and a constructor cannot await. A source that only yields a Future (an asset, a file, a downloaded pack) is therefore awaited before the install, and the resolved map is handed to [TomTextResourceProvider.from]:

readAsset is the target's own asynchronous read — rootBundle.loadString in a Flutter app, (path) => File(path).readAsString() on a server. This package has no Flutter dependency, so the application supplies it. 

Future<void> initializeResources(
  Future<String> Function(String assetPath) readAsset,
) async {
  final strings = await readAsset('assets/strings.json');
  TomTextResourceProvider.setAppResourceProvider(
    TomTextResourceProvider.from(jsonDecode(strings) as Map<String, dynamic>),
  );
}

// Called once at startup, before anything reads a resource.
Future<void> main() async {
  await initializeResources(readAsset);
}

Setting up with a custom provider

final customProvider = TomTextResourceProvider.from({
  'greeting': 'Hello',
  'farewell': 'Goodbye',
});
TomTextResourceProvider.setAppResourceProvider(customProvider);

Checking resource existence

if (resources.exists('optional.message')) {
  showMessage(resources.getText('optional.message'));
}

Static

static TomTextResourceProvider? _resourceProvider

The singleton instance of the text resource provider.

static Map<String, dynamic> Function()?? loader

Optional loader function consulted by the default constructor.

This declares how to build the bundle; [setAppResourceProvider] decides when it is installed. The split lets a platform layer name the source in one place while startup code installs it at the right moment: 

TomTextResourceProvider.loader =
    () => jsonDecode(bundledStrings) as Map<String, dynamic>;
// ... later, in main():
TomTextResourceProvider.setAppResourceProvider(TomTextResourceProvider());

The signature is synchronous, and deliberately so: [getText] is synchronous, so the map must exist by the time the constructor returns. The loader therefore only fits sources that can be produced without awaiting — a computed map, a compiled-in constant, an already-decoded string. Anything asynchronous (assets, files, network) is awaited in main() and installed with [TomTextResourceProvider.from]; see the class documentation.

Setting this on its own installs nothing: [getAppResources] does not bootstrap itself, and will throw until the install above has run.

It is also process-wide and persistent, which is the cost of the split. The field is not consumed by the construction it was set for: it stays set until something assigns null, and every later bare TomTextResourceProvider() — including one built for a purely local scope, far from the startup code that set it — is populated from it rather than starting empty. That is action at a distance, so set it once during bootstrap and leave it alone. Test suites that exercise the default constructor have to clear it between cases for the same reason.

When both halves live in the same place, prefer [TomTextResourceProvider.load]: it takes the loader as an argument, so it populates the one provider being built and leaves no static state behind.

static TomInt appResourcesRevision

Observable revision counter for the application-wide text bundle.

Incremented every time the installed bundle changes — either because [setAppResourceProvider] installed a different provider, or because the [resources] map of the installed provider was replaced. Observe it to re-derive anything computed from the bundle (localised labels, in particular) when the application switches locale: 

// Retain the observer — observers are held weakly.
final observer = TomTextResourceProvider.appResourcesRevision
    >> (_) => rebuildLabels();

In-place mutation of the map (resources['a'] = 'b') cannot be detected; call [notifyAppResourcesChanged] after such an edit.

static void notifyAppResourcesChanged()

Announces that the application-wide text bundle has changed.

Bumps [appResourcesRevision], which notifies its observers. Call this after mutating the installed provider's [resources] map in place; installing a provider or assigning a new map does it automatically.

static void setAppResourceProvider(TomTextResourceProvider provider)

Sets the application-wide text resource provider instance.

Use this method to replace the default provider with a custom pre-configured instance. Bumps [appResourcesRevision] so that text derived from the bundle can be re-resolved.

[provider] - The provider instance to use application-wide.

static void clearAppResourceProvider()

Returns the process to the un-bootstrapped state, where [getAppResources] throws again.

Deliberately does not bump [appResourcesRevision]. The revision exists so that observers can re-derive text from the new bundle, and after a clear there is no bundle to re-derive from — every observer's reaction would throw. Uninstalling is a teardown step, and teardown has no readers.

Tests need this because installation is otherwise one-way: [getAppResources] refuses to bootstrap itself, so the very first install can only be observed by a test that can get back to "nothing installed".

static TomTextResourceProvider getAppResources()

Returns the application-wide text resource provider.

Throws resources.text_provider.not_installed when [setAppResourceProvider] has not run. There is deliberately no lazy bootstrap: a self-installing lookup would put a bundle in place without bumping [appResourcesRevision], leaving observers registered before the first lookup showing raw keys for a bundle that had in fact been loaded. Because installation now happens in exactly one place, and that place notifies, the counter and the installed bundle cannot disagree.

An application with no text resources still installs one — an empty bundle makes every lookup echo its key, which is the intended degradation. Not installing at all is a bootstrap bug, and this reports it at the first read rather than rendering the whole UI in raw keys.

function _resolveStringOrNull

String? _resolveStringOrNull(Map<String, dynamic> resources, String path)

Resolves the String value at [path] in [resources].

Returns the tree value when the dotted [path] resolves to a String, otherwise the flat-key value when it is a String, otherwise null. Backs the text-family accessors, which only surface String content. The flat-key leg is consulted even when the tree walk lands on a non-String value, so a literal dotted key (e.g. 'a.b') still resolves.
