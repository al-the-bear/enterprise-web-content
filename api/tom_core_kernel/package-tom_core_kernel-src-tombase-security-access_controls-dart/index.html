import 'package:tom_core_kernel/src/tombase/security/access_controls.dart';

Access control system for the Tom framework.

This library provides a comprehensive access control system that enables fine-grained authorization for resources, endpoints, and data fields. It supports multiple authorization paradigms including:

  • Role-based access control (RBAC): Grant access based on user roles
  • Group-based access control: Grant access based on group membership
  • Entitlement-based access control: Grant access based on entitlements
  • Resource key protection: Protect individual data fields or resources
  • Custom access handlers: Implement custom authorization logic

Usage Example

// Check if a resource is accessible
if (!tomProtected('user.email')) {
  displayEmail(user.email);
}

// Use access control annotations on endpoints
@TomRoleAccess(['admin', 'manager'])
void deleteUser(int userId) { ... }

// Use entitlement-based access
@TomEntitlementAccess(['feature.premium.*'])
void runPremiumFeature() { ... }

See also: - [TomPrincipal] for the authenticated user context - [TomAccessControlInformation] for the user's access rights

class TomAccessControl

abstract class TomAccessControl

Abstract base class for all access control types.

Extend this class to implement custom access control logic. All access control implementations must override [checkPrincipalAccess] to determine if a [TomPrincipal] should have access.

Built-in Implementations

  • [TomNoAccess]: Denies all access
  • [TomPublicAccess]: Allows all access
  • [TomAuthenticatedAccess]: Requires authenticated user
  • [TomGuestAccess]: Allows guests and authenticated users
  • [TomRoleAccess]: Requires specific roles
  • [TomGroupAccess]: Requires group membership
  • [TomEntitlementAccess]: Requires specific entitlements
  • [TomResourceKeyAccess]: Checks resource key protection
  • [TomCustomAccess]: Delegates to custom handler
  • [TomGradedAccess]: Composes three of the above into all four

[TomAuthState] values — the only built-in that can resolve to [TomAuthState.disabled] or [TomAuthState.read]

Two operands: the user and the deployment

Evaluation has two operands, not one. A user's grant is met with the grant of the deployment the code is running in — the ambient server principal ([TomServerPrincipal]) — and the effective answer is the more restrictive of the two: min(user, server) over the four-state ladder, binary AND for two-state controls. A user's [TomAuthState.full] on a feature this deployment is not entitled to evaluates to [TomAuthState.none]. The deployment's grants cap every user's grants; they never widen them.

What subclasses implement

The public entry points [checkAccessibility] and [resolveAuthState] compute that meet and are not overridable — a cap that any subclass could sidestep by overriding the method everybody already calls would not be a cap at all. Subclasses instead implement the two hooks:

  • [checkPrincipalAccess] / [resolvePrincipalAuthState] — the user operand:

what this control demands of the calling principal. This is the whole of a subclass's own rule; nothing about the deployment belongs here. - [resolveServerAuthState] — the deployment operand: what grade this control's subject is granted to the deployment. It defaults to [TomAuthState.full] (uncapped), because most controls name a user requirement (a role, a group, a resource key) and say nothing about deployment features. [TomEntitlementAccess] is the grant carrier that actually answers it.

Methods

bool checkPrincipalAccess(TomPrincipal? principal)

The user operand: whether [principal] satisfies this control.

Returns true if the principal's own grants suffice, false otherwise. A null principal typically represents an unauthenticated user.

This answer is deliberately uncapped — it is one half of the meet the public [checkAccessibility] computes. Consumers want that public method; this one exists for subclasses to implement and for composite controls (like [TomGradedAccess]) to interrogate their children without the cap being applied once per nesting level.

TomAuthState resolvePrincipalAuthState(TomPrincipal? principal)

The user operand resolved to a four-state [TomAuthState].

The default bridges the binary [checkPrincipalAccess] onto two states — granted → [TomAuthState.full], denied → [TomAuthState.none] — so every binary access control (role/group/entitlement/etc.) keeps its meaning while gaining a four-state outcome. Controls that need to express [TomAuthState.read] (read-only) or [TomAuthState.disabled] (visible but locked) override this; see [TomGradedAccess].

TomAuthState resolveServerAuthState(TomPrincipal serverPrincipal)

The deployment operand: the highest grade this control's subject is granted to the deployment identified by [serverPrincipal].

Defaults to [TomAuthState.full] — uncapped. That default is the correct one rather than a lenient shortcut: a control that names a user role, a group or a resource key expresses nothing about which features a deployment licenses, so it has no opinion to contribute to the meet, and a participant with no opinion must return the identity element. Returning anything lower would make an unrelated deployment grant silently veto a role check.

[TomEntitlementAccess] overrides this — entitlement patterns are the grant carrier — and [TomGradedAccess] composes its children's answers into the ladder.

TomAuthState resolveAuthState(TomPrincipal? principal)

Resolves the effective four-state authorization for [principal]: the user's grade met with the deployment's.

When no server principal is installed the deployment has no identity to cap with, and the result is the user's grade alone — byte-for-byte the behaviour of every deployment built before server-as-principal existed. This is why the guard tests [TomServerPrincipal.current] for null rather than evaluating against an empty principal: an empty entitlement set means "entitled to nothing" and would deny everything.

bool checkAccessibility(TomPrincipal? principal)

Whether [principal] may see this control's content, deployment cap included.

Defined as [TomAuthState.showsContent] over [resolveAuthState], so the binary and graded views can never disagree. For a two-state control this is exactly the plain AND of the user's grant and the deployment's, which is what the meet degenerates to when neither operand can express the middle states.

class TomEntitlementAccess

class TomEntitlementAccess extends TomAccessControl

Grants access based on entitlement patterns.

Entitlements are fine-grained permissions that can be assigned to users, groups, or roles. This access control checks if the user has any entitlement matching the specified patterns.

Patterns are evaluated as regular expressions, allowing for flexible matching:

// Match exact entitlement
@TomEntitlementAccess(['feature.reports.view'])

// Match any reports entitlement
@TomEntitlementAccess([r'feature\.reports\..*'])

// Match multiple patterns (OR logic)
@TomEntitlementAccess(['admin.*', 'feature.reports.edit'])

Also the deployment's grant carrier

Entitlements are the one requirement kind that means the same thing on both sides of the meet. Asked about a user they answer "may this person use the feature"; asked about the ambient server principal they answer "is this deployment licensed for the feature at all". That is why codespecs_mapping.md §5.26 needs no new class for server-level grants — the same pattern set, matched against the other principal. A deployment whose entitlements do not match caps the feature to [TomAuthState.none] no matter what the user holds.

This is the whole of the "grant carrier" in codespecs_mapping.md §5.26 — a feature is granted to this deployment iff the server principal's entitlements match the feature's pattern.

class TomGradedAccess

class TomGradedAccess extends TomAccessControl

Access control that resolves to all four [TomAuthState] values by composing three binary controls — one each named after the state it grants: [full], [read], and [disabled].

Resolution, from most to least privileged:

  • [full] grants → [TomAuthState.full] (interactive/editable)
  • else [read] grants → [TomAuthState.read] (value visible, not editable)
  • else [disabled] grants → [TomAuthState.disabled] (rendered but locked)
  • else → [TomAuthState.none] (hidden)

When [read] is omitted it defaults to [full]; when [disabled] is omitted it defaults to [read]. This preserves the natural monotonicity that anyone who can edit can also read and see, so the common case only needs a single control.

For binary consumers, [checkAccessibility] collapses to "can see content" ([TomAuthState.showsContent]): a [TomAuthState.read] or [TomAuthState.full] outcome is accessible; [TomAuthState.disabled] and [TomAuthState.none] are not. 

final salary = TomGradedAccess(
  full: const TomRoleAccess(['payroll.admin']),
  read: const TomRoleAccess(['manager']),
  disabled: const TomAuthenticatedAccess(),
);
final state = salary.resolveAuthState(currentPrincipal);
// payroll.admin → full, manager → read, other staff → disabled,
// anonymous → none.

The deployment's grade for this graded control: the same ladder, walked against the server's grants instead of the user's.

A tier counts as granted to the deployment when its child reports itself fully granted. So a deployment entitled to a feature's view tier but not its edit tier yields [TomAuthState.read], which caps even an editing user down to read — the worked example in codespecs_mapping.md §5.26, falling straight out of the structure rather than out of a special case.

Note the asymmetry with [resolvePrincipalAuthState]: children that express no deployment opinion answer [TomAuthState.full] (the identity element), so a graded tree of pure role checks resolves to full here and caps nothing.

class TomProtectedField

class TomProtectedField

Marks a reflected field as protected by [resourceKey].

The automatic protection tiers read it and grade the field through [TomResourceKeyProtection.automaticState]:

  • the JSON tier ([TomResourceKeyProtection.globalSettingUseAutomaticJsonProtection])

class TomResourceKeyAccess

class TomResourceKeyAccess extends TomAccessControl

Grants access based on resource key protection.

This integrates with [TomResourceKeyProtection] to provide field-level or resource-level access control. 

@TomResourceKeyAccess('user.salary')
int readSalary(User user) { ... }

Unlike its siblings, this control has a second operand: while [TomResourceKeyProtection.globalSettingProtectionDefault] is false, resource keys are not enforced at all and every principal is granted. Once it is on, the grade is [TomResourceKeyProtection.resourceStateFor] — a flat grant covering [key] is full access, and a resource role for it grades through [TomResourceRoleRegistry].

That makes it the one built-in besides [TomGradedAccess] that can resolve to [TomAuthState.read] or [TomAuthState.disabled]: a principal holding the key through a viewer role sees the resource read-only.

It is deliberately not routed through the shared ACI helper the role and group controls use: that master switch is a genuinely different rule, in the same way entitlement matching is.

class TomResourceKeyProtection

class TomResourceKeyProtection

Provides resource-level protection based on resource keys.

This class implements a protection mechanism that can selectively hide or expose data based on the current user's access rights. It integrates with the zone-based [TomPrincipal] to determine accessibility.

Switches

SwitchDefaultApplied by
[globalSettingProtectionDefault] off every resource-key check: while off, no resource-key grant is enforced
[globalSettingUseAutomaticEndpointProtection] on tom_core_server's endpoint pipeline
[globalSettingUseAutomaticJsonProtection] on the reflective JSON serializer, for [TomProtectedField] fields
[globalSettingUseAutomaticDatabaseProtection] on tom_core_server's repository, for authorized columns
[globalSettingUseAutomaticUIProtection] on tom_flutter_ui's TomAuthLayers

The four tier switches are on by default: a tier applies whatever grants the deployment configured, and a deployment that configured none is not restricted by any of them. They exist to be switched off — during development, to take the authorization system out of the way, or at start-up to run an application without it.

The master switch is the exception and is off by default: turning it on is what makes resource-key grants binding at all, so it would refuse every unannotated endpoint and blank every [protect] call in an application that has not configured grants yet.

Switching from the command line

Every switch has a setting name, read at start-up from a compile-time define and applicable at run time from arguments:

SettingSwitch
tom.protectionall of them at once
tom.protection.resourceKeys[globalSettingProtectionDefault]
tom.protection.endpoint[globalSettingUseAutomaticEndpointProtection]
tom.protection.json[globalSettingUseAutomaticJsonProtection]
tom.protection.database[globalSettingUseAutomaticDatabaseProtection]
tom.protection.ui[globalSettingUseAutomaticUIProtection]
 
dart run -Dtom.protection=false bin/server.dart          # a define
flutter run --dart-define=tom.protection.ui=false        # a Flutter define
dart run bin/server.dart tom.protection.json=false       # an argument

A define sets the start-up value. An argument is applied by [applyArguments], which tom_core_server's server configuration calls with the process arguments; a client calls it itself. A specific setting beats tom.protection, so tom.protection=false tom.protection.ui=true keeps only the UI tier. [disableAll] is the same switch-off from application code.

Example

// Enable protection globally
TomResourceKeyProtection.globalSettingProtectionDefault = true;

// Protect a field - returns fallback if user lacks access
var email = TomResourceKeyProtection.protect(
  user.email,
  '[hidden]',
  'user.email',
);

static bool globalSettingProtectionDefault

Master switch: whether resource-key grants are enforced at all.

When false — the default — every resource is accessible and every resource-key check answers "not protected". When true, access is graded by [resourceStateFor] from the principal's resource grants. Setting: tom.protection.resourceKeys.

static bool globalSettingUseAutomaticEndpointProtection

Whether tom_core_server's endpoint pipeline may grant an endpoint from resource keys after the ordinary access check has refused.

On by default. The pipeline consults it only while [globalSettingProtectionDefault] is on: with resource keys not enforced every key reads as held, and a second chance granted from them would overturn every refusal. Setting: tom.protection.endpoint.

static bool globalSettingUseAutomaticUIProtection

Whether tom_flutter_ui's four-state authorization model applies.

true by default and normally left there: with it on, every element resolves through TomAuthLayers — resource, group, enclosing ceiling, authorizer, UI-state controller — and renders at the state that composition produces. It is the one switch for form fields, actions and components alike: hidden, read-only and disabled are states of the one model, resolved per element rather than per category.

Setting it false bypasses the model and grants every UI resource it protects. Build-time UI state still applies, because a controller that says "this form is in view mode" is describing the screen rather than the principal. It answers "is this element hidden because of authorization, or because of something else?" in one step, without editing grants; a server that relies on it for anything is relying on the client to police itself. Setting: tom.protection.ui.

static bool globalSettingUseAutomaticJsonProtection

Whether the reflective JSON serializer applies [TomProtectedField].

On by default. While on, TomReflectionInfo.getValues — the path every reflected object takes to the wire — leaves out a field annotated [TomProtectedField] whose [automaticState] shows no content. A type that renders itself (toJson, jsonEncode, TomJsonSerializable, TomClass) is not walked, so it protects what it writes with [protect]. Setting: tom.protection.json.

static bool globalSettingUseAutomaticDatabaseProtection

Whether tom_core_server's repository applies column authorization.

On by default. While on, a column carrying a TomDbColumn.authKey or a [TomProtectedField] is graded on every read and write: masked when its grade shows no content, and write-protected unless it is full. While off, every column is unrestricted — including those with a per-row resolver. Row filtering is not part of this tier: it is tom_core_server's data scope (@TomDbScope, TomDataScope, TomResourceDataScope), which stays in force whatever this switch says. A scope says which rows a query addresses, and switching it off would change what a query means rather than what it may reveal. Setting: tom.protection.database.

static TomAuthState automaticState(String resourceKey)

The grade the automatic tiers apply to [resourceKey]: the installed [TomAuthorization] adapter's grade met with the ambient principal's resource-key grade ([resourceState]).

Both sources are consulted because deployments configure either. A client installs an adapter built from its principal; a server has a principal on every request zone and usually no adapter. Each source is full when it is not configured — no adapter, or [globalSettingProtectionDefault] off — so the meet is whichever one is, and the more restrictive when both are. It does not consult the tier switches: each tier checks its own before asking.

static T protectFor<T>(TomPrincipal? principal, T data, T fallback, String resourceKey)

Protects a value based on [principal]'s resource key access.

Returns [data] if [principal] holds [resourceKey], otherwise [fallback]. A null principal holds no keys, so it gets [fallback].

This is [protect] stated over an explicit operand, and it is the form to reach for whenever a principal is already in hand — reading the zone when the caller named someone answers a different question. It matters most where the two differ irreconcilably: minting a token for a principal being authenticated means there is no principal on the zone yet, so the zone-reading form is fail-closed and blanks every protected field.

Requires [globalSettingProtectionDefault] to be true. It defaults to false, and while it is off this returns [data] for every key and every principal — so a call added for protection protects nothing until the switch is set.

  • [principal]: The principal whose keys decide access, or null
  • [data]: The actual value to return if access is granted
  • [fallback]: The value to return if access is denied
  • [resourceKey]: The key identifying the protected resource
static T protect<T>(T data, T fallback, String resourceKey)

Protects a value based on the current user's resource key access.

Returns [data] if the current user — the principal installed on the ambient zone — has access to [resourceKey], otherwise returns [fallback]. Where a principal is already in hand, call [protectFor] instead.

Requires [globalSettingProtectionDefault] to be true. It defaults to false, and while it is off this returns [data] for every key and every principal — so a call added for protection protects nothing until the switch is set.

  • [data]: The actual value to return if access is granted
  • [fallback]: The value to return if access is denied
  • [resourceKey]: The key identifying the protected resource
static TomAuthState resourceStateFor(TomPrincipal? principal, String resourceKey)

The [TomAuthState] [principal] holds on [resourceKey].

This is the rule itself, stated over an explicit operand; every other member of this class — and [TomResourceKeyAccess] — is a view of it. The principal's two resource grants are one answer:

1. A flat grant in aci.resourceKeys covering the key — exact, * or prefix.*, as [TomAccessControlInformation.holdsResourceKey] defines — is [TomAuthState.full]. 2. A resource role in aci.resourceRoles for the key resolves through [TomResourceRoleRegistry], exactly as [TomResourceRoleAdapter] resolves it: an unknown role, or none, grants nothing.

When both apply, the wider state wins ([TomAuthState.widen]): holding a grant is never undone by also holding a narrower role.

A null [principal] holds nothing and gets [TomAuthState.none].

Gated on [globalSettingProtectionDefault]: while that is false — its default — this answers [TomAuthState.full] for every key and every principal, before any grant is consulted.

  • [principal]: The principal whose grants decide access, or null
  • [resourceKey]: The key identifying the resource
static TomAuthState resourceState(String resourceKey)

The [TomAuthState] the current user holds on [resourceKey] — the principal installed on the ambient zone, through [resourceStateFor].

Outside a request zone there is no principal, so with protection on this answers [TomAuthState.none] for everything — fail-closed.

static bool isProtectedFor(TomPrincipal? principal, String resourceKey)

Checks if a resource is protected from [principal].

Returns true if the resource is protected, false if its content is accessible: [resourceStateFor] collapsed to two outcomes, protected unless the state [TomAuthState.showsContent]. A principal holding the resource read-only is therefore not protected from it — it may see the value — and one holding it [TomAuthState.disabled] is, because a disabled element shows no content.

The two-valued form is what [protectFor] needs, since a value is either served or replaced by its fallback. Code that renders a field editable, read-only or hidden asks [resourceStateFor] instead.

  • [principal]: The principal whose grants decide access, or null
  • [resourceKey]: The key identifying the resource to check
static bool isProtected(String resourceKey)

Checks if a resource is protected from the current user.

The "current user" is the principal installed on the ambient zone. Where a principal is already in hand, call [isProtectedFor] instead — reading the zone when the caller named someone answers a different question.

Returns true if the resource is protected (user lacks access), false if the resource is accessible.

Gated on [globalSettingProtectionDefault] exactly as [isProtectedFor] is. Note the two ways this answers false: protection switched off (nothing is protected) and the principal holding the resource. Outside a request zone there is no principal, so with protection on this answers true for everything — fail-closed.

  • [resourceKey]: The key identifying the resource to check

  • [id]: A resource identifier for context-specific checks

Returns true if access is granted, false otherwise.

function _principalAciContainsAny

bool _principalAciContainsAny(TomPrincipal? principal, List<String> candidates, List<String> Function(TomAccessControlInformation) selectCollection)

Returns true when [principal] is non-null and any entry in [candidates] is present in the ACI string collection chosen by [selectCollection].

[TomRoleAccess] and [TomGroupAccess] share an identical accessibility rule — "granted if the principal's ACI lists any of the requested names" — differing only in which ACI collection they consult. This helper is that rule; each class supplies the collection selector. Entitlement access is deliberately not routed through here: it matches by regular expression rather than exact containment, a genuinely different rule.

function tomProtect

T tomProtect<T>(T data, T fallback, String resourceKey)

Convenience function to protect a value based on resource key access.

This is a shorthand for [TomResourceKeyProtection.protect], and inherits its precondition: nothing is protected until [TomResourceKeyProtection.globalSettingProtectionDefault] is true. 

// Once, at start-up — otherwise the call below is a no-op.
TomResourceKeyProtection.globalSettingProtectionDefault = true;

var visibleEmail = tomProtect(user.email, '[hidden]', 'user.email');

function tomProtected

bool tomProtected(String resourceKey)

Convenience function to check if a resource is protected.

This is a shorthand for [TomResourceKeyProtection.isProtected], and inherits its precondition: while [TomResourceKeyProtection.globalSettingProtectionDefault] is false — its default — this always answers false and the guard below always passes. 

if (!tomProtected('user.email')) {
  print(user.email);
}

function tomResourceState

TomAuthState tomResourceState(String resourceKey)

Convenience function for the [TomAuthState] the current user holds on [resourceKey] — a shorthand for [TomResourceKeyProtection.resourceState].

Where [tomProtect] can only serve a value or its fallback, this tells a field whether to render editable, read-only, greyed out or not at all: 

final emailWidget = switch (tomResourceState('user.email')) {
  TomAuthState.full => emailEditor(),
  TomAuthState.read => emailText(),
  TomAuthState.disabled => emailPlaceholder(),
  TomAuthState.none => null,
};
