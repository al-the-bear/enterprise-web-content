class TomEnumResourceSegment

abstract interface class TomEnumResourceSegment

Declares an enum's resource segment explicitly, for enums whose segment cannot be inferred.

[TomObservableEnum.enumTypeSegment] normally reads the enum's declared name out of [Enum.toString], which is stable under a minifying or obfuscating compile. An enum that overrides toString defeats that inference, and rather than guess, the resolver rejects it. Implement this interface to supply the segment yourself: 

enum Colour implements TomEnumResourceSegment {
  red, green;

  @override
  String get resourceSegment => 'colour';

  @override
  String toString() => 'Colour($name)';
}

The value is lower-cased before use, so 'Colour' and 'colour' address the same bundle key.

class TomObservableEnum

class TomObservableEnum<E extends Enum> extends TomObject<E>

An observable [Enum] cell whose display text is derived from the application text bundle instead of a Dart-side label table.

This is an ordinary [TomObject] holding an enum value — | to set, ~ to read, >> to observe — with one addition: it also resolves the value to a human-readable string through [TomTextResourceProvider], and it notifies its observers when either the value or the installed bundle changes. That second trigger is what makes a locale switch re-render a bound field without the caller rebuilding anything.

The cell's value is confined to the [values] it was given: both the constructor and [set] reject anything else, so the option list a picker renders always contains the value the cell holds.

Resource keys

The key for a value is <scope>.<enumName>.<value>, all lower case:

{ "global": { "todostatus": { "inreview": "In review" } } }

The scope segment is implicit: it is taken from the ambient [TomScope] at construction time — scopes are never named at the call site, and there is no class cataloguing resource keys as constants. Resolution walks the scope chain from most specific to least specific and ends at [globalScopeId], so a value declared once under global works everywhere while a single scope can override just the labels it cares about: 

TomScope.withScope('checkout', () {
  final status = TomObservableEnum(TodoStatus.inReview, values: TodoStatus.values);
  status.displayText; // 'checkout.todostatus.inreview', else
                      // 'global.todostatus.inreview', else 'inReview'
});

The scope is captured when the cell is constructed, not when its text is read — display resolution frequently happens inside a Flutter builder callback, which runs outside the zone that installed the scope.

Missing keys

A value with no key in the bundle degrades to the raw enum name (inReview — recognisable, never blank) and logs a warning naming the keys that were tried. The warning is emitted once per key per bundle revision, so a missing label in a list of a thousand rows does not flood the log, but a locale switch reports it again. After a few hundred distinct missing keys the warnings stop altogether — one message says so.

Example

final status = TomObservableEnum(TodoStatus.open, values: TodoStatus.values);

// Retain the observer — observers are held weakly.
final observer = status >> (_) => print(status.displayText);

status | TodoStatus.inReview;                 // prints the localised label
TomTextResourceProvider.setAppResourceProvider(germanBundle); // prints it again

Constructors

TomObservableEnum.new(E initialValue, {required List<E> values, TomScope? scope})

Creates an observable enum cell holding [initialValue].

[values] is the set of values this cell may hold — normally the enum's own list (MyEnum.values), or a subset when the cell offers a restricted choice. It is what a picker enumerates to build its options, and it is required: Dart cannot recover E.values from a type parameter, and any default this constructor could invent would be wrong. [initialValue] must be one of them.

[scope] overrides the ambient [TomScope] used for key resolution — pass it only when the cell is constructed outside the scope whose labels it should use.

E set(E value) override

Sets the value, which must be one of [values].

A cell whose value is not in its own option list is incoherent: it labels itself from a list that does not contain it, so [displayTexts] describes something other than what [displayText] shows, and a picker bound to it has no option to select. Rejecting the write keeps the two in step.

This is the single mutation path — | and << both delegate here — so the guarantee holds for every way of writing the cell.

static int _maxWarnedKeys

Upper bound on [_warnedKeys], so the dedupe set cannot grow without limit.

The set is static and lives for the process, and the number of distinct keys is not bounded by the number of enums: a key carries the scope path, and scope ids are arbitrary strings, so an application that opens a scope per entity produces a new key per entity. Past this many distinct missing keys the point has been made — one more warning says so and the rest are dropped until the bundle changes.

static bool _warnLimitReported

Whether the [_maxWarnedKeys] cutoff has already been reported for the current bundle revision.

static String enumTypeSegment(Enum value)

The enum-name segment of a resource key: the enum type, lower case.

Read out of [Enum.toString], not runtimeType. Both yield TodoStatus for a TodoStatus value in a debug build, but only toString survives a minifying or obfuscating compile: the declared name is baked into the enum as a string literal, whereas runtimeType is a class name the compiler is free to rewrite. Measured under dart compile js -O4 --minify, runtimeType reads minified:y while toString still reads TodoStatus.inReview. Since this segment addresses the text bundle, taking it from runtimeType would lose every label in a release build while working perfectly in development.

An enum that overrides toString defeats the inference and must declare its segment by implementing [TomEnumResourceSegment]; one that does neither is rejected rather than resolved against an unstable name.

static String valueSegment(Enum value)

The value segment of a resource key: the enum constant name, lower case.

static List<String> resourceKeysFor(Enum value, {TomScope? scope})

The resource keys tried for [value], most specific first.

One key per scope-chain prefix of [scope] (defaulting to the ambient [TomScope]), followed by the [globalScopeId] key. In the default root scope the list is the single entry global.<enumName>.<value>.

static String? resolveTextOrNull(Enum value, {TomScope? scope})

The display text for [value], or null when no candidate key resolves.

Use this when the caller wants to supply its own fallback; [resolveText] applies the standard one.

static String resolveText(Enum value, {TomScope? scope})

The display text for [value], falling back to its raw enum name.

When no candidate key resolves, logs a warning listing the keys that were tried (once per key per bundle revision) and returns value.name.

static String resourceKeyFor(Enum value, {TomScope? scope})

The key that [resolveText] would resolve for [value].

Returns the first candidate present in the bundle, or — when none is — the [globalScopeId] key, which is the one an author should add.

static void _warnMissing(List<String> keys)

Logs a missing-label warning for [keys], at most once per bundle revision.

Stops after [_maxWarnedKeys] distinct keys — see that constant for why the set needs a ceiling at all. Installing a new bundle resets both the set and the cutoff, so a locale switch reports its missing labels afresh.

static void _checkInRange<E extends Enum>(E value, List<E> permitted, String operation)

Throws unless [value] is one of [permitted].

[operation] names what was attempted, so the message says which call failed rather than only which value was rejected.
