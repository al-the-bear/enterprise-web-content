class TomReflectionInfo

Provides reflection-based operations for object serialization and deserialization.

This class is the main entry point for reflection operations in the Tom framework. It provides methods to: - Create instances of annotated classes - Set values on objects from JSON/Maps - Get values from objects as JSON/Maps - Resolve element types from collections

Key Features

Instance Creation

Create new instances of annotated classes using the default constructor or from JSON data:

final person = tomReflectionInfo.createInstance<Person>();
final loaded = tomReflectionInfo.createInstanceFromJson<Person>(mirror, jsonData);

Value Setting (Deserialization)

Set field values on objects from a map, handling: - Primitive types (int, double, bool, String) - DateTime and TomZoned* date/time types - Nested objects (annotated with @tomReflector) - Collections (List, Map) of primitives or annotated objects 

tomReflectionInfo.setValues(person, {'name': 'John', 'age': 30});

Value Getting (Serialization)

Extract all field values from an object as a JSON-compatible map:

final json = tomReflectionInfo.getValues(person);
final jsonString = tomReflectionInfo.convertToJsonString(person);

There is exactly one reflector, and it is not a parameter

Every operation goes through the global [tomReflector]. The class used to take a reflector as a constructor argument, which read as an extension point and was not one: the code generator that produces the mirror data refuses to emit anything for a class that is not a direct subclass of Reflection (it warns "An indirect subclass of Reflection will not work as a reflector" and skips it). [TomReflector] is that direct subclass, so a subclass of it is one step too far and silently gets no data at all; and because [TomReflector]'s constructor is const, every const TomReflector() is canonicalised to the very same object as [tomReflector]. The parameter could therefore only ever be handed the global — or a value guaranteed to fail at the first mirror lookup.

Do not reintroduce it. A genuine second reflector would need a second direct subclass of Reflection and a field typed to their common supertype, which is a different design and one nothing currently asks for.

Debug Switches

Enable debug logging for troubleshooting reflection operations: - [debugSwitchLogReflectionDetailsMembers]: Log class member information - [debugSwitchLogReflectionDetailsValues]: Log value setting operations - [debugSwitchLogReflectionDetailsTypes]: Log type resolution details

Constructors

TomReflectionInfo.new({bool strictUnknownFields = false})

Creates a converter over the global [tomReflector].

It takes no reflector, and that is not an omission — see the class documentation for why a second one cannot exist. Prefer the shared [tomReflectionInfo] instance; construct your own only to choose a different [strictUnknownFields], which is the whole of the instance state.

Properties

final bool strictUnknownFields

Whether [setValues] rejects a key that names no declaration on the target.

False by default, which is what the shared [tomReflectionInfo] uses: on the wire, tolerating unknown keys is a feature. A newer client talking to an older server, or a stored document holding fields since removed, sends keys the target no longer declares, and failing the whole payload for them would make the format non-forward-compatible.

Where the payload is under the caller's own control that tolerance is a liability instead, because it hides the commonest deserialization bug there is — a renamed field, or a typo, silently dropped. Construct a strict converter there: 

final strict = TomReflectionInfo(strictUnknownFields: true);
strict.setValues(person, {'nickname': 'Jo'});
// throws reflection.set.unknown_field

It is a property of the converter rather than of the call so that nested objects inherit it: the walk recurses through [createInstanceFromJson] on this same instance, so a strict converter is strict all the way down.

It governs unknown keys only. A key naming a member that exists but cannot be written is an error in both modes — see [_handleMissingField].

Methods

ClassMirror<dynamic> mapValueElementType(Object collection)

Extracts the value type's [ClassMirror] from a Map type annotation.

Given a Map<K, V> collection, this method extracts the type parameter V and returns its corresponding [ClassMirror].

Example:

Map<String, Person> people = {};
final valueMirror = tomReflectionInfo.mapValueElementType(people);
// valueMirror is the ClassMirror for Person

Resolved by simple name, because a collection value carries its type arguments only as text: two annotated classes sharing a simple name make this lookup refuse (reflector.classmirror.ambiguous_simple_name). Deserializing a field is not affected — it reads the field's own mirror.

Exactly two type arguments are required. A collection with any other arity is refused rather than resolved: with one, the caller wanted [singleElementType] and the message says so; with three or more, there is no "the value type" to return, and picking the second argument would be a guess that reads like an answer.

Throws [TomReflectorException] if the value type is not found among annotated classes, or if it is itself generic — see [singleElementType] for why one level is the limit.

ClassMirror<dynamic> singleElementType(Object collection)

Extracts the element type's [ClassMirror] from a single-type-parameter collection (e.g., List, Set).

Given a List<T> or Set<T> collection, this method extracts the type parameter T and returns its corresponding [ClassMirror].

Example:

List<Person> people = [];
final elementMirror = tomReflectionInfo.singleElementType(people);
// elementMirror is the ClassMirror for Person

Resolved by simple name, because a collection value carries its type arguments only as text: two annotated classes sharing a simple name make this lookup refuse (reflector.classmirror.ambiguous_simple_name). Deserializing a field is not affected — it reads the field's own mirror.

Throws [TomReflectorException] if the element type is not found among annotated classes, or if it is itself generic: both methods resolve a name against the classes annotated with @tomReflector, and a generic instantiation such as List<String> is not one of those and never can be. One level of nesting is therefore the supported depth, and the exception says so rather than reporting a name that was never going to match.

Exactly one type argument is required. Passing a Map<K, V> used to succeed and return the mirror for K — a valid mirror for the wrong half of the collection, which no caller could detect, so the arity is checked before the name is resolved.

ClassMirror<dynamic> _resolveTypeArgument(String typeArgument, Object collection, String method, String notFoundErrorKey)

Resolves one parsed type argument to its [ClassMirror].

[method] and [collection] appear in the message so the caller can see which collection was being resolved, named as Dart names it.

ClassMirror<dynamic> _findClassMirror(String typeName, String errorKey, String errorMessage)

Finds a [ClassMirror] by type name among annotated classes.

Searches through all classes annotated with @tomReflector to find one matching the given [typeName].

The one name-based lookup in this class, and reached only from [singleElementType] and [mapValueElementType]: they are handed a bare collection, whose element type exists at run time only as the text of its runtimeType, so a simple name is all there is to go on. The field walk never comes here — it reads a field's element type from the field's own mirror — which is why a shared simple name refuses these two helpers and nothing else.

Throws [TomReflectorException] with the provided [errorKey] and [errorMessage] if not found.

InstanceMirror _reflect(Object o, String operation)

Reflects [o] through the global [tomReflector] on behalf of [operation].

The single door through which every instance-mirror lookup passes, so that the one thing that can go wrong here goes wrong the same way everywhere. That thing is an object whose class carries no @tomReflector: tom_reflection answers with a NoSuchCapabilityError naming the type and nothing else — not the operation that wanted it, not the annotation that would fix it, and not in the exception type the rest of this class raises. Callers that catch [TomReflectorException] would miss it entirely.

[operation] is the public method the caller is inside, so the message says which of serialization, deserialization or reporting failed.

ClassMirror<dynamic> _annotatedType(InstanceMirror im, Object o, String operation)

Resolves the class mirror of [im], insisting it carries @tomReflector.

Reflecting successfully is not the same as being one of ours. The capability set includes deep type-annotation quantification, so every type that appears as a field type of an annotated class — String, int, double, bool, DateTime, List, Map, Object — gets generated data too. Those types reflect happily and then contribute no settable declarations, which is how getValues('hello') came to return {} and convertToJsonString('hello') the string "{}": a valid-looking payload with every field dropped, reported as success. setValues was the mirror image, returning the object untouched.

The test is the @tomReflector metadata rather than membership of [Reflection.annotatedClasses], for two independent reasons. That list holds the quantified types as well, so it cannot separate them; and it holds declaration mirrors, so the instantiated mirror of an annotated generic — GenericHolder<int> — is not in it, and a membership test would reject a class the developer did annotate. Metadata survives instantiation and marks exactly the annotated set.

Resolving the mirror is itself inside the guard: for a generic instantiation the reflector does not own, im.type throws a bare _TypeError from inside tom_reflection, naming neither the type nor the operation.

T convertFromJsonString<T extends Object>(T o, String s)

Creates an instance of type [T] from a JSON string.

This method parses the JSON string and populates the fields of the provided object [o] with the parsed values.

Example:

final person = Person();
tomReflectionInfo.convertFromJsonString(person, '{"name": "John", "age": 30}');
print(person.name); // "John"

Returns [o] with its fields populated — except for a class declaring a fromJson constructor, where it returns the instance that constructor built. Assign the result rather than reading [o] back; see [setValues].

T createInstanceFromJsonString<T extends Object>(ClassMirror<dynamic> objectMirror, String s)

Creates a new instance of type [T] from a JSON string.

Uses the provided [ClassMirror] to instantiate the object, then populates it from the parsed JSON.

Returns the new instance. There is no failure value: every way this can go wrong throws. [s] is parsed before any reflection happens, so malformed JSON raises a [FormatException] from jsonDecode; everything after that is [createInstanceFromJson] and raises [TomReflectorException].

T createInstanceFromJson<T extends Object>(ClassMirror<dynamic> objectMirror, Map<String, Object?> jsonData)

Creates a new instance of type [T] from JSON data.

The inbound entry point for the case where there is no object yet. It honours the same hooks in the same order as [setValues] — see there for the precedence and why it is in that order — reaching them by the only route open to it: the fromJson constructor if the class declares one, otherwise the default constructor followed by [setValues], which settles [TomClass], jsonDecode and the field walk.

The two entry points therefore agree. A class carrying a fromJson constructor decodes through it whichever of the two is called, which is what [setValues] gives up identity for.

Example:

final mirror = tomReflector.reflectType(Person) as ClassMirror;
final person = tomReflectionInfo.createInstanceFromJson<Person>(
  mirror,
  {'name': 'Jane', 'age': 25},
);

Returns the new instance. There is no failure value: a class that cannot be built, a fromJson that raises, and a payload the target rejects all throw [TomReflectorException]. A caller testing the result for null is writing a branch that cannot be entered.

T _invokeFromJson<T extends Object>(ClassMirror<dynamic> cm, Map<String, dynamic> jsonData)

Invokes the fromJson constructor of [cm], which must declare one.

Shared by [createInstanceFromJson] and [setValues] so that the two cannot drift: the hook is one hook, and a class must not decode differently depending on which entry point reached it. Callers check [_declaresConstructor] first — absence is settled before anything runs, per [_hookFailed], so everything caught here is a hook that exists and failed.

T createInstance<T extends Object>([Type? type])

Creates a new instance using its default constructor.

The class must be annotated with @tomReflector and have a default (no-argument) constructor.

The type is named twice over, and the two are not the same question: [type] says what to build, [T] says what to call the result and is applied to it as a cast. Each defaults to the other, so most calls pass only one. 

// The type is known here; T carries it and the result is a Person.
final person = tomReflectionInfo.createInstance<Person>();

// Only a runtime Type is available. Nothing infers T, so it falls to its
// bound: the instance is a Person, but the static type is Object.
final instance = tomReflectionInfo.createInstance(someType);

// Both: build someType, hand it back typed as a supertype it satisfies.
final person = tomReflectionInfo.createInstance<Person>(someType);

Passing both is only worthwhile when they differ, and nothing checks that they agree until the cast runs — a [type] that is not a [T] is not a compile error.

Throws [TomReflectorException] (reflector.instance_creation.failed) if the class cannot be reflected or constructed, or if the result is not a [T].

T setValues<T extends Object>(T o, Map<String, dynamic> values)

Sets values on an object from a map of field names to values.

This is the inbound entry point, and it honours every decoding hook the framework recognises. [createInstanceFromJson] resolves to the same order, so the answer does not depend on which of the two a caller happens to reach for.

Precedence

The first match wins:

1. [TomClass] — delegates to TomClass.setValues(), which knows how to write observable fields. An is test. 2. a fromJson constructor — construction is the hook, so this returns a new instance built from [values]; see below. 3. a jsonDecode method — invoked on [o], which decodes itself. 4. the reflected fields — written one by one.

A fromJson class does not preserve identity

Steps 1, 3 and 4 fill [o] and return it. Step 2 cannot: a constructor produces an object, it does not populate one, and a type that declares fromJson has said that building from a payload is its business. So for such a type this method returns the constructed instance and leaves [o] untouched.

Use the return value. converter.setValues(x, map) and then reading x is correct for every other shape and wrong for this one; write x = converter.setValues(x, map). The alternative — field-walking a fromJson type — would mean the same class decodes two different ways depending on the entry point, which is the asymmetry this ordering exists to remove.

Supported Field Types

  • Primitive types: int, double, bool, String, null
  • DateTime types: DateTime, TomZonedDate, TomZonedTime, TomZonedDateTime
  • Nested objects: Any class annotated with @tomReflector
  • Collections: List<T> and Map<String, T> where T is a supported type,

and Set<T> of a primitive T — filled from the JSON array a set serializes to

Example:

final person = Person();
tomReflectionInfo.setValues(person, {
  'name': 'John',
  'age': 30,
  'address': {'street': '123 Main St', 'city': 'NYC'},
  'tags': ['developer', 'dart'],
});

Returns [o] with its fields populated, or — for a class declaring a fromJson constructor — the instance that constructor built.

List<String> unknownFields<T extends Object>(T o, Map<String, dynamic> values)

The keys of [values] that name no writable declaration on [o], in the order they appear.

The question [strictUnknownFields] answers as it goes, asked in advance and answered for the whole map rather than for the first offender. A caller binding a document it owns — a configuration block, a settings map — uses this to report every misspelled key at once, in its own vocabulary and naming the document the keys came from, which is context this converter does not have and cannot invent. 

final unknown = tomReflectionInfo.unknownFields(driver, settings);
if (unknown.isNotEmpty) throw MyConfigException(name, unknown);

It applies the same rule as the field walk, so the two cannot drift: a key is unknown when the target declares neither a getter nor a setter for it. A member that exists but cannot be written — static, final, private — is not listed, because it is not unknown; [setValues] raises on it in both modes, which is where that fault belongs.

Returns empty for a [TomClass], for a class declaring a fromJson constructor, and for one declaring a jsonDecode hook. Each of those takes the map over entirely, so what counts as a known key is theirs to define and this converter has no view of it — reporting their keys as unknown would be an answer to a question that was never asked here.

bool canReflect(Object o)

Whether [o] can be reflected here: its class carries @tomReflector and generated reflection data has been installed in this isolate.

For callers that have something to do when reflection is not available, rather than a failure to report. Every other method on this class treats an unreflectable object as a fault, because it was asked to convert one and cannot; a caller asking a question about a class — "does this one declare a required field?" — may legitimately have no question to ask when the class has no mirrors at all.

The two conditions are one answer on purpose. tomReflector.canReflect consults the generated registry, which raises rather than answering when nothing has installed one, and both cases mean the same thing to a caller asking whether reflection is available here.

List<String> missingRequiredFields<T extends Object>(T o, Map<String, dynamic> values)

The names of [o]'s [TomRequiredField] fields that [values] supplies no value for.

The mirror image of [unknownFields]: that one names keys with no field, this one names fields with no key. Neither is answered by binding — a setting nobody supplied leaves the field at its initialiser, which reads exactly like a setting nobody required. 

final missing = tomReflectionInfo.missingRequiredFields(config, values);
if (missing.isNotEmpty) throw MyConfigException(missing);

Reporting rather than throwing keeps the vocabulary with the caller, who knows which document the map was merged from and what to call it. Every missing setting is reported at once, so a deployment fixes them in one pass rather than one restart at a time.

Supplied means the key carries a value, not that the value looks filled. An explicitly empty one counts: dbUrl= on a command line sets the setting to nothing deliberately, and refusing it would conflate "set to nothing" with "not set". A null value does not count — a .env line DB_URL= parses to null, which names the setting without giving it one, and TomEnvFile.resolveEnvironment already drops such a key rather than carrying it.

Fields are reported in declaration order, the instance's own class first and then up the superclass chain: an application's configuration is usually the most derived class, so what it declares is what its operator recognises first.

Returns empty for a [TomClass], for a class declaring a fromJson constructor, and for one declaring a jsonDecode hook — the same guard [unknownFields] carries, for the same reason. Each takes the map over entirely, so a field one of them filled from a differently-named key is not missing, and this method has no view of that.

void _handleMissingField(ClassMirror<dynamic> cm, MethodMirror? imGet, MethodMirror? imSet, MapEntry<String, dynamic> entry)

Handles an entry the field walk could not assign, of which there are two unrelated kinds.

The member exists but cannot be written ([imGet] found, [imSet] not): a static, final or private declaration. Always an error, in both modes — the caller named a field this class has and asked for a value it will never hold.

No such member (neither found): an unknown key. Silently traced, or rejected when [strictUnknownFields] is set; see that field for why the default is tolerance.

A setter without a getter reaches the second case and is deliberately not reported as unknown — the member does exist, the walk simply has no return type to resolve the value against. Calling that "unknown field" would send the reader looking for a declaration that is right there.

bool _trySetWidenedNumericValue(InstanceMirror im, MethodMirror imGet, MapEntry<String, dynamic> entry)

Widens an int value onto a double field, returning true when it did.

Why: the wire formats this reflector reads from — JSON and command-line key=value arguments — have no int/double distinction. {"rate": 2} and rate=2 both decode to an int, and there is no way for the source to say "double". Rejecting them would make a whole-number double unrepresentable, so an int destined for a double field is widened.

The converse is deliberately absent: narrowing a double to an int would need a rounding policy, and truncating 2.5 silently loses data.

String convertToJsonString(Object o)

Converts an object to a JSON string.

This is the string-level outbound entry point, and the only one a transport needs: it is [getValues] plus encoding, extended to the two shapes JSON has natively.

What [o] may be

  • a Map or a List — encoded as itself. Its elements are JSON

values already, except the complex ones, and each of those is rendered by [getValues] with the full outbound precedence. Nesting is walked to any depth. - anything else — rendered by [getValues], which is where the precedence and the @tomReflector guard live. A bare String or int is therefore still refused: it is not a container, and a caller handing a scalar to a DTO serializer is not describing an object.

Containers are the reason this method is not simply jsonEncode(getValues(o)). A handler that answers with a list of DTOs, or a map whose values are DTOs, has no reflected type of its own, so [getValues] refuses it — which left every transport to encode collections itself and, in the endpoint pipeline, to grow a parallel hook chain to do it with. Naming the container case once here is what lets those callers be one line.

Example:

final person = Person()
  ..name = 'John'
  ..age = 30;
final json = tomReflectionInfo.convertToJsonString(person);
// '{"name":"John","age":30}'

tomReflectionInfo.convertToJsonString([person]);
// '[{"name":"John","age":30}]'
Object? _renderJsonValue(Object? value)

Renders [value] into something jsonEncode accepts without a toEncodable.

The containers are walked here rather than handed to jsonEncode with a toEncodable callback, because that callback's exceptions do not survive: dart:convert catches whatever it raises and rethrows a JsonUnsupportedObjectError, so the annotation guard's message — which names the type and says it is not annotated — would reach the caller as "converting object to an encodable object failed". Walking the container ourselves lets [getValues] throw its own exception, unwrapped.

Complex values get exactly the [getValues] a top-level object would: an element is not serialized on easier terms than the object containing it, and the same guard applies to it. Nothing here reproduces the field walk's own conversions (dates, zoned times) — those belong to [getValues] and having a second copy of that table is how the two would drift.

Map<String, Object?> getValues(Object o)

Gets all values from an object as a JSON-compatible map.

This is the outbound entry point: every way a Tom Core object reaches the wire passes through here, and every rendering hook the framework recognises is honoured here. A consumer therefore never needs a hook chain of its own — asking this method is the whole contract.

Precedence

The first match wins, and the order is deliberate rather than incidental:

1. [TomClass] — delegates to TomClass.toJson(). An is test. 2. [TomJsonSerializable] — delegates to its toJson(). Also an is test, and settled before any mirror work, so a self-rendering type need not be reflectable at all. 3. a toJson() method — the same rendering declared structurally rather than nominally, found on the reflected type. 4. a jsonEncode getter — the kernel's own hook name. 5. the reflected fields — non-static, non-final, non-private, less any the JSON protection tier withholds (see below).

Why toJson outranks jsonEncode: steps 2 and 3 are the same method under two spellings, one nominal and one structural. Were jsonEncode placed between them, adding implements TomJsonSerializable to a class that happens to have both hooks would silently change its wire format — a declaration of intent would become a behavioural change. Ranking all three toJson forms together removes that trap.

Steps 1 and 2 are is tests by design, not lookups: see [TomJsonSerializable] for why "this type serializes itself" is worth making a type-system fact rather than something to probe for.

Protected fields

While [TomResourceKeyProtection.globalSettingUseAutomaticJsonProtection] is on — its default — a field annotated [TomProtectedField] is graded through [TomResourceKeyProtection.automaticState] and left out when the grade shows no content (none or disabled). Omitted rather than nulled: the reader may be a non-nullable field, and a missing member leaves it at its default where a null would fail the read. Only step 5 walks fields, so a type that renders itself protects what it renders with [TomResourceKeyProtection.protect].

Supported Field Types

  • Primitive types: returned as-is
  • DateTime types: converted to ISO 8601 strings
  • TomZoned* types: converted to string representation
  • Nested objects: recursively converted via [getValues]
  • Collections: elements are recursively converted

Example:

final person = Person()
  ..name = 'John'
  ..age = 30
  ..address = Address()..city = 'NYC';
final values = tomReflectionInfo.getValues(person);
// {'name': 'John', 'age': 30, 'address': {'city': 'NYC'}}
Map<String, Object?>? _tryInvokeToJson(InstanceMirror im, ClassMirror<dynamic> cm, Object o)

Invokes the optional structural toJson() hook, if [cm] declares one.

This is the same rendering [TomJsonSerializable] names nominally, reached for a type that has the method without declaring the interface. It is looked up rather than probed, and its failures are attributed, for the reasons given in [_hookFailed]; a hook returning the wrong shape is reported rather than skipped, as in [_tryGetJsonEncode].

[TomClass] never arrives here — it declares toJson() too, and is answered by the is test at the top of [getValues] before any mirror is taken.

static List<T> _checkedList<T>(MapEntry<String, dynamic> entry)

Builds a List<T> from [entry]'s value, checking every element up front.

Why not .cast<T>(): a cast view is lazy. It accepts a list holding an element of the wrong type without complaint and throws a bare TypeError only when that element is read — in another layer, another method, quite possibly another isolate, with a stack trace pointing at the consumer rather than at the payload that was wrong, and carrying neither the field name nor the source value. Worse, length and every well-typed element keep working, so a shallow post-deserialization check reports success.

One pass up front costs a copy and moves the failure to the only place that still knows the field, the position and the offending value. It also makes the assignment atomic for primitive collections, which is what the module already promises for collections of annotated objects.

The map counterpart of [_checkedList], which explains why a lazy cast will not do. Keys are checked as well as values: cast<String, T>() defers those too, and a non-String key reaches here from any caller that built its map in Dart rather than decoding it from JSON.

static TomReflectorException _hookFailed(String hook, Object owner, Object error, StackTrace stack)

Reports that an optional conversion hook ran and raised.

The four hooks — the fromJson constructor, the jsonDecode method, the toJson method and the jsonEncode getter — are all optional. (The nominal form, [TomJsonSerializable], needs none of this: an is test cannot mistake absence for failure.) Detecting one by trying it inside an unqualified catch — whatever comes out, the hook is declared missing and the ordinary field-walking path takes over — would make a hook that does not exist and a hook that exists and is buggy the same event, and the second is the one worth hearing about: the caller's own code failed, and nothing would say so. The failure would then be attributed to the reflection layer, or to nothing at all.

Each hook is therefore looked up before it is called, so absence is settled without running anything and the invocation itself is guarded only for the purpose of attribution. Nothing is inferred from the type of the failure, which matters because tom_reflection does not report absence in one consistent way: a missing constructor raises [NoSuchCapabilityError], but a missing method or getter surfaces as a plain NoSuchMethodError from a dynamic dispatch, because the generated getters map is shared across the whole reflector rather than per class. Catching by type would therefore keep the two cases fused for two hooks out of three, and would additionally re-fuse them for any hook whose own body happens to raise either error.

static TomReflectorException _hookReturnedWrongType(String hook, Object owner, Object? value, String expected)

Reports that an optional conversion hook ran, returned, and returned something unusable.

Falling back to the field walk would be the quiet answer, and the wrong one: the hook exists precisely to replace that walk, so producing the representation it was written to override is not a recovery.

static List<String> _requiredFields(ClassMirror<dynamic> cm)

The names of the [TomRequiredField] fields [cm] and its superclasses declare, most derived first.

The chain is walked because declarations holds a class's own members only, and a configuration class inherits most of its fields. It ends where the reflector's coverage does: superclass raises rather than answering null for a class outside it, and a requirement declared where nothing can read it is not one this method can report. A name already seen is not repeated, so an override does not report its field twice.

Null and "not covered" are one answer here on purpose: both mean there are no further declarations this reflector can read, and the alternative — a NoSuchCapabilityError escaping — would make a required-field check fail on a class whose parent merely happens to be unreflected.

static Map<String, Object?> _fieldRefusalParameters(String owner, String field, Object declaredType, Object? value, {String? at})

The parameters every refusal of a field's value carries: the class, the field, the field's declared type and the value's runtime type.

The four are what locate a refusal in a payload. The key says how far the reflector got; these say where, and a payload is usually a whole JSON document. The value's type is named in its own right because the only other place it might appear is a root error in the Dart runtime's wording, and a refusal decided by inspection has no root error at all.

static TomReflectorException? _attributedBuildRefusal(TomReflectorException error, StackTrace stack, {required String owner, required String field, required Object declaredType, required Object? value, String? at})

[error] re-raised with the field it was building a value for, or null when it should travel as it is.

A build refusal names the type that would not build and nothing else, because that is all the builder knows: "Failed to create instance of type List" is true, and leaves the caller searching the payload for every field that might hold a list. When the value was being built for a field, the field is the part the caller needs, so the refusal is raised again with [_fieldRefusalParameters] — under the same key, since the key already says the right thing about what went wrong — and the original kept as its rootException. [at] names the element's position when the value was one element of a collection field.

Only an unattributed build refusal is re-raised. Every other key is a verdict that already carries its own context, and a refusal that already names a field was claimed by a nested field closer to the fault: attribution is innermost, so an enclosing field must not overwrite it.

static T _parseDateTimeString<T>(String text, T Function(String) parser, {required String owner, required String field, required Object targetType, String? at})

Parses [text] into a date/time value, naming the site on failure.

Why: DateTime.parse and the TomZoned* parsers throw a bare [FormatException] that carries the offending text and nothing else. static TomReflectorException _allFinalException(Object o, List<String> skipped)

The exception raised when every wire member of a class was skipped for being final.

final members are skipped because they cannot be restored: no reflective deserializer can assign one after construction, so emitting them would buy a payload that never round-trips — asymmetric in the direction that loses data quietly. That skip is not in question here.

What is in question is the answer it produced. A class made entirely of final members walked every declaration, dropped every one, and returned {} reported as success: the same valid-looking payload with everything gone that [_notAnnotatedException] exists to prevent, reached by a different route. The silence is the defect, not the skip — an empty body with no diagnostic is what sends developers back to hand-written serializers, which is the outcome the reflective path exists to avoid.

The condition is deliberately narrow: nothing was contributed and something was dropped. A class declaring no wire members at all still renders {}, because there {} is the truth; a class contributing even one field is left alone, because a caller can see which field survived and infer the rest. Only total, invisible loss is refused.

This is not a ban on immutability. All four rendering hooks — [TomClass], [TomJsonSerializable], a structural toJson(), a jsonEncode getter — are consulted before the walk, so an immutable DTO that says how it renders never arrives here. The refusal asks for that decision to be made, not for the fields to be made mutable.

class TomRequiredField

class TomRequiredField

Marks a reflected field as one that a bound map must supply a value for.

The annotation states the requirement next to the field it constrains; it does not enforce it. [TomReflectionInfo.missingRequiredFields] reads it and reports, and the caller decides what an unsupplied setting means — which is the same division [TomReflectionInfo.unknownFields] makes, and for the same reason: the converter knows the class, not where the map came from or how bad it is for that particular setting to be absent. 

@tomReflector
class BillingConfiguration extends TomBaseServerConfiguration {
  @TomRequiredField()
  String dbUrl = '';
}

Binding cannot report this by itself. A setting no source supplied leaves the field at its initialiser, which is indistinguishable from a setting that was never required — so the failure surfaces much later, as a connection to localhost:0 or an empty application id.

A field with a fallback is not required. The requirement is that a source named the setting, so a field whose constructor applies a default when nothing was configured must not carry this: it would refuse the very launch the default exists to serve.
