import 'package:tom_core_kernel/src/tombase/json/map_merge_and_process.dart';

Utilities for merging and processing nested JSON map structures.

This module provides functions for: - Deep merging of nested Map<String, dynamic> structures - Tree traversal with custom processing callbacks - Path-based access to nested map values - Tree modification with profile-based injection patterns

These utilities are particularly useful for configuration management, where base configurations need to be merged with environment-specific overrides while preserving nested structure.

What counts as a subtree

Every function here that walks a tree treats any map whose keys are all String as a subtree, whatever its reified type: Map<dynamic, dynamic>, Map<String, String> and Map<String, dynamic> are descended into alike. The reified type is not under the caller's control as often as it looks — jsonDecode always yields Map<String, dynamic>, but TomYaml, a hand-written literal and anything round-tripped through an untyped container do not. Testing for a reified Map<String, dynamic> would skip all of those silently, so the test here is on the keys.

A map with a non-String key is not a subtree: it cannot be a JSON object and every callback here takes a String key, so it is skipped whole rather than walked halfway. The in-place traversals still edit in place — the string-keyed view they walk writes through to the caller's map.

Cycles

A JSON document is a tree, but the Dart maps and lists these functions are handed are a general object graph: nothing stops a value from referring back to one of its own ancestors. Every function here that walks a tree therefore keeps the containers on its current path and recognises such a reference instead of following it, because following it recurses until the stack is exhausted — and a StackOverflowError is an Error rather than an Exception, so no documented handling catches it.

The walkers raise [TomJsonCycleException]. [makeCleanJsonMap] does not: it exists to make a value safe to encode or log, so a back-reference is dropped there like any other value with no JSON form.

A container that appears twice at different places is not a cycle. That is a directed acyclic graph, it encodes and copies perfectly well, and only a container that encloses itself is refused.

Example: Merging configurations

final base = {'database': {'host': 'localhost', 'port': 5432}};
final override = {'database': {'host': 'production.db.com'}};
mergeMapsOneSided(base, override);
// base is now {'database': {'host': 'production.db.com', 'port': 5432}}

class TomJsonCycleException

class TomJsonCycleException extends TomException

Raised when a tree walk meets a value that refers back to one of its own ancestors.

Raised by [deepCopyJsonTree], [mergeMapsOneSided], [traverseAndProcess], [traverseAndCreate], [substituteEnvVars] and [processTree] — every function here that descends into a tree, except [makeCleanJsonMap], which drops the back-reference rather than raising because it exists to produce something encodable.

Distinct from [TomJsonPathException] and [TomJsonDirectiveException] because it says something about the input document rather than about a path or a directive in it: whatever the caller passed is a graph, not a tree, and no walk of it can terminate. A caller that wants to tolerate that will want to catch exactly this and nothing else.

Error key:

  • json.tree.cycle — a container on the current path was reached again.

The parameters carry path (the dotted path to the offending value, with list indices as [i]) and segment (its last step).

class TomJsonDirectiveException

class TomJsonDirectiveException extends TomException

Raised when a profile directive cannot be resolved by [processTree].

Distinct from [TomJsonPathException] because the two are answered differently: a path failure is usually a typo in a caller's path, while a directive failure is usually a provider that looked in the wrong place. A caller that could only catch Exception had to read the message to tell them apart.

This does not cover a failure raised by the provider itself. Those propagate unaltered, by design — see [processTree].

Error keys:

  • json.directive.malformed_key — a key carries three or more @ and so

cannot be an ordinary key, but is not the three-part directive shape either. The parameters carry key. - json.directive.unresolved_key — a "@" directive's provider returned no entry under the directive's own key. The parameters carry key, path, profile and providerKeys.

class TomJsonPathException

class TomJsonPathException extends TomException

Raised when a dot-separated path cannot be resolved against a tree.

Both [getObjectFromTree] and [getPathFromTree] raise it, and only for a path that does not lead anywhere. A terminal key that is present and holds null is a value, not a failure, and is returned — that distinction is the reason this is an exception rather than a null return.

Error keys, each naming a condition a running system can meet:

  • json.path.missing_key — no key of that name at that position. The

parameters carry path, key and position. - json.path.not_a_subtree — a segment before the last holds a scalar or null, so there is nothing to descend into. The parameters carry path, key, position and holds.

class _AncestorPath

class _AncestorPath

The chain of containers the current walk has descended through, so a value that refers back to one of its own ancestors can be recognised rather than followed forever.

Membership is by identity, and covers only the current path rather than every container already visited. A document may legitimately hold the same subtree at two places — that is a directed acyclic graph, it copies and encodes perfectly well, and an all-visited set would refuse it. Only a container that is its own ancestor closes a cycle.

Guard on the value a container was reached through, never on a view of it: [_asStringKeyedMap] returns a fresh cast wrapper on every call for a map that is not already Map<String, dynamic>, so a view is a different object each time and could never be recognised as its own ancestor.

class _TreeModification

class _TreeModification

Internal class representing a pending tree modification.

Encapsulates a deferred modification to be applied to a tree structure. Modifications are collected during traversal and applied afterward to avoid modifying the tree while iterating.

Every field is final and non-nullable, so an instance that exists is always applicable. Nullable fields that [apply] cleared on its way out would create a half-applied state describable only by a defensive throw — one that could not say whether the modification had already been applied or the tree was null, guarding a state the module has no path to. A non-directive key is represented by returning null from [_modifyTree] rather than by a mutable singleton standing in for "nothing to do".

Methods

void apply()

Applies this modification to the tree, and consumes the directive.

Behavior depends on [value]: - "...": Spreads [insertTree] entries into [tree] (non-overwriting) - "@": Replaces the value at [keyName] with the corresponding value from [insertTree] - Other: Sets [keyName] to the entire [insertTree]

The "@" directive assumes [insertTree] contains [keyName]; that is checked in [_modifyTree], before any modification is applied.

[directiveKey] is then removed. Removal comes after the write so the spread's non-overwrite check sees the tree the directive found; the two keys cannot collide in any case, since a directive key contains @ and [keyName] is the part before the first one.

function _asStringKeyedMap

Map<String, dynamic>? _asStringKeyedMap(Object? value)

A Map<String, dynamic> view of [value], or null if it is not a map this module can walk.

Testing a child with is Map<String, dynamic> directly would be a reified test: a Map<dynamic, dynamic> fails it, and would be walked past without an error or a log line, leaving its contents silently untransformed. jsonDecode never produces such a map, so the common path would look correct, but TomYaml.loadYamlFile, hand-built maps and anything round-tripped through an untyped container all do — which is why the check is on the keys rather than the reified type.

The returned view writes through to [value], which is what lets the in-place traversals keep their contract: a caller holding the original map sees the edits. Callers that need to store the result in a tree should prefer a real copy, because a cast view revalidates on every write.

A map with a non-String key returns null and is skipped. It cannot be a JSON object, and every callback here takes a String key, so there is nothing meaningful to hand them; walking it halfway would be worse than not walking it. The scan that establishes this is O(keys), paid only for a map that is not already Map<String, dynamic>.

function _cleanJsonValue

Object? _cleanJsonValue(Object? value, _AncestorPath path, String segment)

Returns a JSON-clean copy of [value], or [_notJsonEncodable] when it is not a JSON-compatible type (in which case the caller filters it out).

A null [value] returns null — it is a JSON value, not a failure — which is why the "no JSON form" answer needs its own sentinel.

Shared by [makeCleanJsonMap] and [_cleanList] so the type dispatch — scalars and null pass through, [TomJsonSerializable] converts, maps and lists recurse, everything else is dropped — is defined in exactly one place.

This is the only function in the module that knows [TomJsonSerializable] exists, and deliberately so. The tree functions ([traverseAndProcess], [traverseAndCreate], [substituteEnvVars]) rewrite strings in place inside mutable maps and lists; a value object is immutable and opaque, so there is nothing for them to step into. They also operate on decoded JSON, which never contains a Dart object in the first place. Sanitisation is the one point where a live object tree meets JSON, so it is the one place the interface belongs.

function _createInList

void _createInList(List<dynamic> list, bool Function(String) nameTest, void Function(String, String, Map<String, dynamic>) creator, _AncestorPath path)

Applies [traverseAndCreate]'s rules to the elements of [list], in place.

Dispatch is per element rather than on the list's own type, so mixed lists from jsonDecode — List<dynamic> holding maps, strings and further lists side by side — are handled. A typed check on the list itself (List<Map<String, dynamic>>) never matches a decoded JSON list at all and skips its contents in silence, which is a worse answer than not descending: a directive inside an array read from disk stays in the tree looking exactly like one that was resolved.

A list element recurses through this same function, so a list nested inside a list is reached at any depth.

Unlike [traverseAndProcess]'s list walk there is no string branch, and the asymmetry is the point rather than an omission: this traversal selects on key names, and an element of a list has no key to test. A string only reaches [creator] as the value of a matching key.

function _mergeListsOneSided

List<dynamic> _mergeListsOneSided(List<dynamic> base, List<dynamic> override, String name)

Merges [override] into [base] positionally and returns the merged list.

Each overlapping element pair is combined by the same rules [mergeMapsOneSided] applies to a key/value pair, so "merged element-by- element" means the same thing at every depth:

  • two maps merge recursively;
  • two lists merge positionally, through this function;
  • a map or list override landing on a base element of another shape is a

structural mismatch: it is refused with an error and the base element stays, exactly as a subtree override onto a scalar key does; - anything else — every scalar — is replaced by the override element.

Base elements past the override's length are kept; override elements past the base's length are appended. [name] only labels error messages.

The result is always a fresh List<dynamic> rather than [base] mutated in place. [base] may be reified narrowly — a literal like [<String, Object>{'a': 1}] is a List<Map<String, Object>> at runtime, and writing a scalar override element into it would throw — so a list that accepts every element type has to be allocated for the result.

function _modifyTree

_TreeModification? _modifyTree(String name, String value, Map<String, dynamic> tree, Map<String, dynamic> Function(String, String, String) provider)

Creates a tree modification from a profile-based key pattern.

Parses keys matching the pattern keyName@path@profileName and creates a modification that will inject data from the specified profile.

A key that does not match is an ordinary key and yields no modification — an email address is not a directive.

Throws [Exception] if the key carries enough @ to be a directive but is not a well-formed one, or if the "@" directive is used and the provider's result has no entry named keyName — the value that directive exists to take.

Whatever the provider throws is not caught: it reaches the caller with its own type and its own stack trace.

function deepCopyJsonTree

Map<String, dynamic> deepCopyJsonTree(Map<String, dynamic> source)

Returns a deep copy of [source] that shares no map or list with it.

Every nested map and list is rebuilt, so writing anywhere in the copy — including deep inside it — cannot reach [source]. This is what Map<String, dynamic>.from does not give you: that copies only the top level, leaving every nested subtree shared, so an in-place merge into the "copy" writes straight through into the original.

Use it to keep a document intact across a [mergeMapsOneSided], which mutates its first argument:

final merged = deepCopyJsonTree(baseConfig);
mergeMapsOneSided(merged, overrides);
// baseConfig is untouched

Maps are normalised to Map<String, dynamic> and lists to List<dynamic>, because a copy exists to be written into and a narrowly reified container would throw on the first value of another type. Non-String keys are converted with toString(); a JSON object's keys are strings by definition.

Scalar leaves are shared rather than copied. That is correct for the JSON scalars — String, num, bool, null are immutable — and is the only option for any other object a tree happens to carry, which cannot be cloned generically.

Throws [TomJsonCycleException] when a container refers back to one of its own ancestors. A copy of such a graph is not expressible here anyway: every container is rebuilt, so a shared subtree becomes two independent copies, and a self-reference has no copy to point at. See the library doc's Cycles.

function getObjectFromTree

Object? getObjectFromTree(Map<String, dynamic> baseTree, String path)

Retrieves any object from a nested map using a dot-separated path.

Similar to [getPathFromTree], but returns the raw value at the path rather than wrapping non-map values.

Parameters

  • [baseTree]: The root map to navigate from
  • [path]: Dot-separated path string (e.g., "database.port")

Returns

The value found at the specified path — a Map, List, String, int, or null. A null return means the terminal key is present and holds null, which is a value; a path that cannot be resolved throws instead. Absence is decided by containsKey, matching [makeCleanJsonMap], which keeps a present null for the same reason: an absent field and a field that is present and null mean different things.

Throws

  • [Exception] if a segment names a key that is not there.
  • [Exception] if an interior segment resolves to something with no subtree

to descend into — including null, which is a fine terminal value but cannot be walked through. The message distinguishes the two cases. An interior map is walked through whatever its reified type, as long as its keys are all String; see the library doc's What counts as a subtree.

Example

final config = {'db': {'port': 5432, 'replica': null}};
getObjectFromTree(config, 'db.port');     // 5432
getObjectFromTree(config, 'db.replica');  // null — present, deliberately
getObjectFromTree(config, 'db.absent');   // throws

function getPathFromTree

Map<String, dynamic> getPathFromTree(Map<String, dynamic> baseTree, String path, String name)

Retrieves a subtree from a nested map using a dot-separated path.

Navigates through [baseTree] following the [path] (e.g., "database.connection.pool") and returns the map at that location. If the path leads to a non-map value, wraps it in a map with [name] as the key.

Parameters

  • [baseTree]: The root map to navigate from
  • [path]: Dot-separated path string (e.g., "level1.level2.level3")
  • [name]: Key name to use when wrapping non-map terminal values

A terminal null is a non-map value and is wrapped like any other, giving {name: null}. That keeps it distinguishable from an absent path, which throws — see [getObjectFromTree] for why the two are not collapsed.

A map at the path is a subtree, and so returned rather than wrapped, whatever its reified type, as long as its keys are all String; see the library doc's What counts as a subtree.

Wrapping is silent: it is what this function exists to do, and the returned map says which branch was taken. A caller that wants the raw value, or wants to decide for itself, calls [getObjectFromTree].

Throws

  • [Exception] if the path cannot be resolved or contains invalid segments

Example

final config = {'db': {'host': 'localhost', 'settings': {'pool': 10}}};
final settings = getPathFromTree(config, 'db.settings', 'result');
// Returns {'pool': 10}

function makeCleanJsonMap

Map<String, Object?> makeCleanJsonMap(Map<dynamic, dynamic> map)

Recursively cleans a map to ensure it contains only JSON-compatible types.

Creates a new map containing valid JSON values (String, int, double, bool, null, Map, List). Entries with non-String keys, and values of any other type, are filtered out.

null is a JSON value and is kept. An absent field and a field that is present and null mean different things — to a PATCH-style partial update, to a settings map where null means "explicitly cleared", to a DTO whose schema declares the field nullable — and the sanitiser preserves that distinction rather than collapsing it.

The one exception to the type filter is [TomJsonSerializable]: a value implementing it is converted through its toJson() and the result cleaned in turn, wherever it appears in the tree — at the top level, nested in a sub-map, or inside a list. That is the interface's whole purpose, and dropping such a value would discard state the object was explicitly written to expose.

This is useful when working with maps that may contain non-serializable types (e.g. DateTime, custom objects) and need to be converted to pure JSON. Note that filtering is silent: a DateTime disappears without an error, so give a type a toJson() via [TomJsonSerializable] when its value must survive.

A cycle is dropped, not raised

A value that refers back to a container already enclosing it is filtered out like any other value with no JSON form — a cyclic reference has none, and jsonEncode refuses one. This function is the module's one walker that does not raise [TomJsonCycleException], because it exists to hand back something encodable and loggable: turning a log call into an exception would be as poor a trade as turning it into a stack overflow.

The test is on the enclosing containers only, so the same subtree appearing at two places is emitted twice rather than refused. A [TomJsonSerializable] is tracked as well as the maps and lists, because its toJson() builds a fresh map at every call and a parent re-serialised at each level would otherwise never repeat. 

final m = <String, dynamic>{'name': 'x'};
m['self'] = m;
makeCleanJsonMap(m);   // {'name': 'x'} — the back-reference is dropped

Parameters

  • [map]: The source map to clean (not modified)

Returns

A new Map<String, Object?> containing only JSON-compatible entries.

Example

final dirty = {'name': 'App', 'created': DateTime.now(), 'port': 8080};
final clean = makeCleanJsonMap(dirty);
// clean = {'name': 'App', 'port': 8080}  (DateTime filtered out)

// A deliberate null survives; only what cannot be encoded is dropped.
final patch = {'discount': null, 'when': DateTime.now()};
makeCleanJsonMap(patch);
// {'discount': null}

// A TomJsonSerializable is converted rather than dropped.
final withValue = {'name': 'App', 'price': Money(12, 'EUR')};
final cleaned = makeCleanJsonMap(withValue);
// cleaned = {'name': 'App', 'price': {'amount': 12, 'currency': 'EUR'}}

function mergeMapsOneSided

void mergeMapsOneSided(Map<String, dynamic> base, Map<String, dynamic> override)

Recursively merges [override] map into [base] map (one-sided deep merge).

This function performs a deep merge where: - Nested maps are merged recursively - Arrays are merged element-by-element over the overlapping prefix, then take [override]'s tail; base elements past [override]'s length are kept. Each element pair follows the same rules as a key/value pair: maps merge recursively, lists merge positionally, and any other override element replaces the base element. - Primitive values from [override] replace values in [base] - Keys in [override] that don't exist in [base] are added

A structural mismatch — an [override] map or list landing on a base value of another shape, at a key or at a list index — is refused with a logged error, and the base value is kept.

Important: This modifies [base] in-place. To keep the original intact, copy it with [deepCopyJsonTree] first — Map<String, dynamic>.from is shallow and leaves every nested subtree shared, so the merge would write through into the map you meant to protect.

[override] is deep-copied before the merge, so it is never modified and the merged tree shares no map or list with it. The two documents therefore stay independent: a later edit to either cannot reach the other. This matters in the layered-config flow the function exists for — without it, mergeMapsOneSided(base, env); mergeMapsOneSided(base, local); would leave base holding live references into both documents, and the second merge would write back into the first. Scalar leaves are shared rather than copied, which is safe because JSON scalars are immutable.

A base subtree counts whatever its reified type, as long as its keys are all String; see the library doc's What counts as a subtree.

Throws [TomJsonCycleException] when [override] contains a cycle — raised by the deep copy, before any of [base] is touched. [base] needs no guard of its own: the merge descends only where [override] descends, and [override] has by then been rebuilt as a tree, so the recursion is bounded by its depth however the base tree is shaped.

Parameters

  • [base]: The target map that will be modified with merged values
  • [override]: The source map whose values will be merged into [base]

Example

final base = {
  'server': {'host': 'localhost', 'port': 8080},
  'features': ['auth', 'logging']
};
final override = {
  'server': {'host': 'api.example.com'},
  'features': ['oauth', 'logging', 'metrics']
};
mergeMapsOneSided(base, override);
// Result: base['server']['host'] == 'api.example.com'
// Result: base['server']['port'] == 8080 (preserved)
// Result: base['features'] == ['oauth', 'logging', 'metrics']
//   index 0 replaced, index 1 unchanged, index 2 appended

function processTree

void processTree(Map<String, dynamic> tree, Map<String, dynamic> Function(String, String, String) provider)

Processes a tree by resolving profile-based references.

Scans the [tree] for keys containing "@" patterns (e.g., database@profiles@production) and resolves them using the [provider] function to inject configuration data.

Parameters

  • [tree]: The configuration tree to process (modified in-place)
  • [provider]: Function that resolves profile references to configuration data.

Takes (keyName, path, profileName) and returns the data to inject.

Key Pattern Format

Keys must match keyName@path@profileName in full: - keyName: The resulting key name after resolution - path: The path within the profile to extract - profileName: The name of the profile to use

All three parts are non-empty and the match covers the whole key, so a key with a fourth part is not resolved against its first three. A key that does not match is an ordinary key and is left untouched — user@example.com and @scope/package@1.0.0 are keys, not directives. Only a key carrying three or more @, which no ordinary string in this framework does, is reported as a malformed directive rather than ignored.

Value Directives

  • "...": Spread the resolved data into the current map
  • "@": Replace with the value at the same key from resolved data
  • Other: Replace with the entire resolved data structure

The "@" directive takes the value the provider returned under the same key, so wanted@path@profile: "@" needs a provider result containing wanted. A result containing the key with a null value is a value like any other and is assigned; only an absent key is a failure.

The directive key is consumed

A resolved directive's own key is removed from its map. A directive is an instruction, and one that has been carried out is not part of the configuration it produced — so the resolved tree is ordinary data that can be encoded, diffed or merged without carrying work still to do beside its result.

The consequence worth naming is idempotence: running this again over an already-resolved tree calls the [provider] for nothing, because there is no directive left to resolve. A provider is typically a vault read or a file load, and may have side effects.

Removal happens with the write, not with the resolution, so the collect-before-apply guarantee below covers it: a failure leaves every directive key exactly where it was.

Failures

Throws [TomJsonDirectiveException] if: - a key carries three or more @ but is not a well-formed directive (json.directive.malformed_key) — the message names the key and restates the expected form; - a "@" directive's provider result has no entry under the directive's key (json.directive.unresolved_key) — the message names the key, the resolved path, the profile and the keys the provider did return.

Throws [TomJsonCycleException] when [tree] contains a container that refers back to one of its own ancestors, through the [traverseAndCreate] this is built on. It is raised during collection, so no directive has been applied.

Anything the [provider] throws propagates unaltered — same type, same message, same stack trace — so a caller can catch on the provider's own failure type instead of recovering it from a string. Nothing is wrapped around it, because the only context a wrapper could add is the directive key, and that is just the three arguments the provider was called with. A provider whose own errors need to name the profile it was resolving should say so itself; this function will not paraphrase it.

Every directive is resolved before any is applied, so a failure leaves [tree] exactly as it was passed: the operation does not half-complete. That holds for a provider failure too — a directive resolved earlier in the same call is discarded rather than written.

function substituteEnvVars

void substituteEnvVars(Map<String, dynamic> tree, Map<String, String> environment)

Substitutes environment variable placeholders in all string values of a map tree.

Processes the entire [tree] in-place, replacing placeholders like ${VAR_NAME} with values from the provided [environment] map. Supports default values using the syntax ${VAR_NAME:default}.

Throws [TomJsonCycleException] when a container refers back to one of its own ancestors, through the [traverseAndProcess] this is built on.

Parameters

  • [tree]: The nested map structure to process (modified in-place)
  • [environment]: Map of environment variable names to values

Placeholder Syntax

  • ${VAR_NAME} — replaced with the environment value, or left unchanged if

there is none - ${VAR_NAME:default} — replaced with the environment value, or default if there is none

An empty value counts as unset

A variable present in [environment] with an empty value is treated exactly as an absent one: {'VAR': ''} and {} produce the same result. This follows the shell's ${VAR:-default} convention, which the : in ${VAR:default} mirrors — the colon form is precisely the one that folds empty into unset.

The consequence is worth stating plainly, because it looks asymmetric until the convention is named:

substituteEnvVars({'a': r'${V:fallback}'}, {'V': ''});  // 'fallback'
substituteEnvVars({'a': r'${V}'},          {'V': ''});  // '${V}' survives
substituteEnvVars({'a': r'${V:}'},         {});         // '' — empty default

An empty default is a default that happens to be empty, and resolves; an empty value does not. So a caller passing Platform.environment cannot express "this variable is deliberately empty" — a VAR= in the environment leaves a literal ${VAR} in the tree unless a default is supplied. Give the placeholder an explicit empty default, ${VAR:}, when empty is the intended resolution.

That limit is the shell's too, and is left standing deliberately. A shell script written with ${VAR:-default} cannot be handed an empty value either; the shell's escape is a second form, ${VAR-default}, which this module has no counterpart to. Adding one would not help the operator the limit is about, because either form lives in the config file rather than in the environment they set — so the choice would still be the config author's, exactly as it is today.

And the author already has it. The gap bites in one combination only: the placeholder is ${VAR} with no default and the operator wants empty. Writing no default is how an author says the value is mandatory, so the surviving placeholder there is the loud failure it is meant to be. Where empty is a legitimate value the author writes ${VAR:}, and then VAR= and an unset VAR both resolve to empty — which is what the operator wanted.

Example

final config = {'host': '${DB_HOST:localhost}', 'port': '${DB_PORT}'};
final env = {'DB_HOST': 'production.db.com', 'DB_PORT': '5432'};
substituteEnvVars(config, env);
// config is now {'host': 'production.db.com', 'port': '5432'}

function traverseAndCreate

void traverseAndCreate(Map<String, dynamic> tree, bool Function(String) nameTest, void Function(String, String, Map<String, dynamic>) creator)

Traverses a nested map tree and creates new entries based on key names.

Similar to [traverseAndProcess], but selects on key names rather than value contents. When a key name matches [nameTest] and its value is a String, the [creator] callback is invoked with the key, that string, and the parent map location, allowing insertion of new nodes.

Which keys reach the creator

The value's shape is part of the match, not just the name. A matching key whose value is a map is recursed into instead of being reported, and one whose value is a list is taken by the list branch and likewise never reported — the branches are mutually exclusive. A matching key whose value is an int, bool or null is skipped outright. This is not incidental: [creator] takes a String value, so no other shape could be handed to it.

This is particularly useful for expanding shorthand notations or creating links/references in configuration trees.

Parameters

  • [tree]: The nested map structure to traverse
  • [nameTest]: Predicate function that tests key names
  • [creator]: Callback invoked for each matching key, receiving the key, its

string value, and the map that contains it. It may insert into, remove from, or overwrite that map directly — the walk iterates a snapshot of each map's keys, so mutating during the callback is safe at every depth, including a map an outer recursion level is still walking.

What a creator's edits are visited by

Keys the creator adds are not traversed: the snapshot for a map is taken before its entries are visited. That is deliberate — a creator that inserts a key its own [nameTest] matches would otherwise call itself forever. Run the traversal again if newly created nodes must themselves be expanded.

An entry the creator removes is simply skipped when the walk reaches it.

A map child counts whatever its reified type, as long as its keys are all String; see the library doc's What counts as a subtree.

Lists are walked per element, so a map inside a list, a list inside a list, and any deeper combination are all descended into. Dispatch is on each value's runtime shape rather than on a container's declared type, which is what makes a document straight out of jsonDecode — Map<String, dynamic> and List<dynamic> throughout — behave the same as one built in Dart code.

Throws [TomJsonCycleException] when a container refers back to one of its own ancestors; see the library doc's Cycles. A creator that inserts a cycle is not caught by this — the keys it adds are never traversed — but the next walk of the tree will refuse it.

Example

final config = {'ref@profiles@dev': 'value'};
traverseAndCreate(
  config,
  (name) => name.contains('@'),
  (key, value, location) {
    location['resolved'] = value.toUpperCase(); // inserting is supported
  },
);
// config = {'ref@profiles@dev': 'value', 'resolved': 'VALUE'}

function traverseAndProcess

void traverseAndProcess(Map<String, dynamic> tree, bool Function(String) test, String Function(String) processor)

Traverses a nested map tree and processes all String values matching a condition.

Recursively walks through the [tree] structure, applying [processor] to any String value where [test] returns true. This modifies the tree in-place.

Every string in the tree is reached, whatever holds it: nested maps recurse, and lists are walked per element, so a map inside a list, a list inside a list, and any deeper combination are all descended into. Dispatch is on each value's runtime shape rather than on a container's declared type, which is what makes a document straight out of jsonDecode — Map<String, dynamic> and List<dynamic> throughout — behave the same as one built in Dart code. A map child counts whatever its reified type, as long as its keys are all String; see the library doc's What counts as a subtree.

Throws [TomJsonCycleException] when a container refers back to one of its own ancestors; see the library doc's Cycles.

Parameters

  • [tree]: The nested map structure to traverse
  • [test]: Predicate function that determines which strings to process
  • [processor]: Transform function applied to matching strings

Example

final config = {'url': '${BASE_URL}/api', 'name': 'MyApp'};
traverseAndProcess(
  config,
  (s) => s.contains(r'${'),
  (s) => s.replaceAll(r'${BASE_URL}', 'https://api.example.com'),
);
// config['url'] is now 'https://api.example.com/api'
