class TomClass

class TomClass extends TomObject<Map<String, TomObject<dynamic>>> implements TomObserver<TomObject<dynamic>>

A base class for complex observable objects with multiple [TomObject] members.

[TomClass] automatically registers all [TomObject] fields as observable members using reflection. When any member changes, the parent [TomClass] is notified and propagates the notification to its own observers.

Features

  • Automatic member registration: Fields are discovered via reflection
  • Cascading observation: Changes to any member notify the parent
  • JSON serialization: Built-in [toJson] and [fromJson] support
  • Batch updates: [setValues] for updating multiple fields at once
  • Muting: Temporarily suppress notifications during bulk updates

Operators

A class is addressed through its members, so the whole-value operators do not apply to it: [get], [set] and << all throw. Write members individually (person.name | "John") or many at once with [setValues]. >> works as it does on any observable, and fires for a change to any member.

Example

@tomReflector
class Person extends TomClass {
  final name = TomString("");
  final age = TomInt(0);
  final email = TomNString(null);
}

final person = Person();
person.name | "John";
person.setValues({"age": 30, "email": "john@example.com"});
print(person.toJson());

Member names are always public

The key is member.simpleName, taken from the reflected getter, and reflection excludes private fields and private accessors — so a member key can never begin with an underscore. A private field published through a public getter registers under the getter's name: 

final TomString _label = TomString("");
TomString get label => _label;   // registers as "label"

This is why [setOrMergeValues] looks a key up once and does not also try an underscore-prefixed variant. It used to, and that fallback could never fire: the name it searched for was one reflection is incapable of producing.

Map<String, TomObject<dynamic>> getMembers()

Returns a read-only view of all registered [TomObject] members.

Keys are the field names, values are the [TomObject] instances. The view is live: members registered later appear in it.

Mutating the returned map throws [UnsupportedError]. Registration is not a caller's decision — it is derived from the declared fields, and a removal from the map would deregister the member without detaching the observer wiring [_registerWithMembers] installed, leaving a half-attached object that nothing outside the class can repair. The members themselves are the live cells, so reading one and assigning through it works as usual.

Failure

The input is usually decoded JSON, so a value of the wrong shape is an ordinary occurrence rather than a programming error, and the method is written to survive one:

  • The work runs inside a [batch], which releases in a finally, so a

rejected value cannot leave the object — or its members, which the batch cascades to — permanently silent. Whatever was applied before the failure is announced at that point: the object has changed, and hiding it would be worse than reporting a partial update. - Whatever the underlying failure was, it surfaces as a [TomObservableException] naming the offending key and the runtime type actually supplied. Unwrapped, a mistyped member surfaces as a bare TypeError from deep inside a cast, which identifies neither.

This is the one place where << is not available, and the asymmetry with [TomList.operator <<] and [TomMap.operator <<] is deliberate: their contents are replaceable, whereas a class's set of members is fixed by its declaration. Replacing it wholesale is not a write, it is a different object.

static List<Object?>? _primitiveListFor(TomObject<dynamic> member, List<dynamic> value)

[value] re-typed for a scalar member holding a whole list of primitives, or null when [member] is not one.

getValues() serializes a TomList<TomString> as a plain List<dynamic>, and a member typed TomObject<List<String>> — a multi-select form field is exactly that — rejects the dynamic list in set, so a state's own serialization could not be bound back. The same asymmetry holds for every primitive the framework serializes, so each is re-typed here, next to the int-into-double widening that answers the same round-trip problem for a single number; a List<double> member widens its integral elements too. Re-typing is not coercion: an element of the wrong type throws, and the assignment fails as a scalar's would.

Each test is written against the nullable list type, so a member holding List<String> and one holding List<String>? both match by covariance.

static Object? _serializeMember(TomObject<dynamic> value)

Serializes a single observable member to a JSON-safe value.

Applies the same per-type handling to a member as [getValues] applies to a TomClass's own fields — and, crucially, is reused for the elements of a [TomList] and the values of a [TomMap]. Both containers' get() returns the backing collection with its TomObjects still wrapped, so a TomList<TomString> or a TomMap<String, TomInt> — or either holding nested TomClasses — would otherwise leak raw TomObject instances into jsonEncode, which refuses them. Nested containers recurse the same way.

A map's keys pass through unchanged. The value side is the one that holds TomObjects; a key is whatever K is, and [setValues] restores it from the decoded map's own keys, so rewriting keys here would break the round trip rather than serve it.

class TomDateRange

class TomDateRange extends TomClass

An observable date range with start and end dates.

Both dates are nullable [TomNOZonedDate] values, allowing open-ended ranges, and a fresh range holds null at both ends.

null rather than the noZonedDate epoch sentinel, because the two families answer "no value" differently and these members belong to the nullable one: [TomOZonedDate.setByString] turns an empty @D@ into the sentinel, [TomNOZonedDate.setByString] turns it into null. Initialising a nullable member with the other family's sentinel gave a range two distinct empty states — a fresh one where [TomObject.isNull] answered false, and one deserialized from an empty marker where it answered true — so a consumer branching on isNull got different answers for two ranges that were both unset, and a fresh range serialized two timestamps nobody had entered.

Example:

final vacation = TomDateRange();
final today = DateTime.now();
vacation.startDate | TomZonedDate.fromDateTime(today);
// Add the duration to the `DateTime`, before wrapping: arithmetic
// inherited from `DateTime` returns a plain `DateTime`, not a zoned one.
vacation.endDate | TomZonedDate.fromDateTime(today.add(Duration(days: 7)));

class TomList

class TomList<E extends TomObject<dynamic>> extends TomObject<List<E>> implements TomObserver<TomObservable>, Iterable<E>

An observable list that automatically observes all contained elements.

[TomList] wraps a [List] of [TomObject] elements and provides: - Automatic observation of all elements (changes in elements notify the list) - All standard [List] operations with observer management - Custom operators for convenient element manipulation

It implements [Iterable], not [List]: the standard operations are provided, but a TomList<E> is not assignable to a List<E>. Use [toList] (which returns a copy) at a boundary that insists on the dart:core type, or type the parameter as Iterable<E>.

Methods

  • list.append(element) - Add an element (returns the list for chaining)
  • list[index] - Get element at index
  • list[index] = value - Set element at index
  • list + other - Concatenate two TomLists
  • list << [a, b] - Replace all elements in one notification, returning

the list (see [TomList.operator <<]). Note that << swaps the contents wholesale; to add a single element, use append

Notification contract

A mutator notifies exactly once when it changed the list's contents, and not at all when it left them as they were. clear() on an empty list, addAll([]), sort() on an already-sorted list and list[0] = list[0] are all silent. "Contents" means the sequence of element references, compared by identity — swapping in an equal-but-distinct element is a real change, because observers hold references. A change inside an element is not the mutator's business: it reaches observers through [onNotify].

The one deliberate exception is [resetWith], which notifies even when the new contents happen to equal the old ones — its lifecycle listeners have already torn down and rebuilt whatever they hold per element.

Example

final items = TomList<TomString>();
items.append(TomString("first"));
items.append(TomString("second"));

// Retain the observer — it is held weakly.
final observer = items >> (obs) => print("List changed!");
items[0] | "updated"; // Triggers observer

items.removeObserver(observer);

void _resetWithDynamic(Iterable<TomObject<dynamic>> elements)

Loosely-typed variant of [resetWith] used by deserialization.

[TomClass._setListMember] builds new elements reflectively into a List<TomObject<dynamic>>; every element is really an E, but the list's reified type is not List<E>. Operators

TomList<E> operator <<(List<E> value) override

Replaces every element with [value] and returns this list.

This is the operator form of a wholesale swap, and on a list it is not what [set] does — [set] throws, because replacing the backing list behind the element observers would silently strand them. << performs the swap properly: it detaches the outgoing elements, attaches the incoming ones, and emits one notification for the whole exchange rather than one per element. 

final rows = TomList<TomString>();
rows << [TomString('x'), TomString('y')];   // one notification

Silent if the new sequence is element-for-element identical to the old one. The comparison is by identity, not equality, because observers hold element references: swapping in an equal-but-distinct element is a real change. See [resetWith] for the same swap with lifecycle callbacks, which for that reason notifies unconditionally.

E operator [](int index)
void operator []=(int index, E value)
TomList<E> operator +(TomList<E> other)
bool operator ==(Object other) override

Identity, not contents: a list equals only itself.

Two lists holding equal elements are unequal, and that is deliberate. A TomList is a mutable cell, so a content-based equality would need a content-based [hashCode], and an object whose hash changes while it sits in a Set or serves as a Map key can no longer be found there. Dart's own List and Map decline content equality for exactly this reason, and so does every other observable in this library — [TomObject], [TomClass] and the scalars all inherit identity equality from Object. This override states the same rule explicitly, because a type that implements Iterable invites the opposite assumption.

Identity is also the honest answer for what the type is: observers register per instance, so two lists with equal elements are different cells with different observers and different parents.

To compare contents, unwrap the elements. Those are observables too and compare by identity in turn, so comparing the raw lists — ~a == ~b, or any list-equality helper over them — is not enough: 

bool sameContents(TomList<TomInt> a, TomList<TomInt> b) =>
    a.length == b.length &&
    Iterable<int>.generate(a.length).every((i) => ~a[i] == ~b[i]);

For a list of nested [TomClass] elements compare getValues() per element instead.

Static

static TomList<E> castFrom<S extends TomObject<dynamic>, E extends TomObject<dynamic>>(TomList<S> source)

A new list of type E holding [source]'s elements.

The structure is copied; the elements are shared. The two lists are independent cells from here on — adding to one does not add to the other — but they hold the same element instances, so both observe them and a change inside an element notifies both. That is inherent to a cast: no new elements can be manufactured, only re-typed. [source] is left untouched and fully functional; nothing is taken from it.

A live re-typed TomList sharing the backing list is deliberately not offered: each container carries its own observers, so a shared structure would let one side grow the other without notifying it, and would leave elements added through one side unobserved by the other. When a live view is what you want, [cast] gives one — read-only, and a plain List<R> rather than an observable cell. Use [TomList.of] for this copy without the re-typing.

Both type arguments must be written out — Dart takes type arguments all-or-nothing, so S cannot be left to inference even though [source] determines it: 

final ints = TomList<TomInt>()..add(TomInt(1));
final widened = TomList.castFrom<TomInt, TomObject>(ints);

Throws a TypeError here, not on a later read, if an element is not an E: the copy type-checks the whole sequence up front.

class TomListLifecycleListener

abstract class TomListLifecycleListener

Listener for structural reset events on a [TomList].

Register via [TomList.addLifecycleListener]. Implementors are notified around the [TomList.resetWith] batch-replacement operation so they can tear down state tied to the old elements before the list is cleared and re-create state for the new elements after they are installed.

This is the mechanism used by TomListForm in tom_flutter_ui to keep its sub-form instances in sync when TomClass.setValues() replaces the contents of a list member (e.g. when an outer form discards its changes and restores the bind-time snapshot).

class TomMap

class TomMap<K, V extends TomObject<dynamic>> extends TomObject<Map<K, V>> implements TomObserver<TomObservable>

An observable map that automatically observes all contained values.

[TomMap] wraps a [Map] with [TomObject] values and provides: - Automatic observation of all values (changes in values notify the map) - All standard [Map] operations with observer management - Custom operators for convenient manipulation

Note: Keys are not observed, only values.

It implements no [Map] interface: the standard operations are provided, but a TomMap<K, V> is not assignable to a Map<K, V>. Use [get] (which returns a copy) at a boundary that insists on the dart:core type. Note the asymmetry — [get] works, whereas [set] throws.

Operators

  • map[key] - Get value for key
  • map[key] = value - Set value for key
  • map + other - Merge two TomMaps
  • map << {...} - Replace all entries in one notification, returning

the map (see [TomMap.operator <<])

Notification contract

A mutator notifies exactly once when it changed the map's contents, and not at all when it left them as they were. remove of an absent key, addAll({}), clear() on an empty map and re-binding a key to the value it already holds are all silent; remove of a present key notifies. "Contents" means the key-to-value-reference mapping, compared by identity — swapping in an equal-but-distinct value is a real change, because observers hold references. A change inside a value is not the mutator's business: it reaches observers through [onNotify].

Example

@tomReflector
class Person extends TomClass {
  final name = TomString("");
}

final users = TomMap<String, Person>();
users["john"] = Person();

// Retain the observer — it is held weakly.
final observer = users >> (obs) => print("Map changed!");
users["john"]!.name | "John Doe"; // Triggers observer

users.removeObserver(observer);

Replaces every entry with [newMap] and returns this map.

The map counterpart of [TomList.operator <<], with the same contract: [set] throws on a map, so this is the operator form of a wholesale swap. It detaches the outgoing values, attaches the incoming ones, and emits one notification for the exchange rather than one per entry. 

final scores = TomMap<String, TomInt>();
scores << {'ada': TomInt(10), 'bob': TomInt(8)};   // one notification
bool operator ==(Object other) override

Identity, not contents: a map equals only itself.

The rule, and the reasoning behind it, are the same as for [TomList.operator ==] — a mutable cell cannot carry a content-based [hashCode] without going missing from the Set it was put in, and observers register per instance, so two maps with equal entries are different cells. Every other observable in this library inherits the same identity equality from Object.

To compare contents, unwrap the values; they are observables in their own right and compare by identity too: 

bool sameContents(TomMap<String, TomInt> a, TomMap<String, TomInt> b) =>
    a.length == b.length &&
    a.keys.every((k) => b.containsKey(k) && ~a[k]! == ~b[k]!);

static TomMap<K2, V2> castFrom<K, V extends TomObject<dynamic>, K2, V2 extends TomObject<dynamic>>(TomMap<K, V> source)

A new map of type K2/V2 holding [source]'s entries.

The structure is copied; the values are shared. Same contract as [TomList.castFrom] — the two maps are independent cells, but they hold the same value instances, so both observe them and a change inside a value notifies both. abstract class TomOTimezoned<TZ extends TomTimezoned?> extends TomObject<TZ>

An observable wrapper for [TomTimezoned] values (timezone-aware date/time).

This is the base class for timezone-aware observable types: - [TomOZonedTime] - time with timezone - [TomOZonedDate] - date with timezone - [TomOZonedDateTime] - datetime with timezone

The class is abstract, and so is [setByString]: see that method for why a concrete base would be a data-loss hazard. [getSerializationPrefix], by contrast, has a usable default and may simply be inherited.

Constructors

Creates a new observable timezone-aware value with the given initial value.

Methods

String getSerializationPrefix()

Returns the wire prefix that marks a serialized value of this flavour.

Defaults to [TomZonedDateTime.serializationPrefix] (@X@), which is correct for the datetime subtypes — they inherit this method rather than restating it. The date and time subtypes override it with @D@ / @T@.

Unlike [setByString] this has a defensible default, so it is concrete: a subtype that inherits the wrong prefix produces a value that is visibly mislabelled on the wire, not one that vanishes.

void setByString(String s)

Sets the value by parsing a serialized string representation.

This is the only entry point for a serialized zoned value: TomClass.setOrMergeValues routes every String destined for a [TomOTimezoned] member through here, because [TomTimezoned] extends [DateTime] and would otherwise be handed to DateTime.parse with its @D@/@T@/@X@ prefix still attached.

It is abstract rather than an inherited no-op. There is no default that could be right — the base cannot know which of the three wire formats to parse — and a subtype that inherited an empty body would drop the field during deserialization with no throw, no log and no return value to inspect. Making it abstract turns "forgot to implement it" into a compile error. A subtype that genuinely has nothing to parse must write the empty override itself, so that the silence is a stated decision.

Implementations accept both the prefixed wire form emitted by [TomTimezoned.toString] and a bare ISO-8601 timestamp.

class TomObject

class TomObject<T> extends TomObservable

A generic observable wrapper that holds a value of type [T].

[TomObject] is the foundation of the observable type system. It wraps a value and provides: - Automatic observer notification when the value changes - Convenient operators for getting and setting values - Support for adding observer callbacks

Operators

  • ~obj - Get the value (prefix operator)
  • obj() - Get the value (call operator)
  • obj | newValue - Set the value and notify observers, returning the value
  • obj << newValue - Set the value and notify observers, returning obj

itself so that writes chain - obj >> callback - Add an observer callback function

| and << write identically and differ only in what they hand back: use | when the value is what you need next, << when you want to keep working on the observable. The composites override << — see [TomList], [TomMap] and [TomClass].

Example

final name = TomString("John");

// Subscribe to changes. Retain the observer — it is held weakly, so
// discarding it stops the callback firing at some later point.
// The callback is handed the plain TomObservable, so read the value
// through the typed variable rather than through the parameter.
final observer = name >> (obs) => print("Name changed to: ${~name}");

// Set new value (triggers observer)
name | "Jane";

// Get value
print(~name); // "Jane"
print(name()); // "Jane"

name.removeObserver(observer);

Because it delegates to [set], it inherits the notify-only-on-change rule: writing the value the cell already holds is silent.

The chain's static type is TomObject<T>, not the subtype it started from — TomString("a") << "b" is a TomObject<String>. Chain for the writes, not to keep hold of a TomString.

The composites override this to mean wholesale replacement, which is not what [set] does on them: see [TomList.operator <<] and [TomMap.operator <<]. [TomClass.operator <<] throws.

Static

static Map<String, TomObject<dynamic> Function(String)> _wrapperFactoriesByPrefix

Every serialization prefix the wire format defines, mapped to the wrapper that owns it.

This is the single source of truth for which prefix denotes which type. Only the construction path consults it. [_createFrom] has to recover a type from a string and nothing else, because the element it is building has no cell yet; every path that writes into an existing member dispatches on that member instead — member is TomOTimezoned → [TomOTimezoned.setByString] in [TomClass._setMember], value is TomOTimezoned in [TomClass._serializeMember] — and those are already polymorphic over the whole zoned family. Adding a zoned flavour is therefore one entry here plus the flavour's own setByString, not an edit to a dispatch ladder in three files.

The zoned factories receive the string with its prefix, because their parseFromString consumes its own; [TomDateTime] receives it without, because DateTime.parse would reject it. Storing factories rather than constructors is what lets the two conventions coexist in one table.

static String _stripPrefix(String s, String prefix)

Removes [prefix] from the front of [s], or returns [s] unchanged.

The wire format is <prefix><payload>. Both deserialization paths need to find the payload — [_createFrom] when building a new wrapper and [TomClass._setMember] when writing into an existing one — and both used to spell it as a bare substring(3), which silently encodes the assumption that every marker is three characters long. The length now comes from the prefix itself.

static TomObject<dynamic> _createFrom(dynamic v)

Creates a [TomObject] wrapper from a dynamic value.

Automatically determines the appropriate [TomObject] subtype based on the runtime type of [v]: - [String] → [TomString] (or a temporal type if it carries a prefix from [_wrapperFactoriesByPrefix]) - [DateTime] → [TomDateTime] - [int] → [TomInt] - [double] → [TomDouble] - [bool] → [TomBool] - [Map] → [TomMap] (recursively wraps values) - [List] → [TomList] (recursively wraps elements)

The choice is made from the runtime type of [v] alone; nothing here knows the destination. An integral number therefore always becomes a [TomInt], even when the member it is bound for holds doubles — callers that know the destination type widen the value first with [_widenForDoubleTarget].

Returns [tomNull] if the type cannot be determined.

static dynamic _widenForDoubleTarget<T extends TomObject<dynamic>>(dynamic v)

Widens an integral number to double when the destination type [T] holds doubles, and returns [v] untouched otherwise.

JSON has a single number type, so a producer is free to write 20 for a value the schema calls a double — JavaScript's JSON.stringify(20.0) does exactly that. Widening at a double-holding destination is lossless, so it happens silently. The reverse is not lossless: narrowing a fractional number to an int destination is left to fail rather than truncated.

The destination test is <T>[] is List<TomObject<double?>> rather than an equality against [TomDouble]. Covariance makes it true for [TomDouble], [TomNDouble] and any subclass of either, and false for [TomInt] — and false for an untyped element type, because dynamic is a top type rather than a subtype of double?, so a raw [TomList] keeps its integers as integers.

static TomObject<dynamic> _createForTarget<T extends TomObject<dynamic>>(dynamic v)

Builds the wrapper a destination of type [T] should hold for [v].

[_createFrom] decides from the runtime type of [v] alone, which is the right rule when nothing is known about the destination and the wrong one when something is: it only ever builds the non-nullable leaves, so a TomList<TomNString> rejected every string it was handed, and a JSON null had no representation among them at all — _createFrom(null) answers [tomNull], which is not an instance of any leaf type.

Only a nullable destination changes the answer. Every other case is left to [_createFrom], the untyped destination included, since a member that commits to no element type asks for nothing: this can therefore widen what deserialization accepts but never narrow it.

The destination test is <TomNXxx>[] is List<T> and deliberately not its reverse. [TomObject] is covariant in its value type, so <T>[] is List<TomObject<String?>> is true for [TomString] as well as [TomNString] and cannot tell the two apart — the same covariance [_widenForDoubleTarget] relies on, which is exactly why it cannot serve here. Asking whether the nullable wrapper fits the destination can: TomNString is not a TomString, because String? is not a String.

A value the destination cannot hold falls through to [_createFrom] rather than throwing, so the mismatch is still reported by the element check in [TomClass._setListMember], which names the member and the position.
