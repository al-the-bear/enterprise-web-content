CE-RP Reporting — the report definition and its result envelope.

The two classes tom_core has no home for (codespecs_mapping.md §5.28):

  • [TomReportDefinition] — the authored report: what it selects, how it

groups and measures, which columns and charts it projects, which runtime parameters it takes, and which channels it is delivered on. Server locus. - [TomReportResult] — the shared result envelope a report operation returns, so the client can render it and the server can export it.

Why this is a part and not a composition

A report looks like an endpoint (CE-API) over a query (CE-DB) rendered in a table (CE-EL) — but none of those parts can hold it. CE-API's authored identity is an operation, and one report is delivered on zero to three channels; CE-DB authors entities, columns and row filters but has nowhere to author a grouping dimension or a measure; and a report column is an output projection carrying an aggregate and a format, not a CE-FM input field. What CE-RP adds over all of them is the grouped projection — the dimension/measure pair — and the artifact identity that holds it together.

Why the envelope does not extend TomTabularResult

tom_core_server's export module already has a minimal tabular shape that its CSV / XLSX / PDF renderers consume. That type is server-side, and this envelope is shared — the client renders reports too, and must not depend on a server type. So [TomReportResult] is authored here as the shared shape and the server adapts it onto TomTabularResult when exporting: a one-way projection, exactly the CE-DB pattern where the entity's field shape is authored once in the shared project and the server persistence facet derives from it.

The adaptation constrains this envelope in one way, and it is inherited deliberately: rows stay streamable. A report exists precisely for the results too large to hold inline, and a List of rows would put the whole result in memory before the first rendered byte.

class TomReportChart

class TomReportChart

A chart a report declares over its own projected columns.

Declared here, rendered by whoever can. A chart is authored input — the SOM carries chart type, series and axes as structured fields — so it is part of the specification surface. Rendering is not: the client draws charts natively, while two of the three export formats cannot express one at all. A chart therefore travels on the definition and the envelope, and an exporter that has no way to draw it omits it rather than failing.

class TomReportColumn

class TomReportColumn

One projected output column of a report.

A column displays a dimension or a measure — it does not introduce data of its own. That is the invariant [TomReportDefinition] checks: a column whose [sourceKey] resolves to neither is a column with nothing behind it.

Constructors

Creates a column displaying the dimension or measure keyed [sourceKey].

Properties

final String name

The column's machine-facing name in the result envelope.

final String sourceKey

The [TomReportDimension.key] or [TomReportMeasure.key] this column shows.

final TomReportValueKind valueKind

The value type rendered.

final String? label

The CE-TX message key for the column header.

final String? formatPattern

A presentation pattern for the value — a number or date format.

Presentation only: it never changes what was selected, so a generator may apply it in the renderer without re-running the query.

final String? drillThroughRouteId

The CE-NV route a click on a cell navigates to, if the column drills through.

An open id string, permanently — the one CE-RP target that stays one. A CsRouteRef cannot carry it: codespecs_mapping.md §5.23's locus rule bars a server-owned declaration from citing a client-owned referent, and a report definition runs on the server while a route belongs to the client project.

That makes it unlike the four codespecs_mapping.md §5.23 string exemptions, which are exempt because their referent is not a Dart declaration. A route is one, so the compile-time edge is lost to locus rather than absent by nature, and the lost guarantee is replaced by a named generation-time validator check (codespecs_derivation_contract.md §6 check 18) — the same substitution check 17 makes for a notification channel's fallback.

class TomReportDefinition

class TomReportDefinition

A complete authored report definition — the CE-RP CodeSpec's holder.

Server locus: the definition is where the report is executed. What crosses to the client is the [TomReportResult] envelope and the parameter shape.

Constructors

TomReportDefinition.new({required String reportId, required Type sourceEntity, required List<TomReportColumn> columns, String? displayName, List<TomReportDimension> dimensions = const [], List<TomReportMeasure> measures = const [], List<TomReportParameter> parameters = const [], List<TomReportChart> charts = const [], List<TomReportDeliveryChannel> deliveryChannels = const [TomReportDeliveryChannel.apiResponse], String? scheduleExpression})

Creates a definition and checks its internal consistency.

Throws [ArgumentError] on any of six defects, each a specification error that no generator can repair and that would otherwise emit code referring to something that does not exist:

  • an empty [reportId];
  • an empty [columns] list — a report that projects nothing;
  • a duplicate identifier within one namespace: dimension key, measure key,

column name, parameter name or chart id; - one key claimed by both a dimension and a measure, which would leave a column's [TomReportColumn.sourceKey] ambiguous; - a column whose [TomReportColumn.sourceKey] names neither a dimension nor a measure; - a chart plotting a column the report does not project.

This is the normative list. Prose elsewhere points here rather than restating it, so there is one enumeration to keep in step with the code below — and it sits in the same file, so a seventh check is a diff a reviewer sees alongside it.

Properties

final String reportId

The report's stable id — the key a CsReportRef const carries.

final String? displayName

The CE-TX message key for the report's title.

final Type sourceEntity

The CE-DB entity the projection selects from, as a Type literal.

A Type, never a string (codespecs_mapping.md §5.23, §4.4.1). An entity is already a Dart type, so codespecs_mapping.md §5.23's Cs*Ref family gives it no ref const by design: citing the class directly makes a renamed entity a compile error, which a string could never be. It also needs nothing but dart:core, so it keeps this package's dependencies: {} — the same property that decides TomJobDeclaration.readEntities.

May be empty, which aggregates over the whole filtered set and yields one row — the same meaning an empty groupBy has in the query substrate.

final String? scheduleExpression

When the report runs unattended — a recurrence expression, verbatim.

null means the report is only ever run on demand.

A schedule, not a job id. The specification authors a cron-like expression (codespecs_mapping.md §5.28's Report schedule row, from the report-schedule section's schedule-expression field); the CE-JB job that runs the projection is realised from it. codespecs_mapping.md §5.29 makes that explicit — "a scheduled report is declared once, on the CE-RP report definition; the job that runs it is realised from that schedule, not from a second entry" — so a field holding a job id would invite exactly the second source that rule exists to prevent, and would point at a declaration the generator had not written yet.

This is therefore not a cross-part reference at all: a recurrence expression names nothing declarable. The schedule's remaining authored detail — time zone, effective dates, generation window and timeout — lowers onto the derived job's own TomJobDefinition, where the substrate already carries it, rather than being restated here.

Authorization is not a field here. It rides a @CsAuthorize beside the @CsReport marker, per codespecs_mapping.md §5.15's field-level rule: the report's access level and permitted roles are exactly that annotation's requirement kind and its typed CsRoleRef list, so the edge is compile-checked instead of being an id string here.

class TomReportResultSection

class TomReportResultSection

One titled block of a [TomReportResult]: columns over a stream of rows.

Cells are positional, parallel to [columns], for the reason the export module's row type gives: rows are the one thing there are many of, and a keyed map re-stores every column name for every row.

Constructors

TomReportResultSection.new({required List<TomReportColumn> columns, required Stream<List<Object?>> Function() openRows, String? title})

Creates a section over [openRows], a factory that opens a fresh row stream.

A factory rather than a stream because a section is read more than once: deliveryChannels is a list, and a report declaring apiResponse and fileExport is one run delivered two ways. Handed a stream, the second delivery of a large result throws — a large result is a single-subscription stream, and that is exactly the case the streaming shape exists for.

[openRows] must return a new stream on every call. The type calls it once per read of [rows] and can guarantee no more than that; a factory closing over one StreamController returns the same already-listened stream and reintroduces the defect this shape removes. Open the query, or the file, inside the closure.

Properties

final String? title

An optional caption for the block.

final List<TomReportColumn> columns

The section's columns, in output order.

Stream<List<Object?>> rows

Opens one pass over the rows. See the constructor for its obligation.

enum TomReportChartKind

enum TomReportChartKind

The chart forms a report may declare.

Closed, because a chart kind selects which axes and series are meaningful — an open string would let a specification name a form no renderer has a rule for, and the failure would surface at render time rather than at generation.

Values

bar

Categorical comparison as bars.

line

A trend across an ordered axis.

pie

Part-to-whole as circular segments.

donut

Part-to-whole with a hollow centre.

scatter

Two measures plotted against each other as points.

gauge

A single measure against a target or range.

heatmap

A measure across two dimensions, encoded as colour intensity.

enum TomReportMeasureFunction

enum TomReportMeasureFunction

The aggregate a [TomReportMeasure] computes.

Deliberately 1:1 with tom_core_server's TomAggregateFunction rather than a richer parallel vocabulary. A measure the query layer cannot compile is a measure that cannot run, so the authorable set is exactly the compilable set. The two modifiers SQL expresses as part of the call — COUNT(*) and COUNT(DISTINCT c) — are fields on the measure ([TomReportMeasure.columnName] and [TomReportMeasure.distinct]), not extra members here, for the same reason: that is how the substrate models them.

Values

count

The number of rows, or of non-null values of the measured column.

sum

The total of the measured column across the group.

avg

The mean of the measured column across the group.

min

The smallest value of the measured column in the group.

max

The largest value of the measured column in the group.

enum TomReportValueKind

enum TomReportValueKind

The value types a report column or parameter may carry.

One closed vocabulary for both, rather than two overlapping ones. The SOM authors the two sides from slightly different sets — a column is never an entityRef and a parameter is never a currency — but they agree on the seven kinds in between, and a single vocabulary means a generator has one mapping table instead of two that must be kept in step.

Values

string

Free text.

integer

A whole number.

decimal

A fractional number.

currency

A monetary amount — a decimal that additionally carries a currency.

Column-side only: a parameter takes the amount as a [decimal].

date

A calendar date with no time component.

dateTime

A point in time.

boolean

A truth value.

enumeration

A member of a domainEnum domain enum.

entityRef

A reference to a CE-DB entity, carried as its identity.

Parameter-side only: a column projects the entity's label, which is a [string].
