class AgentSendConfig

class AgentSendConfig

The editor-assembled inputs to one query Options, minus the session id (which the engine supplies from [SpecSessionStore]).

Built from the active profile + global agent settings + the navigation/mutation MCP tools. It carries the profile plus the global knobs the send itself needs; the [mcpServers] seam is a field rather than a constructor requirement so a tool server can be supplied without reshaping the config.

Constructors

const AgentSendConfig.new({String? model, String? systemPrompt, PermissionMode? permissionMode, int? maxTurns, String? cwd, Map<String, McpServerConfig>? mcpServers})
factory AgentSendConfig.fromProfile(AgentProfile? profile, {AgentSettings? settings, String? model, PermissionMode? permissionMode, int? maxTurns, String? cwd, Map<String, McpServerConfig>? mcpServers})

Assembles a send config from the active [profile] overlaid on the global [settings].

For each knob the send carries, the first of these that is set wins: the explicit argument, the profile's field, the settings' field.

  • the turn cap — [maxTurns], else maxRounds of the profile, else of the

settings; * the permission mode — [permissionMode], else the profile's toolApprovalMode, else the settings', mapped by [permissionModeForApproval].

The profile alone supplies the system prompt. maxTokens, thinkingEnabled and promptCachingEnabled are not read: the Agent SDK's Options has no field for any of them.

class AgentSendEngine

class AgentSendEngine

Streams a single prompt through the Agent SDK and keeps the per-spec session id refreshed.

One engine wraps one [AgentSdkClient] (bound to the picked bridge), one [SpecSessionStore], and the assembled [AgentSendConfig]. [send] is a cold stream: each listen runs one query, transparently retrying once with a fresh session if the first attempt fails with a session error before any answer text has streamed.

Methods

Stream<AgentSendEvent> send(String prompt, {CancellationToken cancelToken = CancellationToken.none})

Sends [prompt], streaming the assistant's answer and refreshing the session id on a session error.

Lifecycle: exactly one [AgentSendStarted] first; zero or more [AgentSendChunk]s (optionally with one [AgentSendSessionRefreshed] before the retried attempt's chunks); then exactly one of [AgentSendCompleted] or [AgentSendFailed].

Pass a [cancelToken] to abort an in-flight turn: when it signals, the active query is interrupted (agentSdk.cancelVce), which closes its stream so the loop unwinds, and send then ends silently — no terminal [AgentSendCompleted] or [AgentSendFailed] is emitted, because a user-driven stop is neither a completion nor a failure. Relying on the token (rather than cancelling the returned subscription) is deliberate: cancelling an async* subscription parked on a stalled inner stream does not resolve promptly, whereas [AgentQuery.interrupt] closes the query stream eagerly.

class SpecSessionStore

class SpecSessionStore

The per-specification SDK session id, persisted to a YAML sidecar so the agent can resume the same Claude-Code conversation across sends and launches. Held out of the document: pass — it is transport state, not document content.

Mirrors the editor's other sidecars (e.g. BridgeChoiceStore): a small YAML file written synchronously on every change, degrading to "no session" on any read/parse error rather than throwing.

typedef AgentSdkClientFactory

typedef AgentSdkClientFactory = Future<AgentSdkClient> Function({required String host, required int port})

Builds (and connects) an [AgentSdkClient] over the VS Code bridge at [host]:[port] — the editor's transport seam.

Lives here, in the pure-Dart model layer, rather than in the Flutter tom_forge_agentic controller because the UI layer "never owns transport specifics": it hands the controller this factory (or a fake) and stays transport-agnostic. Throws a [StateError] if the bridge socket does not come up, so the caller can surface a connect failure to the user.

function permissionModeForApproval

PermissionMode permissionModeForApproval(ToolApprovalMode mode)

The SDK permission mode a [ToolApprovalMode] asks for.

The approval gate is about write tool calls, and the SDK expresses it as a permission mode:

  • [ToolApprovalMode.always] — ask before a write: the SDK's default mode,

which prompts for dangerous operations; * [ToolApprovalMode.never] — do not ask for writes: acceptEdits, which auto-accepts file edits. Not bypassPermissions, which turns every check off — more than an approval setting for writes asks for.

function specSessionLooksLikeError

bool specSessionLooksLikeError(String message)

True when [message] should be treated as an SDK session error under the editor rule: its text contains session, message, or msg (case-insensitive).

Deliberately broad — unlike the brain's conservative matcher (agentSdkLooksLikeSessionError) it does not require a separate failure cue. The editor would rather drop and refresh a per-spec session id one extra time than leave a stale id wedged in place.
