D4rt Usage Guide

This guide covers practical usage patterns for the D4rt interpreter in the Tom workspace, including script execution, bridge registration, and the execute/evaluate workflow.

Overview

D4rt is a Dart interpreter written in Dart that enables dynamic code execution at runtime. It's used in this workspace for:

  • VS Code extension scripting (tom_vscode_bridge)
  • Tom CLI automation (tom_build D4rt integration)
  • Dynamic script execution without compilation

Basic Setup

Creating a D4rt Instance

import 'package:tom_d4rt/d4rt.dart';

final interpreter = D4rt();

// Grant filesystem permissions for dart:io access
interpreter.grant(FilesystemPermission.any);

// Initialize execution context (required before using eval())
interpreter.execute(source: 'void main() {}');

Registering Bridges

Bridges expose native Dart classes to interpreted scripts. Register bridges before executing scripts that use them: 

// Register with a package URI that scripts will use for imports
interpreter.registerBridgedClass(
  myBridge, 
  'package:my_package/my_library.dart'
);

The second argument is the import path that D4rt scripts must use to access the bridged class: 

// In D4rt script:
import 'package:my_package/my_library.dart';

void main() {
  final obj = MyClass();  // Now accessible
}

Execute vs Evaluate Pattern

D4rt has two main execution methods that work together:

execute() - Full Script Execution

Use execute() to run complete Dart scripts with imports, declarations, and a main() function: 

final result = interpreter.execute(source: '''
import 'package:my_package/my_library.dart';

void main() {
  final config = MyConfig();
  print(config.name);
}
''');

eval() - Expression Evaluation

Use eval() for quick expression evaluation. Important: eval() can only access classes/variables that were previously imported via execute(). 

// First: execute with imports to set up the environment
interpreter.execute(source: '''
import 'package:my_package/my_library.dart';

void main() {}
''');

// Now eval() can access imported classes
final result = interpreter.eval('MyClass()');

State Preservation

Variables and globals defined in execute() are available in subsequent eval() calls: 

// Define a global variable
interpreter.execute(source: '''
import 'package:my_package/my_library.dart';

MyClass? globalInstance;

void main() {
  globalInstance = MyClass();
}
''');

// Access it via eval
final instance = interpreter.eval('globalInstance');

Filesystem and Import Options

Enabling Filesystem Access

For scripts that use dart:io, grant filesystem permissions:

interpreter.grant(FilesystemPermission.any);

// More restrictive options:
interpreter.grant(FilesystemPermission.read);   // Read-only
interpreter.grant(FilesystemPermission.write);  // Write access
interpreter.grant(FilesystemPermission.path('/specific/path')); // Specific path

Relative Imports from Filesystem

To enable loading .dart files from the filesystem using relative imports:

final result = interpreter.execute(
  source: '''
    import './utils.dart';
    main() => utilityFunction();
  ''',
  basePath: '/path/to/project/lib',
  allowFileSystemImports: true,
);

Parameters:

  • basePath: Directory to resolve relative imports against
  • allowFileSystemImports: Set to true to enable file loading

Note: The basePath alone doesn't set D4rt's current library context. For complex relative import scenarios, use the library + sources approach (see below).

Providing Multiple Sources

For more complex setups with multiple files, provide a map of sources:

final result = interpreter.execute(
  library: 'package:my_app/main.dart',
  sources: {
    'package:my_app/main.dart': '''
      import 'package:my_app/utils.dart';
      void main() => greet();
    ''',
    'package:my_app/utils.dart': '''
      void greet() => print('Hello!');
    ''',
  },
);

Advanced: File-Based Scripts with Import Resolution

When executing scripts from files with relative imports (like in tom_vscode_bridge), the recommended pattern: 

// Build a sources map by resolving imports recursively
final sources = <String, String>{};
final scriptUri = 'file://$basePath/__script__.dart';

// Add main script and recursively resolve its imports
_resolveImportsRecursively(script, scriptUri, sources);

// Execute with library + sources
final result = interpreter.execute(
  library: scriptUri,
  sources: sources,
  basePath: basePath,
  allowFileSystemImports: true,
);

This approach:

1. Uses file:// URIs as keys in the sources map 2. Pre-loads all imported files into the sources map 3. Allows D4rt to resolve imports without filesystem access during execution

Permission System

D4rt uses a permission-based security model. By default, access to dart:io and dart:isolate is blocked.

Available Permissions

PermissionDescription
FilesystemPermission.anyAll file operations
FilesystemPermission.readRead-only file access
FilesystemPermission.writeWrite file access
FilesystemPermission.path('/path')Specific path access
NetworkPermission.anyAll network operations
NetworkPermission.connect('host:port')Specific host
ProcessRunPermission.anyExecute any process
ProcessRunPermission.command('cmd')Specific command
IsolatePermission.anyAll isolate operations

Managing Permissions

// Grant
interpreter.grant(FilesystemPermission.any);

// Check
if (interpreter.hasPermission(FilesystemPermission.any)) {
  print('Has filesystem access');
}

// Revoke
interpreter.revoke(FilesystemPermission.any);

Wrapper Classes

For production use, create wrapper classes that encapsulate D4rt setup:

/// Example from tom_build: D4rtInstance wrapper
class D4rtInstance {
  late final D4rt _interpreter;
  bool _isInitialized = false;

  D4rtInstance._();

  static D4rtInstance create() {
    final instance = D4rtInstance._();
    instance._initialize();
    return instance;
  }

  void _initialize() {
    _interpreter = D4rt();
    _interpreter.grant(FilesystemPermission.any);
    
    // Register all bridges
    MyBridge.registerBridges(_interpreter, 'package:my_pkg/api.dart');
    
    // Initialize execution context
    _interpreter.execute(source: 'void main() {}');
    _isInitialized = true;
  }

  /// Execute a full script
  Future<void> executeScript(String source) async {
    _interpreter.execute(source: source);
  }

  /// Evaluate an expression (requires prior execute with imports)
  Future<dynamic> evaluate(String expression) async {
    return _interpreter.eval(expression);
  }

  bool get isInitialized => _isInitialized;

  void dispose() {
    _isInitialized = false;
  }
}

Testing D4rt Scripts

Pattern for testing bridged classes:

import 'package:test/test.dart';

void main() {
  group('Bridge Tests', () {
    late D4rtInstance d4rt;

    setUp(() {
      d4rt = D4rtInstance.create();
      // Initialize with imports
      d4rt.executeScript('''
import 'package:my_package/api.dart';

void main() {}
''');
    });

    tearDown(() {
      d4rt.dispose();
    });

    test('can create MyClass instance', () async {
      final result = await d4rt.evaluate('MyClass()');
      expect(result, isA<MyClass>());
    });

    test('can call methods', () async {
      await d4rt.executeScript('''
import 'package:my_package/api.dart';

void main() {
  final obj = MyClass();
  final result = obj.someMethod();
}
''');
      // No exception = success
    });
  });
}

Common Issues

"Undefined variable" Error

Cause: Using eval() with a class that wasn't imported.

Solution: Call execute() first with the required imports:

// Wrong:
interpreter.eval('MyClass()');  // Error: Undefined variable

// Correct:
interpreter.execute(source: '''
import 'package:my_package/api.dart';
void main() {}
''');
interpreter.eval('MyClass()');  // Works

"No constructor or static method named" Error

Cause: The bridge doesn't define the constructor or static method being called.

Solution: Check the bridge definition includes the constructor/method: - Named constructors (e.g., MyClass.fromJson()) → register in constructors map with the name as key (e.g., 'fromJson') - Factory constructors → same as named constructors, register in constructors map - Static factory methods (e.g., MyClass.create()) → register in staticMethods map

Bridge Not Found

Cause: Import path in script doesn't match the path used during registration.

Solution: Ensure the import path matches exactly:

// Registration:
interpreter.registerBridgedClass(bridge, 'package:my_pkg/api.dart');

// Script must use same path:
import 'package:my_pkg/api.dart';  // Must match!

Return Values from D4rt Scripts

Expression Returns

eval() and simple expressions return values directly:

final result = interpreter.eval('1 + 1');  // Returns: 2
final name = interpreter.eval('myObject.name');  // Returns: String

Script with Typed main() Returns

Scripts with typed main() (e.g., int main(), String main()) do return values directly: 

// int main() - returns integer directly
final result = interpreter.execute(source: 'int main() { return 42; }');
// Result: 42 (int)

// String main() - returns string directly  
final result = interpreter.execute(source: 'String main() { return "hello"; }');
// Result: "hello" (String)

// Map main() - returns complex types
final result = interpreter.execute(source: 'Map main() { return {"a": 1}; }');
// Result: {a: 1}

// void main() - returns null
final result = interpreter.execute(source: 'void main() { print("hi"); }');
// Result: null

Async main() with Future Returns

D4rt automatically awaits Futures returned from main(). Callers receive the resolved value directly: 

// Future<int> main() async - returns int (auto-awaited)
final result = interpreter.execute(source: '''
Future<int> main() async {
  await Future.delayed(Duration(milliseconds: 10));
  return 42;
}
''');
// Result: 42 (int) - NOT a Future!

// Future<String> main() async - returns String (auto-awaited)
final result = interpreter.execute(source: '''
Future<String> main() async {
  return "async result";
}
''');
// Result: "async result" (String)

// Sync function returning Future - also auto-awaited
final result = interpreter.execute(source: '''
Future<int> main() {
  return Future.value(99);
}
''');
// Result: 99 (int)

Alternative Patterns

IIFE Pattern

For inline expressions with multiple statements:

// Returns the value directly via immediately-invoked function
final result = interpreter.eval('(() { return "computed result"; })()');

Zone-Based Result Injection

For complex scripts that need to set results from nested callbacks (used in tom_vscode_bridge): 

// Setup zone with result container
final resultContainer = <String, dynamic>{};
await runZonedGuarded(
  () async {
    interpreter.execute(source: script);
  },
  (e, s) { /* error handling */ },
  zoneValues: {'result': resultContainer},
);
final value = resultContainer['result'];

Note: Zone-based injection is only needed for special cases like VS Code extension communication. For normal result capture, simply use a typed main() return.
