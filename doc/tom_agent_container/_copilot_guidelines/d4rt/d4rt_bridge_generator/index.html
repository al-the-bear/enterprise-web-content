D4rt Bridge Generator

The Bridge Generator automatically creates BridgedClass implementations from Dart source files, enabling classes to be used in D4rt scripts without manual bridging code.

Overview

The generator:

  • Parses Dart source files using the Dart analyzer
  • Extracts class information (constructors, methods, getters, setters)
  • Generates BridgedClass registrations with proper D4rt patterns
  • Supports filtering by class name, file, or directory
  • Handles abstract classes with factory constructors

---

Usage Methods

1. Tom CLI Command

Use the :generate-bridges internal command (prefix: gb):

# Generate bridge for a specific class
tom :generate-bridges -gb-class=TomWorkspace -gb-output=lib/bridges/

# Generate bridges from a file
tom :generate-bridges -gb-file=lib/src/models/config.dart -gb-output=lib/bridges/config_bridge.dart

# Generate bridges from a directory
tom :generate-bridges -gb-dir=lib/src/models/ -gb-output=lib/bridges/

# With pattern filtering
tom :generate-bridges -gb-dir=lib/src/ -gb-pattern=*Config -gb-output=lib/bridges/

# Full example with all options
tom :generate-bridges \
  -gb-file=lib/src/tom/config/tom_workspace.dart \
  -gb-output=lib/dartscript/workspace_bridge.dart \
  -gb-package=tom_build \
  -gb-helpers=package:tom_core_dartscript/d4rt_helpers.dart \
  -gb-readonly=false \
  -gb-skip-private=true

2. Dart API

Import from tom_build and use the BridgeGenerator class:

import 'package:tom_build/src/tom/cli/bridge_generator.dart';

Future<void> main() async {
  final generator = BridgeGenerator(
    workspacePath: '/path/to/project',
    packageName: 'my_package',
    sourceImport: 'src/my_barrel.dart',  // Optional: barrel file for imports
    helpersImport: 'package:tom_core_dartscript/d4rt_helpers.dart',
    readOnly: false,
    skipPrivate: true,
    verbose: true,
  );

  // Generate bridges from source files
  final result = await generator.generateBridges(
    sourceFiles: [
      '/path/to/project/lib/src/models/config.dart',
      '/path/to/project/lib/src/models/workspace.dart',
    ],
    outputPath: '/path/to/project/lib/bridges/generated_bridge.dart',
    classPattern: '*Config',  // Optional: filter by name
    targetClassName: null,    // Optional: specific class name
  );

  print('Generated ${result.classesGenerated} bridges');
  print('Output files: ${result.outputFiles}');
  
  if (result.errors.isNotEmpty) {
    print('Errors: ${result.errors}');
  }
  if (result.warnings.isNotEmpty) {
    print('Warnings: ${result.warnings}');
  }
}

3. Dart run Command

For standalone scripts or CI pipelines, use dart run:

# Run the generator script directly
cd tom_build
dart run tool/generate_tom_cli_bridges.dart

Create a custom generator script:

// tool/generate_my_bridges.dart
import 'dart:io';
import 'package:tom_build/src/tom/cli/bridge_generator.dart';

Future<void> main() async {
  final workspacePath = Directory.current.path;
  
  final generator = BridgeGenerator(
    workspacePath: workspacePath,
    packageName: 'my_package',
    sourceImport: 'src/models.dart',
    verbose: true,
  );

  // Collect source files
  final sourceDir = Directory('$workspacePath/lib/src/models');
  final sourceFiles = sourceDir
      .listSync(recursive: true)
      .whereType<File>()
      .where((f) => f.path.endsWith('.dart'))
      .where((f) => !f.path.endsWith('_bridge.dart'))
      .map((f) => f.path)
      .toList();

  // Generate
  final result = await generator.generateBridges(
    sourceFiles: sourceFiles,
    outputPath: '$workspacePath/lib/bridges/models_bridge.dart',
  );

  print('Generated ${result.classesGenerated} bridges');
  for (final file in result.outputFiles) {
    print('  - $file');
  }
  
  // Exit with error code if generation failed
  if (result.errors.isNotEmpty) {
    for (final error in result.errors) {
      stderr.writeln('ERROR: $error');
    }
    exit(1);
  }
}

Run with:

dart run tool/generate_my_bridges.dart

Helper Methods

The BridgeGenerator class provides utility methods:

findFileForClass()

Find the source file containing a specific class:

final generator = BridgeGenerator(workspacePath: '/my/project');
final filePath = await generator.findFileForClass('MyConfig');
// Returns: '/my/project/lib/src/config/my_config.dart' or null

findFilesMatching()

Find files matching a glob pattern:

final generator = BridgeGenerator(workspacePath: '/my/project');
final files = await generator.findFilesMatching('**/*.dart');
// Returns all Dart files recursively

Output Format

Generated files follow this structure:

// D4rt Bridge - Generated file, do not edit
// Source: /path/to/source.dart
// Generated: 2026-01-14T12:00:00.000

import 'package:tom_d4rt/d4rt.dart';
import 'package:tom_core_dartscript/d4rt_helpers.dart';

import 'package:my_package/src/models.dart';

/// Bridge class for Models module.
class ModelsBridge {
  /// Returns all bridge class definitions.
  static List<BridgedClass> bridgeClasses() {
    return [
      _createMyConfigBridge(),
      _createUserSettingsBridge(),
    ];
  }

  /// Registers all bridges with an interpreter.
  static void registerBridges(D4rt interpreter, String importPath) {
    for (final bridge in bridgeClasses()) {
      interpreter.registerBridgedClass(bridge, importPath);
    }
  }
}

BridgedClass _createMyConfigBridge() {
  return BridgedClass(
    nativeType: MyConfig,
    name: 'MyConfig',
    constructors: { /* ... */ },
    // Instance members
    getters: { /* (visitor, target) => value */ },
    setters: { /* (visitor, target, value) { ... } */ },
    methods: { /* (visitor, target, positional, named) { ... } */ },
    // Static members
    staticGetters: { /* (visitor) => value */ },
    staticSetters: { /* (visitor, value) { ... } */ },
    staticMethods: { /* (visitor, positional, named) { ... } */ },
  );
}

UserBridge Override System

The generator supports a UserBridge pattern that allows customizing generated bridge behavior without modifying the generated code directly. This is useful for:

  • Adding custom validation logic
  • Implementing complex type conversions
  • Providing alternative implementations for specific methods
  • Excluding methods that shouldn't be bridged

How It Works

1. Create a class named {ClassName}UserBridge that extends D4UserBridge 2. Place it in the same package (the generator scans for these automatically) 3. Add static override methods following the naming convention 

import 'package:d4rt/d4rt.dart';

/// User overrides for MyConfig - the generator detects this automatically
class MyConfigUserBridge extends D4UserBridge {
  /// Override the 'validate' method with custom implementation
  static bool overrideMethodValidate(
    Object target,
    List<Object?> positional,
    Map<String, Object?> named,
  ) {
    final config = target as MyConfig;
    // Custom validation logic
    return config.isValid && config.hasRequiredFields;
  }
  
  /// Override a getter
  static String overrideGetterDisplayName(Object target) {
    final config = target as MyConfig;
    return '${config.name} (${config.type})';
  }
}

Override Naming Convention

Member TypeOverride Method Name
MethodoverrideMethod{MethodName}
GetteroverrideGetter{PropertyName}
SetteroverrideSetter{PropertyName}
Constructor overrideConstructorDefault or overrideConstructor{Name}
Static MethodoverrideStaticMethod{MethodName}
Static GetteroverrideStaticGetter{PropertyName}
Static SetteroverrideStaticSetter{PropertyName}

See d4rt_bridgedclass_guidelines.md for detailed examples.

Best Practices

1. Use barrel imports - Set sourceImport to a barrel file that exports all classes 2. Exclude bridge files - Filter out *_bridge.dart when scanning directories 3. Handle abstract classes - Only abstract classes with factory constructors are bridged 4. Regenerate on change - Re-run generation when source classes change 5. Review warnings - Check the warnings list for skipped classes 6. Use skipPrivate - Keep skipPrivate: true to avoid exposing internal implementation 7. Use UserBridge for customization - Override specific behaviors without modifying generated code
