D4rt - Dart Interpreter and Runtime

Overview

D4rt (pronounced "dart") is a Dart interpreter and runtime written in Dart itself. It enables dynamic execution of Dart code at runtime, making it ideal for scripting systems, plugin architectures, and AI-driven code generation workflows.

Version: 0.1.9 License: MIT Repository: https://github.com/kodjodevf/d4rt Documentation: https://pub.dev/documentation/d4rt/latest/

Key Features

  • Dynamic Dart Execution: Execute Dart code at runtime without compilation
  • Full Generics Support: Complete support for generic classes, functions, and type constraints
  • Bridging System: Expose native Dart/Flutter classes, enums, and methods to interpreted code
  • Async/Await Support: Handle asynchronous code and Futures
  • Pattern Matching: Full support for Dart 3 pattern matching
  • Security Sandboxing: Permission-based system to restrict dangerous operations
  • Code Introspection: Analyze Dart code structure without execution
  • Dynamic Evaluation: Execute code dynamically while preserving execution state
  • Multi-Platform: Works on Android, iOS, Linux, macOS, Web, Windows

Installation

Add to pubspec.yaml:

dependencies:
  d4rt: ^0.1.9

Then run:

dart pub get

Basic Usage

Simple Execution

import 'package:d4rt/d4rt.dart';

void main() {
  final code = '''
    int fib(int n) {
      if (n <= 1) return n;
      return fib(n - 1) + fib(n - 2);
    }
    main() {
      return fib(6);
    }
  ''';

  final interpreter = D4rt();
  final result = interpreter.execute(source: code);
  print('Result: $result'); // Result: 8
}

Function Argument Passing

Pass positional and named arguments directly to interpreted functions:

final interpreter = D4rt();

final result = interpreter.execute(
  source: '''
    String greet(String name, {String greeting = "Hello"}) {
      return "\$greeting, \$name!";
    }
  ''',
  name: 'greet',
  positionalArgs: ['Alice'],
  namedArgs: {'greeting': 'Hi'},
);
print(result); // Hi, Alice!

Dynamic Evaluation with State Preservation

Execute code dynamically while preserving execution state:

final interpreter = D4rt();

interpreter.execute(source: 'int x = 10;');
final result = interpreter.eval('x + 5'); // Returns 15

This is particularly useful for: - Interactive REPLs - Incremental code execution - Stateful scripting sessions

Interfacing with Native Dart Code

Bridging Native Classes

Expose your Dart classes to the interpreter using the bridging system:

import 'package:d4rt/d4rt.dart';

// Your native Dart class
class MyClass {
  static const int defaultValue = 100;
  static int instanceCount = 0;
  static String info() => 'MyClass info';

  int value;
  MyClass(this.value) {
    instanceCount++;
  }
  int doubleValue() => value * 2;
}

// Create a bridge
final myClassBridge = BridgedClass(
  nativeType: MyClass,
  name: 'MyClass',
  
  // Define constructors
  constructors: {
    '': (InterpreterVisitor visitor, List<Object?> positionalArgs, Map<String, Object?> namedArgs) {
      if (positionalArgs.length == 1 && positionalArgs[0] is int) {
        return MyClass(positionalArgs[0] as int);
      }
      throw ArgumentError('MyClass constructor expects one integer argument.');
    },
  },
  
  // Static getters - signature: (visitor) => value
  staticGetters: {
    'defaultValue': (visitor) => MyClass.defaultValue,
    'instanceCount': (visitor) => MyClass.instanceCount,
  },
  
  // Static setters - signature: (visitor, value) { ... }
  staticSetters: {
    'instanceCount': (visitor, value) {
      if (value is int) {
        MyClass.instanceCount = value;
      } else {
        throw ArgumentError('instanceCount requires an int');
      }
    },
  },
  
  // Static methods - signature: (visitor, positional, named) { ... }
  staticMethods: {
    'info': (visitor, positional, named) => MyClass.info(),
  },
  
  // Instance getters - signature: (visitor, target) => value
  getters: {
    'value': (InterpreterVisitor? visitor, Object target) {
      if (target is MyClass) {
        return target.value;
      }
      throw TypeError();
    },
  },
  
  // Instance setters - signature: (visitor, target, value) { ... }
  setters: {
    'value': (InterpreterVisitor? visitor, Object target, Object? value) {
      if (target is MyClass && value is int) {
        target.value = value;
      } else {
        throw TypeError();
      }
    },
  },
  
  // Instance methods - signature: (visitor, target, positional, named) { ... }
  methods: {
    'doubleValue': (InterpreterVisitor visitor, Object target, List<Object?> positionalArgs, Map<String, Object?> namedArgs) {
      if (target is MyClass) {
        return target.doubleValue();
      }
      throw TypeError();
    },
  },
);

void main() {
  final interpreter = D4rt();
  
  // Register the bridge with a package URI
  interpreter.registerBridgedClass(myClassBridge, 'package:example/my_class_library.dart');

  // Now use it in interpreted code
  final code = '''
    import 'package:example/my_class_library.dart';

    main() {
      var obj = MyClass(21);
      return obj.doubleValue();
    }
  ''';

  final result = interpreter.execute(source: code);
  print(result); // 42
}

Bridging Native Enums

Expose Dart enums to the interpreter:

import 'package:d4rt/d4rt.dart';

enum Color { red, green, blue }

final colorEnumBridge = BridgedEnumDefinition<Color>(
  name: 'Color',
  values: Color.values,
);

void main() {
  final interpreter = D4rt();
  interpreter.registerBridgedEnum(colorEnumBridge, 'package:example/my_enum_library.dart');

  final code = '''
    import 'package:example/my_enum_library.dart';

    main() {
      var favoriteColor = Color.green;
      print('My favorite color is \${favoriteColor.name}');
      return favoriteColor.index;
    }
  ''';

  final result = interpreter.execute(source: code);
  print(result); // 1
}

Bridge Component Types

BridgedClass has separate fields for instance vs static members. When creating bridges, you can define:

1. Constructors (constructors): Factory functions that create instances 2. Instance Members: - getters: Instance property getters - signature: (visitor, target) => value - setters: Instance property setters - signature: (visitor, target, value) { ... } - methods: Instance methods - signature: (visitor, target, positional, named) { ... } 3. Static Members: - staticGetters: Static property getters - signature: (visitor) => value - staticSetters: Static property setters - signature: (visitor, value) { ... } - staticMethods: Static methods - signature: (visitor, positional, named) { ... } 4. Operators: All operators are bridged as methods with the operator symbol as the method name (e.g., '+', '-', '*', '/', '[]', '[]=', '&', '|', '<', '>', '==', etc.)

IMPORTANT: Static getters and constants must go in staticGetters, NOT staticMethods. Static getters use (visitor) => value signature (no positional/named args), while static methods use (visitor, positional, named) { ... } signature.

Best Practice: Use package URIs when registering bridges to avoid conflicts and enable proper import statements in interpreted code.

Registering Global Variables

Expose native Dart objects as global variables accessible in scripts without imports:

final interpreter = D4rt();

// Register configuration and utilities
interpreter.registerGlobalVariable('config', {'debug': true, 'maxRetries': 3});
interpreter.registerGlobalVariable('appName', 'MyApp');
interpreter.registerGlobalVariable('logger', Logger.instance);

// Access globals directly in scripts
final result = interpreter.execute(source: '''
  main() {
    print('Running \$appName');
    print('Debug mode: \${config['debug']}');
  }
''');

Global variables can be updated after execute() for subsequent eval() calls: 

interpreter.registerGlobalVariable('counter', 42);
final result = interpreter.eval('counter + 10'); // Returns 52

Code Introspection

Analyze Dart code structure without executing it:

final interpreter = D4rt();

final analysis = interpreter.analyze('''
  class User {
    String name;
    int age;
    User(this.name, this.age);
  }
  
  int getAge(User user) => user.age;
''');

// Access metadata
print(analysis.functions['getAge']?.parameters);
print(analysis.classes['User']?.constructors);
print(analysis.classes['User']?.fields);

Use Cases: - Pre-validation of script syntax - Extracting API signatures - Generating documentation - Static analysis tools

Security Sandboxing

Default Behavior

By default, D4rt blocks access to dangerous modules like dart:io and dart:isolate to prevent malicious code execution. This makes it safe to execute untrusted code.

Permission Types

D4rt provides a granular permission system:

1. Filesystem Permissions

// Allow all filesystem operations
interpreter.grant(FilesystemPermission.any);

// Allow read-only operations
interpreter.grant(FilesystemPermission.read);

// Allow write operations
interpreter.grant(FilesystemPermission.write);

// Allow operations on specific paths
interpreter.grant(FilesystemPermission.path('/specific/path'));

2. Network Permissions

// Allow all network operations
interpreter.grant(NetworkPermission.any);

// Allow connections to specific hosts
interpreter.grant(NetworkPermission.connect('api.example.com:443'));

3. Process Execution Permissions

// Allow execution of any command
interpreter.grant(ProcessRunPermission.any);

// Allow execution of specific commands
interpreter.grant(ProcessRunPermission.command('git'));
interpreter.grant(ProcessRunPermission.command('dart'));

4. Isolate Permissions

// Allow all isolate operations
interpreter.grant(IsolatePermission.any);

Permission Management

final interpreter = D4rt();

// Grant permissions
interpreter.grant(FilesystemPermission.any);

// Check permissions
if (interpreter.hasPermission(FilesystemPermission.any)) {
  print('Filesystem access granted');
}

// Revoke permissions
interpreter.revoke(FilesystemPermission.any);

Example: Controlled Execution

import 'package:d4rt/d4rt.dart';

void main() {
  final interpreter = D4rt();

  // Grant only specific permissions
  interpreter.grant(FilesystemPermission.read);
  interpreter.grant(NetworkPermission.connect('api.trusted.com:443'));

  // Execute code with restricted access
  final result = interpreter.execute(source: '''
    import 'dart:io';

    void main() {
      // Can read files
      final content = File('/path/to/file.txt').readAsStringSync();
      
      // Cannot write files - would throw SecurityException
      // File('/path/to/output.txt').writeAsStringSync('data');
      
      // Cannot access arbitrary network hosts
      // HttpClient would be restricted to api.trusted.com:443
      
      return content;
    }
  ''');
}

Security Best Practices

1. Principle of Least Privilege: Only grant permissions actually needed 2. Validate Input: Sanitize and validate user-provided code before execution 3. Use Path Restrictions: Use FilesystemPermission.path() instead of .any when possible 4. Isolate Untrusted Code: Run untrusted code in separate interpreters with minimal permissions 5. Monitor Execution: Use timeouts and resource limits for long-running scripts 6. Audit Permissions: Regularly review granted permissions

Setting Sandbox Restrictions

Conservative (Default)

final interpreter = D4rt();
// No dangerous operations allowed
// Safe for untrusted code

Moderate (Filesystem Read-Only)

final interpreter = D4rt();
interpreter.grant(FilesystemPermission.read);
// Can read files but not modify or execute processes

Permissive (Local Development)

final interpreter = D4rt();
interpreter.grant(FilesystemPermission.any);
interpreter.grant(NetworkPermission.any);
interpreter.grant(ProcessRunPermission.any);
interpreter.grant(IsolatePermission.any);
// Full access - suitable for trusted scripts in development

Custom (Production)

final interpreter = D4rt();

// Allow reading from specific directories
interpreter.grant(FilesystemPermission.path('/app/data'));
interpreter.grant(FilesystemPermission.path('/app/config'));

// Allow writing to logs directory
interpreter.grant(FilesystemPermission.path('/app/logs'));

// Allow network access to specific APIs
interpreter.grant(NetworkPermission.connect('api.production.com:443'));
interpreter.grant(NetworkPermission.connect('metrics.service.com:443'));

// Allow specific tools
interpreter.grant(ProcessRunPermission.command('git'));
interpreter.grant(ProcessRunPermission.command('dart'));

// No isolate operations

Integration Patterns

Pattern 1: Script Loader

class ScriptLoader {
  final D4rt interpreter = D4rt();
  
  Future<Object?> loadAndExecute(String scriptPath) async {
    // Grant necessary permissions
    interpreter.grant(FilesystemPermission.read);
    
    // Read script file
    final scriptContent = await File(scriptPath).readAsString();
    
    // Execute with error handling
    try {
      return interpreter.execute(source: scriptContent);
    } catch (e) {
      print('Script execution failed: $e');
      rethrow;
    }
  }
}

Pattern 2: Plugin System

class PluginManager {
  final D4rt interpreter = D4rt();
  final Map<String, dynamic> plugins = {};
  
  void registerAPI(String name, BridgedClass bridge) {
    interpreter.registerBridgedClass(bridge, 'package:plugins/$name.dart');
  }
  
  Future<void> loadPlugin(String name, String code) async {
    // Execute plugin initialization
    final result = interpreter.execute(
      source: code,
      name: 'initialize',
    );
    
    plugins[name] = result;
  }
  
  Object? callPlugin(String name, String method, List<Object?> args) {
    final plugin = plugins[name];
    if (plugin == null) throw Exception('Plugin not found: $name');
    
    return interpreter.execute(
      source: 'main() => plugin.$method(...args)',
      // Inject plugin and args into scope
    );
  }
}

Pattern 3: REPL (Read-Eval-Print Loop)

class DartREPL {
  final D4rt interpreter = D4rt();
  
  void start() {
    print('Dart REPL - Type "exit" to quit');
    
    while (true) {
      stdout.write('>>> ');
      final input = stdin.readLineSync();
      
      if (input == 'exit') break;
      if (input == null || input.isEmpty) continue;
      
      try {
        final result = interpreter.eval(input);
        print(result);
      } catch (e) {
        print('Error: $e');
      }
    }
  }
}

Limitations

1. Not a Full Dart VM: Some language features may behave differently 2. FFI: Foreign Function Interface not available 3. Mirrors: Dart reflection/mirrors not supported (use introspection API) 4. Performance: Interpreted code is slower than compiled code

Use Cases for Tom AI Build

1. Dynamic Workflow Scripts

Execute complex build workflows without recompilation:

// Load workflow script at runtime
final workflow = await File('workflows/generate_docs.dart').readAsString();
interpreter.execute(source: workflow);

2. AI-Generated Code Validation

Validate AI-generated code before committing:

// Analyze generated code
final analysis = interpreter.analyze(aiGeneratedCode);
if (analysis.errors.isEmpty) {
  // Code is syntactically valid
  await saveToFile(aiGeneratedCode);
}

3. Interactive Workspace Operations

Build REPL-like interfaces for workspace manipulation:

// User can execute commands interactively
interpreter.execute(source: '''
  final workspace = Workspace.load();
  workspace.projects.where((p) => p.hasParts).forEach(print);
''');

4. Safe Plugin Execution

Execute user-provided plugins with sandbox restrictions:

final interpreter = D4rt();
interpreter.grant(FilesystemPermission.read);
interpreter.grant(FilesystemPermission.path('/app/plugins'));

// Execute plugin in restricted environment
final plugin = await loadPlugin('user_plugin.dart');
interpreter.execute(source: plugin);

5. Template Processing with Logic

Execute templates with embedded Dart logic:

final template = '''
  String generate() {
    final modules = workspace.modules;
    return modules.map((m) => '- ${m.name}').join('\\n');
  }
  main() => generate();
''';

final output = interpreter.execute(source: template);

Best Practices

1. Reuse Interpreters: Create one interpreter per session, reuse for multiple executions 2. Bridge Selectively: Only bridge classes that scripts actually need 3. Use Package URIs: Always use package URIs for bridges to enable proper imports 4. Handle Errors: Wrap execute calls in try-catch for robust error handling 5. Validate First: Use analyze() before execute() for untrusted code 6. Set Timeouts: Implement execution timeouts for long-running scripts 7. Monitor Memory: Be aware of memory usage with large script executions 8. Grant Minimal Permissions: Start with no permissions, add only what's needed
