Projects and Repositories

This document defines: 1. Project IDs - Short identifiers for projects, used for tool configuration (e.g., issuekit) and cross-project references 2. Repository IDs - Short identifiers for git repositories, used for repository traversal commands

Important: Project IDs are independent of repository location. Projects may move between repositories without changing their project ID. Use project names/IDs for all normal operations; repository IDs are only needed for git repository traversal.

ID Conventions

  • Name format: Lowercase, one word preferred, hyphen-separated if needed
  • ID format: Short uppercase/mixed-case identifiers (2-10 characters)
  • Uniqueness: Each ID must be unique across the entire workspace
  • Naming sources (in order of preference):

1. Main executable name (e.g., buildkit, testkit, issuekit) 2. Last words of project name with hyphen (e.g., core-kernel) - Stability: Once assigned, IDs should not change (tools may reference them)

Test Projects (zom_ prefix)

Test projects in zom_workspaces/ are excluded from project IDs. They are used for testing build tools and should not have production IDs.

---

Git Repository IDs

Repository IDs are separate from project IDs. They identify git repositories for traversal commands (e.g., --modules basics).

When to use repository IDs: - Git operations across multiple repositories - Repository traversal in build tools - Specifying which repositories to include/exclude

When NOT to use repository IDs: - Normal project references (use project name/ID instead) - Issue tracking (use project ID) - Configuration files (use project ID)
