Appendix A4 · Implementation-rules cheat-sheet

Appendix A4 of the Tom Core advanced-sample user guide — see the guide index.

The spine teaches the rules in context; this appendix is the checklist you keep open while building a new tom_core app. Every rule is one line, stated imperatively, carrying (a) the framework enforcement anchor (where the rule is made true — kernel / tom_flutter_ui / tom_core_server) and (b) a sample site you can copy from. Nothing here is new: it consolidates what 07, 08, 09, 13, A1, A2, and A3 establish, so you can verify a rule holds without re-reading the prose.

> How to read the anchors. Paths are relative to tom_core_samples/ unless > they name tom_flutter_ui / tom_core_kernel / tom_core_server (the > framework). An anchor is the named declaration — a type, a member, or a > top-level function — that makes the rule true, given with its file, because a > name survives the edit that moves a line.

The two headline rules (read these first)

Everything else is detail around these two. If a new app honours only these, it is already "doing it the tom_core way":

#RuleWhyFramework anchorSample site
H1 Externalize every UI text. A widget ships no hard-coded label/hint/error string; each resolves from a server-delivered bundle keyed by the field's basePath . One name configures display and access; texts change without a client release; the no-strings property is testable. tom_flutter_ui tom_form.dart — TomField.resolvedLabel ( TomCtr.textOrNull(basePath, 'label') ?? tomId ) advanced_app_server/assets/resources_app.json ; install via setAppResourceProvider ( 08 )
H2 Drive UI authorization by scope/form/field names , not hand-wired widget logic. The item screen stamps each gradable field with a per-field TomAuthorizer.fixed , keyed on its basePath , from the server-resolved grade matrix; there is no per-field installed adapter (the one global adapter gates <type>:<id> resource keys only). The same widget renders differently per principal purely from the fetched matrix; grades come from the server, enforced where the data lives. tom_flutter_ui tom_form.dart — TomField.resolveEffectiveAuth (layer 4 applies the field's authorizer.effectiveAuth ) _ItemDetailScreenState._resolveForm ( advanced_app_client/lib/screens/item_detail_screen.dart )

Resources & texts

  • [ ] No label/hint/error literal in any widget. → H1; anchor TomField.resolvedLabel (tom_form.dart). Sample: todo_item_form.dart fields pass only a tomId, never a label.
  • [ ] Resources are server-delivered, installed once via TomTextResourceProvider.setAppResourceProvider at bootstrap — pre-login bundle first (public loginResources), full bundle after sign-in. → 08; sample AppSession._installResources (app_session.dart), the two /resources endpoints (AdvancedAuthApiService.loginResources in auth_endpoints.dart, AdvancedAppApiService.resources in app_endpoints.dart).
  • [ ] Key texts by <basePath>.<suffix> (.label / .hint / .error.<code>). The join is one helper — TomCtr._key (tom_flutter_ui tom_construction_helpers.dart): empty suffix = basePath verbatim, else '$basePath.$suffix'. → A2.
  • [ ] Author texts as a nested scope → form → field → suffix JSON tree, flattened server-side to the flat wire map. Keep the flatten pure and web-safe — flattenResourceTree in advanced_todo_contracts (no dart:io); the File read lives in each server. → A2; sample resource_bundle_dto.dart.
  • [ ] Prove it with the [srv] sentinel. A test installs a bundle whose every value carries a [srv] suffix and asserts the suffixed strings render — a hard-coded label would fail it. → 12; sample form_label_resolution_test.dart.

Authorization

  • [ ] *A field's basePath is its grade key* — <scopePath>.<formId>.<tomId>, no suffix. Authorization keys on the bare path; texts add a suffix. → H2; anchor tom_form.dart — TomForm.prepareForSelfObservation (form path), the TomField constructor (field path), TomField.resolveEffectiveAuth (auth lookup).
  • [ ] Install the principal's resourceRoles as the global adapter at login, then narrow per field locally — at login the app client fetches GET /resource-roles and installs AppResourceRoleAdapter(resourceRoles) as the global TomAuthorization adapter (gating only <type>:<id> keys; dotted chrome stays permissive). In the item screen set each gradable field.authorizer = TomAuthorizer.fixed(resourceState.narrow(projectRoleFieldGrades[role][basePath] ?? none)) where resourceState = TomAuthorization.resolveAuth(ResourceRoleKeys.item(id)); there is no per-field installed adapter, and non-gradable chrome keeps the permissive default. → sample _ItemDetailScreenState._resolveForm (item_detail_screen.dart), app_session.dart, app_resource_role_adapter.dart.
  • [ ] Per-field grades ride the layer-4 authorizer, closed-safe. Composition can only restrict (narrow), never widen; an unsent grade or a missing role defaults to none. The item screen narrows the registry-resolved resource ceiling by the shared projectRoleFieldGrades[role] row; the admin forms use TomAuthorizer.fixed for create-vs-edit shaping. → 07, A1.
  • [ ] Default closed. Unknown/absent grade ⇒ TomAuthState.none (hidden), enforced at three independent points: the resource adapter (an ungranted <type>:<id> key → none), a roleName with no matching ProjectRole → none, and the client per-field narrow (projectRoleFieldGrades[role][basePath] ?? none). The server WRITE-path resolver (FieldGradeResolver.resolveItemFieldStates in field_grade_resolver.dart) defaults the same. → A1.
  • [ ] Enforce writes on the server too. Field grades are a UX convenience client-side; the server re-checks every changed field is full and rejects otherwise. → AppWriteService._enforceFieldWrites (app_endpoints.dart), A3.
  • [ ] Role-gate admin routes by declaring TomRoleAccess([...]) on the contract endpoint (TomApiEndpoint.access) — the pipeline extracts and enforces it before the method runs. → tom_core_server; sample api_registry.dart (adminApi, shared adminAccess).
  • [ ] Register a per-row resolver for every graded file column —

TomRowColumnAuthorization.register(authKey, resolver) at boot, composed from the authorization layers you already have (role on the row × that role's grant row), closed-safe at every edge. The default source is the synchronous, process-global TomAuthorization, which answers full when no adapter is installed — so an authKey with no registered resolver is worse than none. → 13; sample column_grade_resolver.dart, column_grade_resolver_test.dart. - [ ] Grade a file field on the client by the same rule as a form field — resource ceiling narrowed by the role's grade, defaulting to none. It is cooperation, not enforcement: the server's per-row C-4 answer is the binding one, and an admin's grant edit changes it without touching the client map. → 13; sample item_detail_screen.dart (_buildAttachmentField), projectRoleAttachmentGrades. - [ ] Source the server principal from the request zone, getFromCurrentZone<TomPrincipal>() — never the client-side TomBearerAuthentication singleton (not request-scoped). → sample AdvancedAppApiService._principalId (app_endpoints.dart), AdvancedAuthApiService.me (auth_endpoints.dart).

Domain & reflection

  • [ ] Reflect every entity and every form-bound class with @tomReflector so bind/save and wire serialization work. → 03; sample advanced_todo_domain/.
  • [ ] One reflection seed per package, last-writer-wins. A single reflection_seed.dart whose main() touch-imports the reflected types; the generated reflection_seed.reflection.dart is the build output. → 02; sample advanced_app_server/, advanced_authadmin_client/lib/reflection_seed.dart.
  • [ ] Regenerate reflection only on signature changes, via the package's reflection_generation.sh (copy from a sibling if missing) — not on every edit. → memory: reflection-regen rules; sample */reflection_generation.sh.
  • [ ] Address scope/form/field keys by convention, not a catalogue. Declare scope/formId/tomId as plain string literals at use (super(formId: 'item'), TomScope.withScope('todo', …), tomId: 'title'); the form, the grade matrix, and the JSON texts stay aligned by naming the same <scope>.<formId>.<field> keys — never a constants class (G-RES-2/6). → A2; sample todo_item_form.dart, item_detail_screen.dart.
  • [ ] Enums carry a stored-name vs label split — the stored name token is the wire/DB value; the label is a resource. → 03.

Forms & UI

  • [ ] Use bound reflected forms (TomForm<T>/TomField<T>); fields self-render via field.widget, createFormElements stays empty. → 09; sample todo_item_form.dart, user_form.dart.
  • [ ] *Unscoped: formId is the base path.* A plainly-constructed LoginForm (formId: 'login') gives login.username. Use this for login + admin editors. → A2.
  • [ ] *Scoped: push the scope at the call site*** to make field paths equal the server's grade keys — TomScope.withScope('todo', TodoItemForm.new). Constructing the item form unscoped silently breaks every grade/text lookup (renders empty, no throw). → A2; sample _ItemDetailScreenState._resolveForm (item_detail_screen.dart).
  • [ ] *bind/save round-trip on the reflected member name*, independent of tomId. The one deliberate divergence (estimate tomId ↔ estimateHours member) proves the decoupling. → A2; sample TodoItemForm.estimateHours (todo_item_form.dart).
  • [ ] Observe state with the two-layer model — ListenableBuilder over a ChangeNotifier session, TomObject fields for in-form reactivity. → 09, 11.

Persistence & migrations

  • [ ] Number migrations consecutively (000,001,002,…) and split schema / admin / demo. DDL untagged, the production admin bootstrap untagged, and demo seeds in a separate @dev,test-tagged file (G-MIG-1/2/3) — so a production apply seeds the admin account but omits demo users, and every table exists before it is seeded. → 05; sample app_db/app_schema/[000]-app_core_schema.sql + [001]-app_demo_seed@dev,test.sql (auth: [000]+[001] schema, [002]-auth_admin_seed.sql, [003]-auth_demo_seed@dev,test.sql).
  • [ ] Keep every seed INSERT idempotent (ON DUPLICATE KEY UPDATE) so a re-applied migration is a no-op. → 05; sample [002]-auth_admin_seed.sql, [003]-auth_demo_seed@dev,test.sql, [001]-app_demo_seed@dev,test.sql.
  • [ ] Map columns with @TomDbColumn on the persistence record; the empty-bodied TomSqlDatasourceRepository singletons are the CRUD seam. → 05; sample app_persistence_model.dart.
  • [ ] Declare a file column with three facts, all beside the field —

@TomFileReference(exposed:, cascadeDelete:) next to @TomDbColumn(authKey:). Each is silent when lost: no exposed ⇒ the column is unreachable (nothing fails to compile); no cascadeDelete ⇒ orphaned blobs on every delete; no authKey ⇒ the column falls back to the permissive process-global TomAuthorization. Pin them in a reflection-read declaration test. → 13, 05; sample ItemRecord.attachment (app_persistence_model.dart), file_column_declarations_test.dart. - [ ] Point each blob store at the database that owns the rows. A type: database store names its datasource in blobstores_default.yaml; that name is what keeps one tier's blobs out of the other tier's database, and it must be initialised after the datasources. → 05; sample */assets/blobstores_default.yaml. - [ ] One datasource per logical DB, configured in YAML (map-key = folder, literal-int port). Cross-DB references are logical (no cross-DB FK); the app server binds the framework main datasource to auth_db to read the shared grant table. → 05; sample assets/datasources_*.yaml, GrantRepository (field_grade_resolver.dart).

Servers & endpoints

  • [ ] The contract declares the access; the server enforces it — set each endpoint's TomApiEndpoint.access (TomPublicAccess / TomAuthenticatedAccess / TomRoleAccess) in the registry, and the pipeline extracts it on first call (G-API-3/C-12). A handler-side TomAccessControl annotation is only a local override (tea ?? ae.access); the advanced servers declare nothing inline. → 10; sample api_registry.dart (authApi/adminApi/appApi).
  • [ ] Validate the bearer on every non-public request — the pipeline rejects pre-invocation and the framework answers a bare 404 carrying no key, so nothing in the application maps it. → 10; framework tomEndpointAccessDeniedErrorKey names the audited event, not a wire status.
  • [ ] Fail closed/safe: 404 over 403 for unreachable resources. A resource the caller cannot reach is reported missing, never leaking its existence. → A1/A3; sample itemNotFound (app_endpoints.dart, key app.item.not_found).
  • [ ] Keep services server-/zone-free; map error keys at the boundary. Services throw stable TomEndpointHandlerException keys; a server-level handler maps them to HTTP statuses. → sample appForbiddenOrNotFound (app_endpoints.dart), LoginUnauthorizedErrorHandler (auth_endpoints.dart).
  • [ ] Publish file slots from the annotations, one line per entity —

TomFileSlots.register(repository) at boot (after reflection + stores, before serving) turns the exposed file columns into /files/{entity}/{id}/{column} slots. Never restate a table or column name; an unexposed column resolves to nothing and answers 404 — the same answer a column that does not exist gets. → 13, 10; sample app_server_start.dart. - [ ] Boot servers in dependency order — the token-issuing auth server before the app server that trusts its key; reserve a distinct path for the typed status (/status) vs the framework liveness probe (/health). → 10; sample AdvancedAppApiService.health (app_endpoints.dart, the appHealth endpoint at /status).

Testing

  • [ ] Run Flutter suites with a bare flutter test — no -j flag, and no dart_test.yaml. Each suite file gets its own flutter_tester process, so the three process-global singletons (TomTextResourceProvider / TomAuthorization / TomBearerAuthentication) cannot leak between suites, and no widget suite opens a socket, writes a file or touches a database. → 12.
  • [ ] Test each layer against the seam directly below it, never a live socket — inject an in-memory backend (AppBackend / AdminBackend) mirroring the server's ownership + four-state model. → 12; sample in_memory_app_backend.dart.
  • [ ] Assert texts with the [srv] sentinel and grades with the four-role matrix (TC-30-01…04). Same widget, four principals, four renderings purely from the installed matrix. → 12; sample item_detail_screen_test.dart.
  • [ ] Exercise the real stack once, end-to-end, with a scripted runner that boots both DBs + servers and skips-as-failure when unreachable. → 12; sample run_cross_tier_integration.sh, cross_tier_integration_test.dart (TC-37-01).
  • [ ] The green gate is all three together: dart analyze clean + every suite green + the cross-tier runner exits 0.

Using the checklist

For a new app: start at H1/H2, then walk top to bottom. A rule you cannot point at an anchor for is a rule your app is not yet honouring — open the linked spine part for the worked example, and copy the named sample site. The order is the build order the spine follows: domain & reflection → persistence → servers → resources → authorization → forms → tests.
